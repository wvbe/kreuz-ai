# Digest 025 — Status Explanations & Production Flow

## 1. Purpose
Every stall-able subject (citizen, posting, board, workstation, site, zone, loose pile, standing order, dwelling) gets a derived, machine-readable status (Active/Idle/Blocked + ordered BlockedReason list, never text) with grace-period settling and `status.*` events. Plus a rolling per-day ProductionLedger (produced/consumed per material per FlowSource) feeding an Anno-style Flow view, why-chains (`causeRef`), badges, Idle&Blocked list, toasts in the renderer.

## 2. Module layout / public API (as stated)
Implied modules: `status/` (evaluator, reason collection, settle tracker, explain), `ledger/` (ProductionLedger, FlowSummary), renderer parts in spec 024 (FR-025..028 = badges, list, Flow view, toasts).
Enums: `StatusState {Active, Idle, Blocked}`; `StatusSubjectKind {Citizen, JobPosting, JobBoard, Workstation, ConstructionSite, Zone, LoosePile, StandingOrder, Dwelling}`; `BlockedReasonKind` (23, spec 023 FR-005); `ZoneGapKind {NotEnclosed, TooSmall, MissingFurniture, MissingJobBoard}`; `FlowDirection {Produced, Consumed}`; `FlowSource {Recipe, Gathering, Deconstruction, Construction, NeedConsumption, HouseholdConsumption, Spoilage, Trade}`.
Types:
- `StatusSubjectRef = { kind, entityId, postingId? }` | `{ kind: StandingOrder, orderId }` (no entityId). Dwelling ref = dwelling zone entity id. ConstructionSite covers Construction+DeconstructionJob.
- `Status = { state, reasons: BlockedReason[], sinceTick, settle progress, (query adds) settled: boolean }`
- `BlockedReason = { kind, params, causeRef: StatusSubjectRef|null }`
- `ZoneRequirementGap = { kind: ZoneGapKind, furnitureId?, required?, present? }`
Reason kinds + params: Paused{jobBoardId?,constructionJobId?,standingOrderId?}; NoSeatOfGovernment{}; NoSteward{}; LockedByTier{contentKind,contentId,requiredTier}; ScopeZoneMissing{zoneId}; ZoneRequirementsUnmet{gaps[]}; ZoneInactive{zoneId}; MissingWorkstation{workstationTag}; MissingRoom{zoneTypeId}; LocationBlocked{}; Unreachable{entityId}; NoReachableJobBoard{}; NoQualifiedWorker{skillId?,requiredLevel?}; MissingTool{tag}; MissingInput{materialId,required,available,noProducer}; NoHouseholdStorage{}; NoStorageDestination{materialId}; OutputBlocked{materialId}; AwaitingTownCrier{townCrierId:int|null,pendingChanges}; AwaitingWorker{postingRef}; NoJobsAvailable{jobBoardId}; DwellingRequirementsUnmet{targetLevel,unmet:DwellingRequirementKind[]}; NoOrders{}.
Queries (headless): `getStatus(ref)`, `getStatuses({state?,subjectKind?,reasonKind?,settledOnly?})` (insertion order), `explain(ref)` -> chain, `getLedger({materialId?,fromDay?,toDay?})`, `getFlowSummary(materialId)` -> `{producedPerDay, consumedPerDay, netPerDay (x1000 avgs over complete days, null if none), stock, daysOfSupply (x1000, null unless net<0), producers: refs}`.
Events: `status.blocked {subject,state,reason,previousReason|null,sinceTick}`; `status.unblocked {subject,previousReason,stalledTicks,removed}`.
Save keys (GameState root, 006 FR-004a already lists them): `statuses`, `productionLedger`.
Constants: `statusGraceTicks`=12, `ledgerWindowDays`=7, `maxExplanationDepth`=5.
Events consumed by ledger: `production.crafting.completed`, `construction.job.completed` (ConstructionJob & DeconstructionJob), `inventory.item.expired`, `jobboard.job.completed` (gathering, `outputs[]`), `need.item.consumed {entityId,needId,materialId,quantity}`, `housing.goods.consumed`, `trade.completed`.

## 3. Functional requirements
- FR-001 Status kept for every subject kind in StatusSubjectKind; ref shapes as above; Citizen = adult humanoid with TaskQueue.
- FR-002 Status = state, reasons[], sinceTick. Idle only for Citizen (no work), Workstation (NoOrders), Dwelling (DwellingRequirementsUnmet); all other non-Active = Blocked.
- FR-003 BlockedReason shape + 23-kind enum/params (list above); no free text; params only int/bool/entityId/contentId/enum.
- FR-004 reasons sorted by precedence: Paused, NoSeatOfGovernment, NoSteward, LockedByTier, ScopeZoneMissing, ZoneRequirementsUnmet, ZoneInactive, MissingWorkstation, MissingRoom, LocationBlocked, Unreachable, NoReachableJobBoard, NoQualifiedWorker, MissingTool, NoHouseholdStorage, MissingInput, NoStorageDestination, OutputBlocked, AwaitingTownCrier, AwaitingWorker, NoJobsAvailable, DwellingRequirementsUnmet, NoOrders. Ties: source order (recipe inputs / material list / gap order) then ascending entity id. reasons[0]=primary.
- FR-005 Owning systems (014,015,016,017,018,026,029) report their stall conditions as BlockedReason; status system only gathers/orders, never re-derives; replaces free-text reason strings in those specs.
- FR-006 Settling: non-Active state or new primary reason must hold `statusGraceTicks` (12) continuously before publishing (events, `settled:true`). Immediate: Paused, NoSeatOfGovernment, NoSteward, LockedByTier, ScopeZoneMissing, NoOrders; also StandingOrder & Dwelling subjects (daily-evaluated by owners). Unsettled still queryable with settled:false.
- FR-007 Emit status.blocked on first settle and on settled primary-reason change; status.unblocked when settled non-Active -> Active or removed (removed:true). Via bus (010 FR-009), subscribable `status.*`.
- FR-008 Evaluation once per tick after all sim systems, before event-queue boundary; visit subjects in entity insertion order (002 FR-007) then StandingOrders ascending orderId; pure; no PRNG; incremental allowed if identical to full.
- FR-009 MissingInput.causeRef/noProducer: producers of M = Workstations with active order/recurring posting for a recipe outputting M (014 FR-016) + JobPostings whose job type `outputs` lists M (022 FR-024). Any producer Active -> causeRef null; else first non-Active producer in insertion order; none -> noProducer true.
- FR-010 Queries getStatus/getStatuses/explain; explain stops at repeated subject or maxExplanationDepth.
- FR-011 ProductionLedger: per game day (`toDay(tick)`, 001 FR-011) counts keyed (materialId, FlowDirection, FlowSource); keep last ledgerWindowDays complete days + current; drop older.
- FR-012 Ledger updated at tick boundary FIFO from the listed events: Recipe (outputs produced, inputs consumed); Construction (materials consumed); Deconstruction (yield produced); Spoilage (consumed); Gathering (`outputs` produced); NeedConsumption; HouseholdConsumption; Trade only when exactly one party is player settlement (until 019 defines it: exactly one party inventory is a Throne Room treasury container). Day bucket = day of tick being processed. Never record hauling, transfers, wages, treasury payments.
- FR-013 getLedger / getFlowSummary as above; `stock` = sum over storage-furniture inventories (018 FR-001), excl. household storage on dwelling tiles (029 FR-017); 026 FR-006 builds on it.
- FR-014 Serialize statuses (subject,state,reasons,sinceTick,settle progress) + ledger; ints/bools/strings only. On load re-evaluate; same primary reason keeps sinceTick/settle progress and emits no event; different follows settle rules from load tick.
- FR-015 Engine never produces display text; renderer maps each kind to a modern-English template, resolving content IDs via registries (022).
- FR-016 Renderer: badge per primary kind on every settled Idle/Blocked visible subject; one-line primary reason first in inspection panel (024 FR-007); "why?" shows explain() when causeRef.
- FR-017 Renderer: Idle & Blocked list of settled non-Active, grouped by primary kind, sorted by sinceTick asc; click centres camera.
- FR-018 Renderer Flow view: one row per material with non-zero ledger counts; produced/day, consumed/day, net/day, stock, days of supply or "surplus", per-day trend, producers w/ badges; sort net asc then material id; expand = FlowSource breakdown; names link to content browser (024 FR-019).
- FR-019 Renderer MAY show grouped/throttled toasts, group by (subjectKind, reason kind, key content id); per-kind off switch; prefs are not game state.

## 5. Ambiguities / contradictions / blockers
- "LoosePile" has no prototype or owning system; no spec posts `haul.deliver` for it (stated open question). Blocks LoosePile subject + US1 scenario 4.
- Trade attribution open (no "player settlement" party in 019); interim treasury-container heuristic double-counts/misses NPC-to-NPC or non-treasury trades.
- causeRef used two different ways: producer-chain for MissingInput (FR-009) but, per Edge Cases, a citizen waiting at a workstation points causeRef at the *workstation*, and ZoneInactive points at the Zone subject. Chain semantics (explain stops at repeated subject) fine but FR-009 text does not cover these.
- Dwelling zone entity is simultaneously a Zone subject and a Dwelling subject (same entityId, different kind); 029 FR-019a says inactive dwelling reports `ZoneInactive` on the Dwelling subject while the Zone subject would report ZoneRequirementsUnmet: double reporting/ordering undefined. Also ZoneInactive.causeRef -> Zone subject.
- Idle vs Blocked for Dwelling with 0 residents (029 does not update streaks then) and "active dwelling at top level" not covered beyond Active.
- Spec 025 requires per-system "reason reporting" but defines no registration interface (callback/ECS component/collector) – design gap; FR-008 "pure function of game state" conflicts with "owning systems REPORT reasons" (push vs derive). Must pick pull (derivation fns per subject kind).
- Settling when reason set changes but primary stays same: not defined whether reasons[] list change re-emits (only primary changes emit). `settle progress` shape not defined.
- FR-006 grace is per-"new primary reason" but a subject flapping between two reasons each shorter than 12 ticks: undefined whether grace timer resets on primary-change while still Blocked (US3 sc.3 says new reason must hold the grace period; the old reason stays published meanwhile? unspecified).
- NoJobsAvailable defined "home board has no suitable job, and no fallback board has one" (017 FR-017) – needs 017 query.
- StandingOrder/Dwelling "settle at once" yet evaluated daily => status.blocked only once per day; SC-001 grace+1 tick does not apply.
- 027/028 tie-ins: `LockedByTier.contentKind` uses 027 LockedContentKind incl. DwellingLevel.
- Performance SC-003 (2 ms) vs full reachability/pathing checks per tick; incremental evaluation optional but needs dirty tracking.
- Statuses stored in save AND re-derived: the stored copy only matters for sinceTick/settle progress; a subject deleted while save is offline: orphan records need purge on load.
- Ledger: `construction.job.completed` for DeconstructionJob distinguishes via payload; payload fields (materials, yield) must be present in 016 FR-010 — verify. Byproducts (014 FR-019) presumably in crafting.completed outputs.

## 6. Tests to derive
US1 sc.1-7 (bakery missing flour -> Blocked MissingInput{flour,2,0}; citizen NoJobsAvailable; NoReachableJobBoard; pile NoStorageDestination; MissingTool hammer; Paused immediate no grace; Active -> empty reasons). US2: precedence ZoneInactive<NoQualifiedWorker<MissingInput; multi-MissingInput ordered by recipe inputs; byte-identical statuses across two runs; secondary reason becomes primary. US3: no event at grace-1, event at grace with sinceTick=T; reason cleared before grace -> no event; primary change re-emits with previousReason and unchanged sinceTick; status.unblocked with stalledTicks; removed:true. US4: bakery 6/day vs 8/day over 3 days -> produced 6 (Recipe), consumed 8 (NeedConsumption), net -2; crafting plank +4 / log -2; construction stone_block -4; spoilage cheese -5; window of 7 shows days 2-8 + partial day 9; save mid-day no loss/dup. US5: Oven->Mill->Farm chain with AwaitingWorker; Active producer -> causeRef null; no producer -> noProducer true; cycle stops <= maxExplanationDepth. US6-8 renderer (badge, list of 6 entries, camera centre, list update within one tick, Flow view bread +6/-8/-2, stock 10, 5 days, "surplus", FoR breakdown, grouped toast). Edge cases: hauler holding unstorable material Blocked NoStorageDestination; OutputBlocked on workstation+crafter; AwaitingTownCrier / NoSeatOfGovernment on board; Unreachable board; load re-eval keeps sinceTick, no event. SC-001 (all stall cases within grace+1), SC-002 (byte-identical 2000 ticks), SC-003 (<2 ms), SC-004 (ledger = independent count over 10 days), SC-005 (save/load emits no spurious events), SC-008 (summary parity).
