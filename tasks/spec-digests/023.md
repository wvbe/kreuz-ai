# Digest 023 - TypeScript Code Style Convention (165 lines, fully read) + docs/CONSTITUTION.md v1.1.0

## 1. Purpose
Defines enforceable code-style, naming, docs, test co-location and folder rules for all of src/, and the one-way engine -> renderer dependency boundary (src/game vs src/renderers). Doubles as the project scaffold spec (tsconfig, eslint, test runner, README check).
Constitution constraints that shape scaffold: I engine/renderer decoupling (no DOM in game), II determinism + JSON-serialisable + fixed-point x1000 + seed once, III headless-first, IV scenario snapshot tests, V modular systems, tests with minimal harness, state transparency, save migration tests.

## 2. Implied scaffold (no code yet)
```

src/game/README.md  src/renderers/README.md  src/renderers/react/README.md (+ every subfolder)

```
Layout rule: src/game = headless engine (also shared utilities); src/renderers/<name>/ = renderer(s) (react now, cli later). No shared layer. Scripts/config/generated output are out of scope for rules.
Public API: none (conventions only). Style-driven shape conventions: pure-data entities (no methods), systems = functions on state; cell-level coordinates in game logic, interpolation in renderer only; events = string topics + typed payloads + type guards; behavior: two-layer async/await over tick state machines, only task records serialised.

## 3. Functional requirements (condensed) with enforcement mapping
- FR-001 Named exports only; default exports PROHIBITED. -> `import/no-default-export` (eslint-plugin-import) + `no-restricted-exports`.
- FR-002 Barrel files (index.ts re-exporting) PROHIBITED; import from defining file. -> custom check: forbid any `index.ts` under src (script or `check-file/no-index`), plus `no-restricted-syntax` on `export * from` / `export { x } from`.
- FR-003 No file extensions in import paths; ordering left to formatter. -> `import/extensions: ["error","never"]` (JSON conflict, section 5) + `moduleResolution: bundler`.
- FR-004 `type` not `interface` (except declaration merging); classes allowed. -> `@typescript-eslint/consistent-type-definitions: ["error","type"]`.
- FR-005 `enum` for closed named-constant sets, string-literal unions PROHIBITED in hand-written code; Zod uses z.nativeEnum; open vocab (content IDs, categories, tags, faction types/dispositions) are `string`. Enforcement: code review ONLY. (Possible partial lint: `no-restricted-syntax` on TSUnionType of TSLiteralType, would false-positive on `string | undefined` no, only literal unions; spec says no automated rule exists.)
- FR-006 `any` and `unknown` PROHIBITED in production code; use generics/narrowing/satisfies; exceptions via `// eslint-disable-next-line` with justification. -> `@typescript-eslint/no-explicit-any: error`, `no-restricted-syntax` selector `TSUnknownKeyword`, `eslint-comments/require-description`.
- FR-007 Symbol names SHOULD be >=3 chars (`id` allowed; domain abbreviations ok). -> `id-length: ["warn" or "error", {min:3, exceptions:["id"], properties:"always"}]`. (SHOULD vs CI zero violations - decide severity.)
- FR-008 Types/classes/enum members PascalCase; functions/variables/params/properties camelCase. -> `@typescript-eslint/naming-convention` (note: content-data property names like `maxSpeedBonus` fine; snake_case IDs are string VALUES not identifiers).
- FR-009 File name == primary exported symbol exactly (ContentLoader.ts); multi-symbol files named after domain (materials.ts). -> custom script/`eslint-plugin-check-file` + custom rule (hard to automate fully).
- FR-010 Every exported function/method/type/enum/class has a TSDoc block; `/**` on own line, description starts next line. -> `jsdoc/require-jsdoc` (publicOnly, contexts for TSTypeAliasDeclaration, TSEnumDeclaration, ClassDeclaration, MethodDefinition) + `jsdoc/require-description`.
- FR-011 No one-line TSDoc blocks. -> `jsdoc/multiline-blocks: {noSingleLineBlocks:true, noZeroLineText:true}`.
- FR-012 Non-obvious params/returns SHOULD have @param/@returns (getters exempt). -> `jsdoc/require-param`/`require-returns` as warn.
- FR-013 Every exported function has >=1 unit test in co-located `<SourceFile>.test.ts`. -> custom check script (exported-symbol vs test-file mapping) + vitest coverage thresholds ("build fails").
- FR-014 Test helpers in .test.ts exempt from co-location and TSDoc. -> eslint override for `**/*.test.ts(x)` disabling jsdoc rules.
- FR-015 Files with `// @generated` first-line header exempt from all style rules. -> `ignores` via custom processor/`eslint-disable` header check; script must skip them.
- FR-016 Every folder under src/ has README.md (purpose, contents, relation to other folders). -> scripts/check-readmes in CI.
- FR-017 Top-level layout: src/game (engine, registries, schemas, utils), src/renderers/<name> (siblings), shared utility code lives in src/game only.
- FR-018 Dependency direction: renderers MAY import game; game MUST NOT import renderers. Enforced BOTH by TS project references (separate tsconfig per tree, game does not reference renderers) AND lint rule (`import/no-restricted-paths` zones: target src/game, from src/renderers).

## 5. Ambiguities / contradictions / missing (blockers [B])
1. [B] Test runner not named (vitest/jest). Coverage threshold value not given ("coverage thresholds enforced"), and per-function coverage cannot express "every exported function has a test" - needs custom script; decide metric (functions 100%? statements?).
2. [B] FR-006 bans `unknown`, but JSON.parse/Zod `safeParse` inputs, `catch (error)` (TS `useUnknownInCatchVariables`), and event payload type guards naturally use `unknown`. Needs an explicit boundary exemption (e.g. only in `ContentLoader`, save/load, type-guard helpers) or `useUnknownInCatchVariables:false`.
3. [B] FR-003 (no extensions) vs JSON static imports for content (022 FR-018) which need `.json` + resolveJsonModule. Also `import type`-only JSON schema generation. Needs carve-out.
4. [B] FR-002 forbids barrel `index.ts` yet 022 requires "static imports in a fixed order"; clarify that a ContentLoader.ts importing JSON files is not a barrel (it is not re-exporting) - OK, but FR-002's detector must key on re-exports, not on filenames only. Also vitest/React entry `src/renderers/react/main.tsx` + `index.html` names vs FR-009.
5. FR-005 (enums over string unions) enforced by review only -> inconsistent with SC-003 "zero violations"; and conflict with 022 where SettlementTier/DwellingLevel/BlockedReasonKind are enums but content IDs are strings: fine, but rule for event topic strings ("hybrid string topics") is unclear (string-literal union of topics prohibited?).
6. FR-007 is SHOULD but CI must report zero violations (SC-003): pick lint severity; `i`, `x`, `y` coordinates and `e` event params become errors. Test names like `id` fine. Properties named `x`,`y` (cell coordinates) conflict - decide exemption list (domain-standard abbreviations).
7. FR-009: "primary exported symbol" is undefined for files exporting a type + function; React `.tsx` component files (PascalCase), hooks (`useThing.ts`), JSON content files (kebab-case, 022 FR-019) - kebab JSON inside src/ vs README rule and FR-009; eslint-config files outside src are out of scope.
8. FR-010/013 count "exported function" - do exported arrow-function consts, React components, class methods, re-exported types count? Zod schema consts? (tests for schemas?). Type-only files (types are not functions) need no tests; are `export const` data tables exempt?
9. README rule applies to every folder in src/ including data folders and `__fixtures__`/test snapshot folders; scenario snapshot saves (constitution IV) location not defined - maybe under tests/ outside src/ (then not covered).
10. Spec says "tsconfig layout not prescribed" but also demands separate game & renderers tsconfig with game not referencing renderers; `src/renderers/` as a single project vs one project per renderer is open. Test files (vitest types) in a composite build: include/exclude test files in emit.
11. Headless Node execution: "TS-aware runner or bundler" unspecified (tsx? vite-node? node --experimental-strip-types - which forbids enums/non-erasable syntax!). Important: enum use (FR-005) conflicts with Node's native type stripping and `isolatedModules/erasableSyntaxOnly`; choose tsx/vite-node/esbuild.
12. Formatter (Prettier "or equivalent") not decided; import-sort plugin unspecified; Node/TS versions unspecified; no CI provider given; no git hooks.
13. FR-017 mentions utility code in src/game but doesn't say how a CLI renderer / tests tools (scripts/) depend; scripts/ out of scope yet README-check and content tooling live there.
14. Async/await in game logic: determinism requires no real timers/Promise.race; no lint rule (e.g. ban `setTimeout`, `Date.now`, `Math.random` in src/game) is specified though Constitution II mandates it - recommended extra rules (`no-restricted-globals`/`no-restricted-properties`) that this spec omits.
15. Success criteria SC-001/002 are experimental (human/AI sample file), no automated test beyond a lint fixture.
