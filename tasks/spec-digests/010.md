# Digest 010 - Event Bus

## 1. Purpose
Single global per-game typed pub/sub bus with hierarchical dot-names and wildcard subscriptions; emits are queued and drained FIFO at tick boundary (deterministic, error-isolated, nested-depth-capped).
Queue is serialized into GameState; promise-based `waitFor` for async tasks (spec 003); catalog of standard events.

## 2. Module/API (as stated)
- `EventBus` (singleton per game instance; not a module global).
- `emit<T>(topic: string, payload: T): void`  (spec text: `emit(eventName, payload)`).
- `subscribe<T>(topic: string, callback: (payload: T) => void, options?: { once?: boolean }): handle` (return value = "subscription handle"; type not named).
- `unsubscribe(eventName, callback)` (FR-008; also "unsubscribe()" via handles - signature mismatch, see 5).
- `waitFor<T>(eventName, predicate?: (e) => boolean): Promise<T>` resolves at tick boundary.
- `getQueue()` -> immutable copy snapshot of pending `Event[]` (name + payload).
- `processQueue()` (named only in Assumptions; called by game loop 001 at tick end; also "explicit flush").
- `Event` = `{ name, payload }` JSON-serializable; `Subscriber`; `WaitForPromise`; `StandardEvents` catalog.
- Name grammar: dot-separated lowercase kebab-case segments; wildcard `*` (exactly one segment) and `**` (one or more segments, any depth); wildcards only as LAST segment.
- Standard events named: `game.started`, `game.paused`, `game.saved`, `entity.spawned {entityId, prototype}`, `entity.deleted`, `entity.movement.started/completed`, `entity.health.changed`, `inventory.item.stored {entityId, materialId, quantity}`, `inventory.item.retrieved`, `inventory.item.expired {entityId, materialId, quantity}`, `inventory.item.transferred`, `inventory.item.stack.merged` (example), `tick.begin`, `error.system-failed`, `status.blocked {subject,state,reason,previousReason,sinceTick}`, `status.unblocked {subject,previousReason,stalledTicks,removed}` (025 FR-007), `trade.offer.made` (custom example). Namespaces owned by other specs: `standing-order.**`, `steward.**`, `bell-tower.rang` (026 FR-024), `settlement.**` (027 FR-025), `identity.**`, `chronicle.**` (028), `housing.**` (029 FR-020). Others seen in this batch: `need.item.consumed` (013 FR-023), `production.crafting.started|completed|failed|interrupted`, `production.output.blocked` (014 FR-011), `zone.requirements.met|lost` (015 FR-008).
- GameState queue shape not given beyond "event name and payload" in order.

## 3. Functional requirements
- FR-001 emit + subscribe.
- FR-002 Name format: dot-separated lowercase kebab-case.
- FR-003 Subscribers called with payload.
- FR-004 Exact or wildcard subscriptions (`*` one segment; `**` any depth; `inventory.item.*` !~ `inventory.item.stack.merged`).
- FR-005 `*` exactly one segment; `**` one or more; both only as last segment.
- FR-006 Permanent and one-time subscriptions.
- FR-007 `{ once: true }` auto-unsubscribes after first delivery (with wildcards: after ANY matching event).
- FR-008 `unsubscribe(eventName, callback)`; cleanup is caller's job (entities track handles).
- FR-009 Emits during tick are queued; all processed at tick boundary FIFO.
- FR-009a Nested emits appended to queue, delivered same boundary, FIFO; fixed engine-defined depth cap; over-cap emit NOT queued and raises error caught+logged (FR-017); queue empty at end of tick.
- FR-010 Subscribers to same event called in registration order, stable across ticks and save/load.
- FR-011 Subscriber registered after an event was queued (same tick, before boundary) does NOT receive that queued event (future-only).
- FR-012 `waitFor<T>(eventName, predicate?)` promise resolving at tick boundary on next matching event; promises not serialized; behavior scripts record the wait in the 003 task checkpoint and re-issue on load.
- FR-013 Global singleton per game; all maps share it; no map routing.
- FR-014 `getQueue()` for debugging/serialization (returns copy).
- FR-015 Queue at save serializes to GameState (name + payload).
- FR-016 On load, queue restored same events same order.
- FR-017 Subscriber throw caught+logged; remaining subscribers continue.
- FR-018 Standard event types documented with payload schemas (list above).
- FR-019 Custom events supported.
- Edge: unsubscribe during processing applies to every later delivery (queued events never reordered/removed); invalid name (empty/bad chars) rejected at emit AND subscribe time; no queue truncation; emit outside tick (bootstrap) queued until next boundary or explicit flush; subscriber errors may emit error events; subscriptions NOT serialized (systems re-register on load).

## 4. Dependencies
Consumes: 001 game loop (calls processQueue at tick end), 006 (queue serialization), 003 (waitFor from task scripts). Provides: pub/sub to every system (005 inventory events, 013, 014, 015, 025-029 namespaces). Also 011 only as "may receive PRNG" (no actual use).

## 5. Ambiguities / contradictions / blockers
- CONTRADICTION: FR-011 (late subscriber misses events queued before registration) vs US5 scenario 5 (after load, "a subscriber registered for one of those events is called when processed - no events missed"). Subscriptions are re-registered after load, always after the queue was restored => by FR-011 they'd miss everything. Need rule: delivery set resolved at processing time vs emit time; load-restored events should use "registered by first processQueue". Implementation of FR-011 needs a per-event emit-sequence vs per-subscription registration-sequence; define whether sequence numbers are serialized.
- Depth cap value unspecified; error type/log sink (logging API) unspecified; "tick.begin" semantic: if emits queue until boundary, tick.begin is delivered at END of the tick, contradicting "setup work at tick start" (US6.4) and SC-001 "queue empty at tick N start". Need explicit phases (flush queue at tick start for tick.begin? or tick.begin delivered first). `tick.*` payloads not defined.
- Unsubscribe signature: `unsubscribe(eventName, callback)` vs "handles (return values of subscribe())" vs "unsubscribe()" on a subscription object. Same callback subscribed twice, or to exact+wildcard patterns?
- Ordering between exact and wildcard subscribers: global registration order assumed; not stated. Registration order for subscriptions registered during processing: applies to current event? (FR-011 says no for queued ones.)
- waitFor mechanism vs determinism: promise continuations run as microtasks; they must run in a defined point (drain microtasks within boundary?) - unspecified; resolving "at tick boundary" while awaiting scripts then emit/queue more -> which tick? Rejected/timeouts on waitFor absent. Interaction with save: events that resolved vs pending. Payload predicate invoked on events - predicate errors?
- Payload typing: "strongly typed" via TS generics but no event-map type (topic->payload) exists; wildcard handler type is union. Payloads must be JSON-safe (FR/US5.3) - no validation rule stated; numbers fixed-point ints per Constitution.
- Entity IDs: examples use numeric (`entityId: 42`) - confirm vs string ids elsewhere; `entity.spawned {entityId, prototype}` vs wildcard example list ("entity.movement.started", "entity.health.changed") not formal.
- GameState event queue JSON schema and where (key name) not defined; SC-003 <10% overhead, SC-004 100+ events <100ms.
- `error.system-failed` payload and the identity of "systems" (system registry doesn't exist in these specs).
- `**` doesn't match the bare prefix (`inventory.**` !~ `inventory`) - state explicitly in tests. "game.saved" emitted during save: queued event serialized in same save? Re-entrancy.
- Standard-event catalog is scattered across specs (025-029 by owner); no single registry module/typing.

## 6. Tests to derive
US1: emit -> subscribers receive typed payload; two subs both fire; after tick end all called; FIFO A,B,C; compile-time narrowing (type test).
US2: `inventory.item.*` hits stored/retrieved/expired; `game.*` hits started/paused/saved; exact + `inventory.**` both called; `entity.*` only matches `entity.spawned` not `entity.movement.started`; subscription not serialized.
US3: permanent x3; once fires once; entity deletion unsubscribes (caller-managed); explicit unsubscribe; once+permanent mix; once on wildcard fires after first match of any.
US4: A,B,C order; nested emit processed after current event fully delivered; getQueue mid-tick shows pending; queue empty at next tick start; throwing subscriber isolation; depth cap overflow error logged & queue empties; unsubscribe during processing; late subscriber doesn't get queued event; emit outside tick queued.
US5: 3 events saved with payloads; loaded queue processed same order; payload JSON-only; emit after load appends after restored events; 100+ events save/load <100ms; determinism replay (SC-002).
US6: standard payload schemas; `entity.**` receives spawn/move/delete; custom `trade.offer.made`; `tick.begin`; `error.system-failed`.
Name validation: empty, uppercase, underscores, mid-pattern wildcard rejected. waitFor with predicate resolves on matching; not serialized; re-issued after load. 

## 7. Size: M (small core, but subtle ordering/serialization semantics and waitFor/microtask determinism need care).
