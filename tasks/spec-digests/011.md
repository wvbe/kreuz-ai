# Digest 011 - PRNG & Seed

## 1. Purpose
Pure-JS deterministic PCG-family PRNG (no Math.random/crypto) injected as a dependency, seeded once at bootstrap (explicit or generated-once-and-recorded), fully serializable, with named derived sub-streams.
Gives gameplay helper API (ints, choice, weighted, bool, shuffle) and test-only reseeding; cross-platform bit-identical.

## 2. Module/API (as stated)
- `PRNG` (main generator, serializable), `DerivedPRNG` (sub-PRNG), `Seed` (integer 0..2^32-1), `PRNGState` (JSON-serializable internal state: "seed, position, counters").
- Methods: `random(): number` in [0.0,1.0) ; `randomInt(min, max): number` (inclusivity of max not stated; examples `randomInt(1,10)` produce 1..10 => inclusive); `randomChoice<T>(array: T[]): T`; `randomWeighted<T>(options: T[], weights: number[]): T`; `randomBool(probability: number): boolean`; `shuffle<T>(array: T[]): void` (in place, Fisher-Yates); `derive(name: string): PRNG`; `setSeed(newSeed: number): void` (tests/debug only); `getSeed(): number`.
- State lives in GameState (`initOptions` holds seed per 007; PRNG state + derived streams "serialized by name" in 006 GameState). No key names defined.
- Injected, never global (FR-007). Named streams referenced elsewhere: `identity.names` (028 FR-004), `housing.immigration` (029 FR-015); pathfinding "pathfinding" and room gen "room-gen" given as examples (US4).
- Errors: clear validation errors (type names not defined).

## 3. Functional requirements
- FR-001 Seed explicit integer at bootstrap (007) or engine-generated exactly once and recorded in state; all later randomness derives from it.
- FR-002 Valid seed 0..2^32-1; others rejected at init.
- FR-003 PCG or equivalent deterministic cross-platform algorithm.
- FR-004 Identical seed+call sequence => bit-identical outputs.
- FR-005 `random()`, `randomInt(min,max)`, `randomChoice(array)`.
- FR-006 `randomWeighted(options, weights)`, `randomBool(probability)`, `shuffle(array)` in place.
- FR-007 Dependency-injected, not global singleton.
- FR-008 State (seed, position, counters) serializes to JSON into GameState.
- FR-009 Load restores state; sequence resumes exactly.
- FR-010 `derive(name)` independent deterministic sub-PRNG; same name => same initial state (fresh each call; identical sequences); different names => different sequences.
- FR-011 Derived PRNGs serialize with GameState (by name); reconstructed on load; unknown names start fresh.
- FR-012 `setSeed(newSeed)` tests/debug only; resets all derived PRNGs (re-derived from new seed, same name => same new sequence).
- FR-013 Pure code, no platform APIs.
- FR-014 Validate all params (seed range, array bounds, weight sums); reject with clear messages.
- FR-015 Cross-platform determinism verified (Node vs browser, bit-for-bit).
- FR-016 `randomWeighted` also accepts positive-integer weights of any sum: draw one integer uniformly in [0,sum), pick option whose cumulative range contains it. Fractional weights must sum to 1 (not normalized, else error).
- Edge: max<min error; empty options error; corrupt state (negative position) fails validation on load; >100 derived PRNGs fine; mid-op reseed: current op completes.

## 4. Dependencies
Consumes: 007 bootstrap (seed provision, `initOptions`), 006 (state serialization). Provides: injected PRNG to 009 (derived), 012 (derived tie-break), 010 (optional), 013 (success rolls), 014 (quality), 028 `identity.names`, 029 `housing.immigration`, and all gameplay randomness. Constitution seed carve-out is implemented here.

## 5. Ambiguities / contradictions / blockers
- Exact PCG variant (PCG32 XSH-RR?) and increment/stream constants unspecified; "position" is not a PCG concept (state+inc): define PRNGState = {state, inc} (64-bit each) - JSON numbers cannot hold 64-bit => must be hex strings or four 32-bit words (BigInt for arithmetic or 32-bit split math). "Full 32-bit precision" random() = u32/2^32 (only 32 bits of entropy; "double" claim in Q3 is loose) - decide and fix.
- SC-003 1M values/s with BigInt PCG may be hard; implement with 32-bit halves.
- derive(name) hashing (name -> seed/stream) unspecified; must be stable across platforms and independent of main PRNG position (US4: derived deterministic from "main seed" - implicit dependency only on seed, not state; then re-deriving after main advanced yields initial state). But FR-011 says derived streams serialized (they advance); "derive() returns fresh at initial state" (edge) vs serialized-by-name restore: a consumer that calls derive("x") again after load gets initial state, not saved state -> must the PRNG hold a registry of live streams by name and return the SAME stream? Contradiction/ambiguity: derive() "fresh each call" vs "engine's derived streams serialized by name". Need an explicit API like `stream(name)` (get-or-create, persisted) vs `derive(name)` (fresh).
- Fixed-point policy: Constitution says state numbers are fixed-point ints; `random()` float and fractional weights/probability are API only, but 013 uses mood probabilities (20-80%) and 012 weights; define integer helpers (e.g., `randomBool` with permille) to avoid float drift. Fractional weights "must sum to 1" with float equality - tolerance undefined (0.1+0.2+0.7 != 1 exactly). 
- randomInt inclusivity, non-integer args, randomChoice on empty array, weights.length != options.length, negative/zero weights, randomBool outside [0,1], not specified beyond "validate".
- US2.5 "different shuffles each tick (no repeated shuffles in sequence)" is not a determinism property; remove or treat as natural. US3.5 "shuffle mid-operation save" impossible (synchronous) - no-op test.
- setSeed on derived streams / clock of "reset" and what the recorded seed in `initOptions` becomes (US5.4 says save reflects new seed).
- Seed generation source at bootstrap (only allowed non-deterministic input) - mechanism (Math.random? Date?) not specified; belongs in 007 but is required here (US1.2).
- 012 says tie-breaking uses "the game's seeded PRNG (spec 004)" vs 011 Assumption "pathfinding receives derived PRNG" - see cross-spec.
- SC-005 state <1KB incl. derived streams: with 100+ derived streams may exceed.

## 6. Tests to derive
Same seed -> same 10 / 100 / 10,000 values (SC-001); seed 0, 2^32-1 valid; -1, 2^32, 1.5, NaN rejected; no seed at bootstrap -> seed generated once, stored in state, replay from save identical; getSeed.
randomInt uniformity (1..10 all appear, min/max inclusive), randomChoice coverage, randomWeighted 1000/10,000 samples within +-5% (50/30/20), integer weights exact proportionality + empty options/fractional-not-summing/ negative errors, shuffle permutation + same-seed identical + in place; randomBool(0)/(1).
Serialization: save mid-sequence; load; next 10 equal continuous run (SC-002); JSON < 1KB; corrupt state rejected; cross-platform vectors (golden values for seed 12345 stored in fixtures); derive same name twice identical; different names differ; derived independent from main; derived survive save/load; unknown names fresh; setSeed(99) then equals fresh PRNG(99); setSeed resets derived; two games same reseed identical; perf 1M/s.
