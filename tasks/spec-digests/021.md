# Digest 021 - Diplomacy & Factions

## 1. Purpose
Factions are ECS entities (leader, directional standing map, disposition); membership lives only on members' `Citizen.factions`. Diplomatic acts (Gift, TradeAgreement, Declaration, Overture) are carried by one Diplomatic Envoy each, pathfinding to the target faction's current leader; standing then gates trade, biases affinity and gates labour. NPC factions run a rate-limited AI that initiates acts.

## 2. Implied module layout / public API
Module: diplomacy (factions, standing, envoys, NPC faction AI).
- `Faction` entity components: `name`, `factionType` (string, open: political|occupational|religious...), `leaderId` (entity id | null), `standing: { [factionId]: FactionStanding }`, `disposition` (open set: mercantile, aggressive, isolationist...; static prototype data with act-selection weights). Player government is a Faction; it additionally carries `SettlementChronicle` (028 FR-018) and `SettlementProgress` (027 FR-002).
- `FactionStanding`: `{ value: integer [-100,100], tradeAgreement: boolean }`; default 0, asymmetric (each faction keeps own view).
- `Citizen` component fields: `factions: EntityId[]` (sole source of membership), `homeDwellingId` (id|null), `homeAssignedTick` (int) (029 FR-005).
- `DiplomaticEnvoy` entity: carries `DiplomaticMessage`; status `traveling | delivered | returning`; destination = leader entity (tracked live); not batched; unlimited (one per act).
- `DiplomaticMessage`: `senderFactionId`, `targetFactionId`, `actType: DiplomaticActType { Gift, TradeAgreement, Declaration, Overture }`, `payload` (items/currency for gifts; subtype war|peace|neutrality for declarations; terms for agreements), `creationTick`.
- Enums: `DispatchFailureReason { leader-unavailable, unreachable, envoy-destroyed }`.
- Query: `getEntitiesByProperty('Citizen.factions', { contains: factionId })` (002; FR-015).
- Events: `diplomacy.act.initiated`, `diplomacy.dispatch.started`, `diplomacy.message.delivered`, `diplomacy.dispatch.failed` (reason enum), `diplomacy.standing.changed`, `diplomacy.agreement.formed`, `diplomacy.agreement.cancelled`.
- Config constants (data): hostile gate -30; trade agreement threshold standing >= +20; war standing <= -50; gift standing delta (e.g. +10); trade-agreement priceMultiplier discount (e.g. 0.9x); affinity bias range; Envoy stuck timeout; AI cooldown; rejection penalty; per-tick war probability; `factionHostilityMultiplier` (027 FR-015).
- Player ops implied (no names): issue Gift/TradeAgreement/Declaration/Overture; respond to incoming (accept/counter/reject).

## 3. Functional requirements
- FR-001: Faction entity type in prototype registry with components name, factionType, leaderId, standing, disposition.
- FR-002: Membership in `Citizen.factions`; only source of truth; any number of factions; player government is a faction; Citizen also carries homeDwellingId/homeAssignedTick.
- FR-003: Exactly one leader at a time (entity id); leader destroyed -> `leaderId` null (leaderless; cannot receive dispatches until new leader); faction destroyed -> its standing entries removed from all other factions.
- FR-004: DiplomaticEnvoy entity type (distinct from TownCrier); pathfinds to target's current leader; destination updates dynamically.
- FR-005: DiplomaticMessage fields above.
- FR-006: On delivery, standing changes applied immediately to both maps (independently); emit `diplomacy.message.delivered`; negative deltas an NPC faction applies toward player faction scaled by difficulty `factionHostilityMultiplier` (027).
- FR-007: Standing clamped [-100,100]; default 0.
- FR-008: Consequences: trade (019) standing < -30 refuses, agreement gives priceMultiplier discount; affinity (013) first-meeting offset = average standing across shared faction pairs mapped to configurable bias range; labour (017) standing < -30 -> won't accept jobs from the hostile faction.
- FR-009: Four acts: Gift (deduct from sender treasury, deliver to leader inventory), Trade Agreement (sets `tradeAgreement:true` on both entries if accepted), Declaration (sets standing to configured value; war/peace/neutrality), Overture (faction AI evaluation, may counter-dispatch).
- FR-010: Gift deducts items/currency from sender treasury (Throne Room containers for player) before dispatch; insufficient funds -> act blocked.
- FR-011: Events listed above.
- FR-012: NPC faction AI evaluates each tick by disposition, standing, resource/need state; 0 or 1 acts per tick per faction (cooldown configurable); hostile-act weight toward player scaled by `factionHostilityMultiplier`.
- FR-013: Incoming NPC envoys arrive at player's faction leader; player may accept, counter-dispatch or reject (reject = small configurable standing penalty); hostile deltas scaled by `factionHostilityMultiplier`.
- FR-014: Serialize standing maps, leader refs, `Citizen.factions`, pending envoys.
- FR-015: Entity queries support list containment on `Citizen.factions`.

Rules: leader moves -> envoy re-queries position, intercepts; new leader assigned mid-transit -> envoy retargets; sender leader dying after dispatch doesn't stop delivery; simultaneous mutual war declarations independent; destroyed faction -> pending envoys targeting it recalled; war cancels trade agreement (`tradeAgreement:false`, `diplomacy.agreement.cancelled`); each act = own envoy; envoy stuck for timeout -> `unreachable`, returns, act not applied; envoy destroyed -> `envoy-destroyed`; leaderless NPC faction sends nothing; standing crossing hostile threshold cancels pending TradeOffers (`faction-hostile`).

## 5. Ambiguities / contradictions / blockers
1. Open question: Gift refund when dispatch fails after deduction (leader unavailable/unreachable/envoy destroyed).
2. Labour gate has no hook in 017: postings carry no poster/faction field and entity-side claim predicate list doesn't exist; also which faction "posts" a job on a system board.
3. Trade-agreement acceptance threshold: AC says "standing >= 20" for proposal and "above acceptance threshold" for AI evaluation (not same thing); mutual consent AI decision procedure (disposition weights) unspecified. Discount mechanism: affects seller `priceMultiplier` per-trade not stored (019 treats multiplier as base).
4. Standing deltas per act/event are unspecified numbers (gift +10 "e.g.", war <= -50 "configured", peace/neutrality target values, passive events: completed trades, attacks, broken agreements have no deltas or event sources). Sender-side standing change on delivery and "asymmetric both maps" rules per act undefined. Gift value scaling (currency amount vs fixed +10).
5. NPC factions' physical presence: leaders must be real entities with positions; NPC "seat of government" origin of NPC envoys unspecified; multi-map / off-map factions unsupported yet NPC diplomacy implies external factions. Where do NPC leaders exist (on this map)? Envoy spawn location for NPC senders.
6. Leader succession: "until a new leader is designated" - no mechanism/who designates (player faction leader, NPC). Player faction leader assignment (throne occupant?) undefined; "Head of Government" entity concept.
7. Envoy attack/destruction implies combat/hostiles, not in any spec; what happens to the gift cargo; envoy fleet limit absent (unbounded spawn); envoy as entity (needs, AI) and respawn at "government seat"; "returns to sender" vs "returns to base".
8. Incoming-proposal UI: player response commands/event names (accept/counter/reject) not defined; response delivery requires an outbound envoy? Rejection penalty applied to which faction ("refusing faction").
9. Affinity baseline: "average across shared faction pairs" - pairs are cross product of each entity's factions? Unclear when entity has no factions; mapping function to bias range; 013 hook doesn't exist in this spec's neighbours.
10. Declaration of peace semantic: sets standing to a value; improving from hostile; also war cancel of agreement only on war.
11. `Citizen.factions` implies only citizens belong to factions - what about non-citizen entities (leader is "a specific entity", animals, envoys)? Leader must have Citizen component?
12. Hostile threshold -30 consistent with 019; war sets <= -50; "disposition is static prototype data and does not change" contradicts NPC AI evaluation using standing? no, fine; but disposition weights unspecified.
13. Faction destroyed definition ("all members gone") requires member-count check by query each tick; cost.
14. Performance of per-tick NPC evaluation and `Citizen.factions` list-contains queries (index needed in 002).

## 6. Acceptance scenarios / tests
- US1: Faction has name/type/leader/standing; derive members via query; citizen in two factions returns both; `getEntitiesByProperty('Citizen.factions',{contains})` returns only members; player govt faction same schema; serialization preserves standing/leader and derived members (SC-005).
- US2: envoy paths to leader's current tile; leader moves -> re-query/continue; leader destroyed -> `diplomacy.dispatch.failed` `leader-unavailable`, envoy returns; new leader assigned mid-transit retargets; player faction has leader reference. SC-003, SC-004.
- US3: default 0; gift 100 currency -> +10 clamped; war -> <= -50 (worse of current); cap at 100; asymmetry.
- US4: gift act spawns envoy at Throne Room seat; envoy payload/destination/status inspectable; delivery emits `diplomacy.message.delivered` and applies standing; one envoy per act; stuck -> `unreachable`.
- US5: gift 500 deducted pre-dispatch, appears in leader inventory, standing up; trade agreement with standing >= 20 -> `tradeAgreement` both maps; war -> standing <= -50 and agreement auto-cancelled (blocks trade); overture response by standing/personality; insufficient treasury blocks initiation.
- US6: -60 standing -> TradeOffer rejected `faction-hostile`; +50 standing warmer affinity; -40 standing -> members skip player's jobs; agreement reduces seller priceMultiplier (0.9x); crossing hostile threshold cancels mid-negotiation offer. SC-002 100%.
- US7: mercantile NPC with neutral standing and surplus resource sends trade-agreement overture to player's leader; incoming proposal accept/counter/reject with penalty; aggressive faction at standing <= -20 has per-tick war probability; ally attack -> war declaration cancels agreement; leaderless NPC sends nothing. SC-007 AI produces an act in a standard run.
- Edge: simultaneous war declarations; destroyed faction clears references and recalls envoys; envoy destroyed; save/load SC-006 (no orphaned envoys).

Entities, standing model, envoy pathing with dynamic retargeting, NPC AI, and three cross-system hooks; many unspecified numbers.
