# Digest 009 - Quick Room Generator

## 1. Purpose
Deterministic, square-grid-only fixture/test room generator: one call returns one populated room (walls, floor, 10-20 entities, 5-10 objects, starter inventories) ready for tick simulation.
Supports scenario types (Trade/Interaction/Navigation), size/count/density params, validation+retry, and is the Principle-IV scenario-fixture source.

## 2. Module/API (as stated)
- `RoomGenerator` - stateless utility/module (class or module); `RoomGenerator.generate(options?: GeneratorOptions): Room`.
- `GeneratorOptions` = `{ size?: RoomSize; entityCount?: number; objectDensity?: number /*0-1*/; seed?: number; scenarioType?: ScenarioType }`. (US5 text also mentions `objectCount: 0` as invalid - NOT a listed param, see 5.)
- `enum RoomSize { Small, Medium, Large }` : ~15x15, ~25x25, ~40x40 (FR-002, "~" = approximate, exact values not fixed).
- `enum ScenarioType { Trade, Interaction, Navigation }`.
- `Room`: map grid + entity list + object list; serializable, GameState-compatible (spec 006). Generation parameters (incl. the seed actually used) are stored in GameState so room is regenerable.
- Walls are wall entities occupying a cell (spec 004); boundary cells + interior obstacles (Navigation: corridor-based layouts).
- No event names, commands or JSON shapes defined. Inventory examples: merchant ~500 currency, 10 wood, 5 cheese; worker hammer/chisel; pool example 10,000 currency total.

## 3. Functional requirements
- FR-001 `generate(options?)` returns fully populated room (entities, objects, terrain).
- FR-002 Square grid, floor + wall entities; sizes small~15x15 / medium~25x25 / large~40x40; no Voronoi/hex.
- FR-003 Default 10-20 entities (citizens, NPCs); `entityCount` overrides (min 1); random walkable positions; no two on same tile.
- FR-004 Default 5-10 objects (furniture, containers, resources), scaled by `objectDensity`; walkable tiles; reachable by pathfinding.
- FR-005 Placement deterministic per seed.
- FR-006 No seed => use a derived stream of engine PRNG (spec 011), never time-based; used seed stored with generation params.
- FR-007 ScenarioType enum; each seeds appropriate entities/objects.
- FR-008 Trade: merchant/customer roles, starter inventory with currency + tradeable goods.
- FR-009 Interaction: worker roles, tools/equipment, job-capable components.
- FR-010 Navigation: entities in multiple walkable regions.
- FR-011 Valid rooms: on walkable tiles, connectivity intact, no collisions.
- FR-012 Validate before return; reject with descriptive error or auto-retry.
- FR-013 Params: size, entityCount, objectDensity (0-1), seed, scenarioType.
- FR-014 Validate all params at call time with clear errors.
- FR-015 Output JSON-serializable via GameState (006), round-trip identical.
- Clarifications: same seed + same scenarioType => same layout; different scenarioType => different population. Retry "up to N times with minor layout adjustments", then clear error (N unspecified). Too many entities for free tiles => retry with larger room/fewer entities, else error. Stack-limit violations (spec 005) => generator adjusts quantities. entityCount 0 / objectCount 0 rejected (>=1 each).

## 4. Dependencies
Consumes: 004 (square map, wall entities, floor terrain), 005 (inventory stack limits), 006 (GameState serialization, entity prototypes registered, Transition n/a), 007 (bootstrap/PRNG seeded, state record), 011 (derived PRNG), 012 (connectivity/pathfinding checks), 003 (job-capable components), materials registry (014/022), entity prototypes (Citizen, Merchant, Worker - NOT defined here). Provides: fixtures for all scenario/integration tests.

## 5. Ambiguities / contradictions / blockers
- Seed semantics: `options.seed` (number) vs FR-006 derived stream. Unspecified: with explicit seed, does it construct a private PCG(seed) or `prng.derive("room-gen:"+seed)`? Does it consume main PRNG? 011 Assumption says generator "receives a derived PRNG" (name not given; 011 US4 example "room-gen"). Pick: private PRNG from seed; when absent, `derive(name)` and persist the resulting numeric seed.
- "Stateless" vs deriving a named stream (derive() returns same initial state per call => two no-seed calls in a game give identical rooms unless unique names/seed recorded). Needs a per-call unique derive name (e.g., counter) - unspecified.
- `objectCount` is validated in an edge case but not in FR-013 params; objectDensity base/scale (what density=1 means vs 5-10 default) undefined.
- Float `objectDensity` 0-1 vs Constitution fixed-point (only options, not state; acceptable but clarify).
- "Room" term collides with spec 015 Room (enclosed zone); here "room" = a whole map. Rename in code (e.g. `GeneratedRoom`/`FixtureMap`).
- Return type: "populated game world" (US1) vs "room instance" (Key Entities) vs "Room contains map grid, entity list, object list". Does generate() mutate GameState/add entities, or return data to be inserted? Unspecified.
- Retry N, "minor layout adjustments", and error type/class names undefined. Perf: SC-001 200ms vs US4.4 validation <50ms vs edge "500x500 <1s" yet sizes max ~40x40 (500x500 not reachable via RoomSize).
- Entity prototype ids, material ids, quantities (500 currency, 10,000 pool, "currency conserved") not data-defined; "10,000 distributed across merchants and consumers" vs per-merchant 500 not reconciled. US5.5 "goods degrade/transform" depends on perishability not defined here.
- "mix of citizens and NPCs": NPC definition absent; navigation scenario entity/object mix unspecified; "5-10 objects" in Navigation/Trade (stalls/benches) vs default count.
- Walkability check: all objects "on walkable tiles" but furniture may make cell non-traversable (spec 004/012 furniture sets cell non-traversable) - objects must be placed adjacent/interactable, not on blocking cells; contradictory with "reachable".
- Door entities absent from spec though 015/012 depend on doors.
- Citizen identity (spec 028) and dwellings (029) not considered: generated citizens need names/household? out of spec.

## 6. Tests to derive
US1: seed 42 -> grid map, 10-20 entities, 5-10 objects; same seed twice -> identical layout/positions/placement byte-for-byte (SC-002); all entities on walkable non-wall tiles; 15-entity room serialize/deserialize round trip; interactions with furniture/containers succeed.
US2: Trade (merchants+customers with currency/goods, benches/stalls; trade exchange works), Interaction (workers with tools; workbench/loom/forge), Navigation (multiple pathable areas separated by obstacles; path computed across). Seed 42 trade != seed 42 navigation.
US3: Small ~15x15 fewer entities; Large + entityCount 5 -> large grid with 5 entities; determinism across params; invalid params ("huge", entityCount 0, objectCount 0) rejected with clear errors; stored params regenerate identical room.
US4: 1000+ random seeds/params all valid (0 collisions, 100% walkable, 100% connected); validation <50ms on large; invalid config errors or retries.
US5: merchant currency+goods, worker tools, all entities food; total currency pool conserved/sensible; same seed => identical inventories; stack limits respected.
SC-001 <200ms; SC-006 runs in plain Node. Edge: more entities than free tiles; disconnected regions retry/error.
