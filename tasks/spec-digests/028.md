# Digest 028 — Citizen Identity & Chronicle

## 1. Purpose
Every Citizen gets a deterministic period name (seeded `identity.names` stream), a derived (never stored-authoritative) skill title ("Ansel the Baker" / "Master Baker" + offices), structured NotableMoments (events + per-citizen bounded journal + settlement chronicle), and a rename command; all text comes from content templates via a pure helper.

## 2. Module layout / public API
Implied: `identity/` (naming, title derivation, finest tracker, moment recorder, journal, chronicle, formatter helper `formatMoment/formatStyledName`), content: name-list registry (022 FR-021), skill `titleNoun`, guild `masterSkillThreshold`, moment & name-format template table (fixed-key config, 022 FR-018), renderer 024 FR-038..041.
Components: `Identity { givenName, byname|null, nameOrdinal (0=none), nameListId, titleSnapshot, journal: NotableMoment[] }` on every entity with `Citizen`; `SettlementChronicle` on player government faction: Major moments list, finest-holder table (per skill `{entityId, level, sinceTick, lastAnnouncedTick}`), next momentId.
Types/enums: `TitleRank {None, Practitioner, Master}`; Title `{ skillId, rank, noun, guildId|null }`; `offices: [{ factionId, leaderTitle }]`; `NotableMomentKind {Arrived, TitleEarned, MasteryAchieved, BecameFinest, LostFinest, JoinedGuild, LeftGuild, TookOffice, LostOffice, FirstWork, FirstTrade, HomeImproved, Renamed, Died, SettlementMilestone, TierReached}`; `MomentProminence {Minor, Major}` (Major: Arrived, MasteryAchieved, BecameFinest, TookOffice, Died, SettlementMilestone, TierReached; Minor: rest); `NotableMoment { momentId (monotonic), tick, kind, entityId|null, nameSnapshot|null, params (strings/ints only: skillId, guildId, factionId, milestoneId, dwellingLevel, previousName, tier) }`.
Name-list entry: `{ id, givenNames[], bynames[], weight? per name }`; default `common_13c` >= 60 given, >= 40 bynames. Prototype fields: `nameListId?`, `givenName?`, `byname?`.
Commands/queries: `renameCitizen { entityId, givenName, byname|null }`; `getIdentity(entityId)` -> given, byname, ordinal, full name, title, offices, styled name; `getJournal(entityId)`; `getChronicle({ entityId?, kinds?, sinceTick? })` (entityId filter works for deleted entities).
Events: `identity.named {entityId, givenName, byname, nameOrdinal}`, `identity.title.changed {entityId, oldTitle, newTitle}`, `chronicle.moment.recorded {record + prominence}`.
Styled name templates: plain "{given} {byname}"; Practitioner "{given} the {noun}"; Master "{given}, Master {noun}"; office suffix " of the {factionName}" when leaderTitle equals Master title else ", {leaderTitle} of the {factionName}". Moment template placeholders: {name},{noun},{nounLower},{skillName},{guildName},{settlementNoun},{day}; e.g. BecameFinest: "{name} hath become the {settlementNoun}'s finest {nounLower}". Steward office title "Steward" lives in the name-format templates.
PRNG stream: `identity.names` (011 `derive`). Constants (022 FR-023): `titleThreshold`=20, `titleSwitchMargin`=5, `finestMinimumLevel`=30, `finestCooldownDays`=3, `bynameChance`=0.85 (stored x1000 = 850), `nameRedrawLimit`=8, `journalCapacity`=24, `chronicleCapacity`=200; renderer `toastBurstLimit`=3.

## 3. Functional requirements
- FR-001 Name-list registry entries; default list; duplicates within a list and bynames equal to any skill `titleNoun` are load errors.
- FR-002 Humanoid prototypes MAY declare `nameListId` (default common_13c); prototype/scenario MAY fix `givenName`/`byname` -> no draw.
- FR-003 Every Citizen carries Identity; names stored as strings.
- FR-004 Names drawn at Citizen creation from `identity.names`: weighted given name, then byname with probability bynameChance. If full name equals a living citizen of same government faction: redraw up to nameRedrawLimit; still colliding -> keep last draw, set nameOrdinal to lowest integer >= 2 unused for that full name. Draw count depends only on game state.
- FR-005 Emit `identity.named` on naming/rename.
- FR-006 Skills declare `titleNoun`; guilds carry `masterSkillThreshold` (022 FR-012; 0-100; > membership threshold; default 60).
- FR-007 Title derived from skills (020 FR-002), guild catalog, faction leadership, never authoritative profession. Practitioner: level >= titleThreshold; Master: also a guild's criterion uses that skill and level >= guild masterSkillThreshold (lowest across guilds using the skill; guildId = that guild); else None. Guild membership not required.
- FR-008 Title skill chosen ordering by rank (Master first) then level; keep current title skill unless candidate has higher rank or same rank with level >= current + titleSwitchMargin; no current -> tie by skillId ascending. May differ from 020 `dominantSkill`.
- FR-009 Leaders (faction.leaderId) expose offices ordered by faction entity id with the faction's leader title (022). Steward (026 `stewardEntityId`) adds `{ factionId: player government, leaderTitle }` after faction leaderships; title text from name-format templates ("Steward").
- FR-010 Identity stores `titleSnapshot` for change detection; recompute on `skill.increased` (020 FR-013) and faction membership/leadership change; emit `identity.title.changed` when differs; at most one per citizen per event processed.
- FR-011 Pure headless `getIdentity` and formatter using templates.
- FR-012 NotableMomentKind enum + fixed prominence.
- FR-013 Moment sources only: creation as settlement member or later joining player government (Arrived); `identity.title.changed` (TitleEarned when new rank Practitioner and skill/rank changed upward; MasteryAchieved when Master); finest tracking; Citizen.factions change involving an occupational faction (Joined/LeftGuild); faction leaderId change or `steward.appointed`/`steward.dismissed` (TookOffice/LostOffice); first `skill.work.completed` (020 FR-005) per skill per citizen (FirstWork); first `trade.completed` (019 FR-010) as buyer or seller (FirstTrade); `housing.dwelling.upgraded` (029 FR-020), one HomeImproved per resident with dwellingLevel=toLevel; rename (Renamed); `entity.deleted` of citizen (Died); `settlement.milestone.reached` (SettlementMilestone, milestoneId); `settlement.tier.reached` (TierReached, tier). Creation-time title changes record no moments.
- FR-014 Moment = JSON record; recording emits `chronicle.moment.recorded`; recorded only for members of player government faction, except SettlementMilestone/TierReached (entityId null).
- FR-015 Finest tracking per skill over living settlement citizens: strictly exceeding holder and >= finestMinimumLevel -> becomes holder; BecameFinest (new) + LostFinest (previous) recorded only if >= finestCooldownDays (288 ticks/day) since lastAnnouncedTick, else silent change; holder dies/leaves -> recompute by scan (highest level, ties lowest entity id) with no moments.
- FR-016 Moment text never stored; content template per kind (and per journal form) with placeholders; `{settlementNoun}` = current tier noun (027 FR-001); pure helper usable headless.
- FR-017 Identity.journal: ordered moment records concerning citizen (Minor+Major), max journalCapacity; when full drop oldest non-Arrived entry; non-members keep empty journal; Arrived recorded when joining.
- FR-018 SettlementChronicle on player government faction: Major moments (incl. milestones/tier), recording order, max chronicleCapacity (oldest dropped), plus finest table and next momentId.
- FR-019 Queries getJournal/getChronicle; entityId filter works for deleted entities.
- FR-020 renameCitizen validation: given 1-40 chars, byname 0-40, trimmed, printable, no control chars; else rejected with validation error. Applies ordinal rule (no redraw), records Renamed(previousName), emits identity.named.
- FR-021 Serialize all identity state incl. `identity.names` stream; save/load reproduces identical names/titles/moments/journals.
- FR-022 Renderer: styled name everywhere (map label hover, panel header, job/trade records), rank+offices in panel, "Journal" tab (024 FR-038, FR-039).
- FR-023 Renderer: Major moments as non-blocking notifications linking to citizen (or chronicle); > toastBurstLimit in one game hour folded into "N more tidings" (024 FR-040); Minor not notified.
- FR-024 Renderer chronicle view newest first, filter by citizen/kind (024 FR-041).

Hooks into 013-022: 020 (skill.increased consumed; titles don't mutate skills), 021 (leaderId/membership change events needed), 022 (name-list registry, titleNoun, masterSkillThreshold, templates, constants), 019 (trade.completed).

## 5. Ambiguities / blockers
- 021 events for `Citizen.factions` change and `leaderId` change are not named (028 FR-010/FR-013 depends on them; spec 021 only defines diplomacy events); need an event or direct component-change hooks. Same for "leaves the player faction" (026 FR-016, 027 FR-018).
- `entity.deleted` payload: by the time Died is recorded the Identity component may be gone; need pre-deletion hook or payload snapshot (last styled name). Also "Died" for citizens leaving map? Only deletion.
- Arrived is Major and 029 spawns up to maxImmigrantsPerDay (2) settlers/day, each recording a Major Arrived -> contradicts SC-005 ("<= 2 Major per game day on average") and floods chronicle (capacity 200 = ~100 days) and toasts (burst limit 3).
- SC-006 (<=300 KB for 200 full journals + chronicle): 24 entries x ~150-200 B JSON x 200 citizens ~ 0.7-1 MB; infeasible as written unless records are compact or capacity lowered.
- FR-004 collision scope "same government faction" is evaluated at creation; a settler is named at spawn (029 FR-015) before/after joining the faction? Order of faction assignment vs naming not defined; a visitor named earlier then joining may duplicate a name (no re-check at Arrived).
- Initial title at creation: snapshot is set; does `identity.title.changed` fire at creation (suppresses moments only) or not? 027 FirstMasterCraftsman listens to the event; a prototype starting at Master (none today) would be missed/misfire.
- `titleSnapshot` vs 020 `dominantSkill` and 020's skills never decrease: Master rank permanence OK. But `masterSkillThreshold` edit (content) between versions can change rank without an event; ignore.
- `bynameChance` "default 0.85, stored x1000" mixes author decimal/fixed-point (006 FR-014): fine, but test fixtures must specify.
- Moment params ints/strings only, but TitleEarned/MasteryAchieved require which params (skillId, rank, guildId); not enumerated for most kinds. Per-kind params table missing (FirstTrade counterpart? JoinedGuild guildId; LostOffice factionId; Renamed previousName only? also newName?). Template placeholders `{day}` needs day derivation from tick (001 FR-011).
- "Arrived" when joining player faction later: any non-member -> member transition; journal retains earlier moments? (non-members have empty journal).
- Journal vs chronicle duplicates: Major moments recorded in both; `Died` is in chronicle only (journal destroyed).
- Potter titles (masonry noun) open question; sex/gender-neutral nouns open question.
- 028 US2 sc.4: Master rank outranks higher Practitioner skill (consistent with FR-008).
- US3 sc.5 visiting merchant: titles updated but no moments; `offices` for NPC faction leaders still apply.
- Journal "first completed work per skill per citizen" requires a persisted per-citizen set of seen skills beyond the journal (journal can drop entries) -> derive from journal fails once FirstWork dropped; needs an explicit stored set (not in FR-003/021).
- Rename ordinal ambiguity: "next free ordinal" when rename target equals own current name.
- identity.names stream consumption by non-settlement spawns affects settlement names (consistent per seed but order-sensitive).
