# Digest 027 — Settlement Tiers, Milestones & Difficulty

## 1. Purpose
Four monotonic settlement tiers (Hamlet/Village/Market Town/Chartered Town) advanced daily by data-driven requirements, gating new build/designate/craft/post commands via per-content `unlockTier`; fixed-at-start Difficulty (Peaceful/Steady/Harsh) with three x1000 multipliers (decay, need decay, faction hostility); once-per-game milestones.

## 2. Module layout / public API
Implied: `settlement/` (SettlementProgress component, tier evaluator, milestone detector, unlock gate, difficulty multipliers `combine()`), config files `settlement-tiers.json`, `difficulty-modes.json`; hooks in 005 (decay), 013 (needs), 014/015/016/017 (gates), 021 (hostility), 007 (newGame options), 006 (migration).
Enums: `SettlementTier {Hamlet:"hamlet", Village:"village", MarketTown:"market_town", CharteredTown:"chartered_town"}` (ordinal compare); `TierRequirementKind {Population, DwellingsAtLevel, ActiveZone, FoundedGuilds, MilestoneReached}`; `MilestoneKind {ThroneRoomEstablished, FirstWorshipSpace, FirstMarket, FirstGuildFounded, FirstMasterCraftsman, FirstTradeAgreement, FirstDwellingUpgrade}` with kebab payload form (`throne-room-established`, `first-worship-space`, `first-market`, `first-guild-founded`, `first-master-craftsman`, `first-trade-agreement`, `first-dwelling-upgrade`); `LockedContentKind {Furniture, ZoneType, Recipe, JobType, DwellingLevel}`; `Difficulty {Peaceful:"peaceful", Steady:"steady", Harsh:"harsh"}` (default Steady).
Types: `SettlementProgress { tier, tierReachedAtTick: {[tier]: tick}, milestones: MilestoneRecord[] }` component on player government faction entity; `MilestoneRecord { milestone, tick, subjectIds: int[] }`; `TierRequirement`: Population{min}, DwellingsAtLevel{level,min}, ActiveZone{zoneTypeIds,min}, FoundedGuilds{min}, MilestoneReached{milestone}; `ContentLockedError { contentKind, contentId, requiredTier }`.
Queries: `getSettlementProgress()` -> tier, settlementNoun, reach ticks, next-tier requirements `{kind, params, current, target, met}` (current computed at query time); `isUnlocked(contentKind, contentId)`; `getUnlockedAt(tier)`.
newGame options: `difficulty`, `startingTier` (stored in initOptions). Config: `settlement-tiers.json` (per-tier `settlementNoun`: hamlet/village/market town/town + requirements), `difficulty-modes.json` (`decayMultiplier`, `needDecayMultiplier`, `factionHostilityMultiplier`).
Events: `settlement.tier.reached {tier, previousTier, tick}`, `settlement.milestone.reached {milestone, tick, subjectIds}` (wildcard `settlement.**`).
Field: optional `unlockTier` on furniture, zone type, recipe, job type, dwelling level (`z.nativeEnum(SettlementTier)`; absent = hamlet). Constant `minFoundingMembers` (default 3, 022 FR-023). Combine rule: `sign(base)*trunc(|base|*m/1000)`, magnitude raised to 1 if both nonzero and result 0.
Defaults (assumptions, tunable): tier table: Village = Pop>=8, 4 dwellings >=Hovel, active Throne Room, active Chapel|Church; Market Town = Pop>=20, 8 >=Cottage, active Market, active Tavern, 1 founded guild; Chartered = Pop>=40, 12 >=TimberFramedHouse, 3 >=BurgherHouse, active Church, 3 founded guilds, FirstTradeAgreement. Multipliers: Peaceful 500/700/250; Steady 1000/1000/1000; Harsh 1500/1300/1500. Unlock slices per zone type listed in spec (Hamlet: stockpile, farm field, pasture, herb garden, quarry, fishing dock, charcoal yard, kitchen, carpentry, mason's workshop, bedroom, dormitory, chapel, guard post, throne room; Village: bakery, smithy, tannery, pottery, brewery, smokehouse, pantry, warehouse, orchard, apiary yard, tavern, market, cemetery; Market Town: weaving hall, wine cellar, vineyard, great hall, church, barracks, armory; Chartered: scriptorium, cloister).

## 3. Functional requirements
- FR-001 SettlementTier enum + order fixed in code; each tier in settlement-tiers.json declares lowercase `settlementNoun` (fills {settlementNoun} of 028 FR-016); engine produces no text.
- FR-002 One settlement per game owned by player government faction (021 FR-002); progress stored in `SettlementProgress` component on that faction entity (ints/enum strings).
- FR-003 Tier requirements authored in settlement-tiers.json (Zod, read-only after bootstrap); kinds with params (list above); DwellingsAtLevel uses 029 `countDwellingsAtOrAbove(level)`; ActiveZone uses active zones (015 FR-008).
- FR-004 Evaluate next tier once per game day at `tickCount % 288 == 0`, after population/zone/faction systems ran that tick; all met -> advance exactly one tier, set tierReachedAtTick, emit `settlement.tier.reached`; max one step per evaluation.
- FR-005 Tier never decreases; reached-tier requirements never re-checked.
- FR-006 `getSettlementProgress()` as above.
- FR-007 Optional `unlockTier` on furniture/zone type/recipe/job type/dwelling level (022 FR-022).
- FR-008 Locked content stays registered, browsable, referenceable, storable, tradeable. Reject with ContentLockedError (state unchanged): ConstructionJob queue for locked furniture (016 FR-016/017); zone designation of locked zone type (015 FR-003); production order/craft of locked recipe (014 FR-005 step 1, FR-016); new job posting of locked job type on any board (017 FR-003; recurring re-post exempt). Locked dwelling level is not a command target; blocks upgrade (029 FR-007 TierUnlocked).
- FR-009 `isUnlocked`, `getUnlockedAt(tier)` pure queries.
- FR-010 Load error if a tier requirement references a zone type whose unlockTier >= required tier T; for alternatives lists, at least one zone type must be unlocked below T; every tier reachable with content unlocked before it.
- FR-011 Load error if recipe unlockTier < lowest unlockTier of furniture carrying its required workstation tag, or < unlockTier of its required room zone type (014 FR-003).
- FR-012 Unlock effective at tick boundary where tier event emitted; later commands see new tier; nothing auto-built/posted/crafted.
- FR-013 Difficulty enum (007 FR-007) Peaceful/Steady/Harsh default Steady; stored in initOptions.difficulty, fixed per game; multipliers from difficulty-modes.json (x1000, non-negative ints; decimals authored OK per 006 FR-014).
- FR-014 Multiplier combine rule (above); sequential application in order listed per FR.
- FR-015 decayMultiplier scales per-tick decay of every perishable stack (005 FR-020) AFTER zone modifier: `combine(combine(1000, zoneModifier), decayMultiplier)`. needDecayMultiplier scales per-tick decay of every need of every entity with needs (013 FR-002; base rates from 022 need registry); critical thresholds and restoration amounts not scaled. factionHostilityMultiplier scales (a) every negative standing delta an NPC faction applies toward player faction (021 FR-006, FR-013), (b) selection weight NPC faction AI (021 FR-012) gives hostile acts (Declaration of war) targeting player; not positive deltas, not direct-set standings from a Declaration, not NPC-NPC.
- FR-016 Difficulty must not influence map gen, starting entities, content loading or any bootstrap PRNG draw: same seed -> identical maps/entities at tick 0.
- FR-017 Settlement member = living humanoid whose `Citizen.factions` contains player government faction id; Population = count via 021 FR-015 membership query.
- FR-018 Guild (factionType "occupational") is founded while leaderId non-null and >= minFoundingMembers members who are also settlement members; evaluated on membership/leadership change at tick boundary.
- FR-019 MilestoneKind enum + triggers: ThroneRoomEstablished (first Throne Room zone active, via zone.requirements.met), FirstWorshipSpace (first Chapel|Church active), FirstMarket (first Market zone active), FirstGuildFounded (FR-018), FirstMasterCraftsman (from 028 `identity.title.changed` new rank Master, settlement member; masterSkillThreshold default 60), FirstTradeAgreement (`diplomacy.agreement.formed` involving player faction, 021 FR-011), FirstDwellingUpgrade (`housing.dwelling.upgraded`, subjectIds holds dwelling id).
- FR-020 Milestone recorded at most once per game as MilestoneRecord; emits `settlement.milestone.reached`; detected from events at the tick boundary they occur (not daily).
- FR-021 startingTier records no milestone.
- FR-022 newGame accepts `startingTier` (default Hamlet): settlement starts at that tier, tierReachedAtTick 0 for it and all lower, no tier events; stored in initOptions.
- FR-023 Progress state serializes with component; requirement status derived, not stored.
- FR-024 Save migration: legacy `normal`->`steady`, `hard`->`harsh`.
- FR-025 Emit the two events (spec 010 naming).
Validation message: "Invalid difficulty: 'normal'. Valid values: peaceful, steady, harsh."

## 5. Ambiguities / blockers
- OPEN (self-declared): Hamlet slice not self-sufficient for iron (Mason's Bench needs Iron Chisels, Throne needs Iron Ingots, Smelter/Forge in Smithy at Village) so Village is unreachable from Hamlet content -> violates FR-010/SC-003. Blocks scenario SC-001 until content decision (starting kit / move forge to Hamlet / change costs). Also check 022 has already reconciled (022 table shows Notice Post/Bell Tower tiers consistent).
- Dwelling zone type (`dwelling`, 029 FR-001) is not in any 027 unlock slice (absent = Hamlet; fine but table incomplete). Dwelling-level unlockTier values (e.g. Burgher House) are not assigned here; tie to tier table (Chartered needs 3 Burgher Houses; Burgher House requires Church, Weaving Hall cloth: unlocked at Market Town, Tapestry source unverified) -> reachability proof needed for FR-010 beyond zone types (only zone types are validated; furniture/recipe reachability for dwelling requirements is not).
- Tier evaluation tick (tick%288==0) vs 029 housing eval at tick-of-day 72 and 026 review at 72: tier lags dwelling upgrades up to a day; also at tick 0 the evaluation runs on a fresh game (no-op).
- FR-004 hard-codes 288; should use ticksPerDay constant (001 FR-011).
- Multiplier on decay: "after zone modifier" but spec 018 pantry modifier may be a rate or multiplier; combine() on a base of 1000 composition assumed; 005's own rate unit must be x1000 milli. Min-magnitude-1 rule means decay can never reach 0 for positive multipliers; with Peaceful need decay 700 on base 1 -> 1.
- FR-015(b) selection weight scaling: 021 FR-012 AI weights format unknown (fixed-point?). "Rejecting Envoy -8 -> -2" test requires scaling at point of delta application; rounding combine on -8*250/1000 = -2 OK.
- Who applies `LockedByTier` for existing content loaded from scenario (025/026) vs FR-008: consistent.
- Milestone FirstWorshipSpace/FirstMarket detection "first Chapel or Church / Market zone becomes active" via zone.requirements.met; scenario with startingTier and pre-existing active zones: do milestones fire when zones activate in play? (yes presumably); FR-021 says startingTier grants none, but a scenario already containing active Throne Room at tick 0 emits zone.requirements.met at bootstrap? unspecified.
- FirstMasterCraftsman depends on 028 title rank; 028 recomputes titles only on `skill.increased`/faction events; consistent. Master of non-settlement members excluded? FR-019 says "settlement member".
- Guild founding event: FR-018 "evaluated whenever membership or leadership changes" -> requires 021 events for membership/leader changes (not named; 021 stores membership on Citizen.factions without a change event?).
- Peaceful only scales *standing* hostility; no raids exist (assumption), so SC-006 "count of hostile diplomatic acts at most half" relies on weight scaling only: 250/1000 vs rounding of discrete weights.
- Change difficulty mid-game and in-world charter: open questions.
- Pre-existing 007 text already mentions Peaceful/Steady/Harsh and 006 already lists migration; verify 007 FR-007 no longer has Normal/Hard.
