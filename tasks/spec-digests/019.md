# Digest 019 - Trade System & Currency

## 1. Purpose
Currency is a normal stackable material (stack 1000), treasury = currency in storage furniture in the Throne Room zone. Peer-to-peer trade: buyer proposes TradeOffer to any entity with `sellsItems`; seller applies base value x priceMultiplier x (1+margin) check, accepts/counters/rejects; execution is atomic. Workers earn wages from the treasury on job completion.

## 2. Implied module layout / public API
Module: trade (offers, seller evaluation, execution) + treasury/wages (PendingWagePayment queue).
- Material registry field: `value` (base price in currency units, read-only at runtime). Currency material: `stackLimit:1000`. No Currency component.
- Entity fields: `sellsItems` (bool; runtime-togglable, FR-008b), `priceMultiplier` (fixed-point, default 1000 = 1.0; runtime-updatable by entity), `minimumMarginRate` (fixed-point, default 100 = 0.1). Config: `maxNegotiationRounds` (default 3), offer expiry timeout (ticks, configurable), faction hostile threshold (021, -30).
- `TradeOffer` (non-persistent data, but pending ones serialized): buyerId, sellerId, requested items (materialId x quantity), offered payment (currency amount and/or barter items), creationTick, expiryTick (+ negotiation round count implied).
- `PendingWagePayment` (serializable): jobId, workerEntityId, wage amount, due tick; retried each tick.
- `PlayerTreasury`: virtual aggregate (via 018 storage query) of currency in Throne Room storage furniture.
- Events: `trade.offer.proposed|accepted|countered|rejected|cancelled|expired`, `trade.completed` (buyerId, sellerId, items, tick), `trade.execution.failed` (reason `buyer-inventory-full`|`seller-inventory-full`), `treasury.payment.deferred|completed`. Reject reasons: `insufficient-stock`, `unknown-item-value`, `faction-hostile` (021). Warning event when no treasury containers.
- Errors: `InventoryFullError`.
- Price formula: `minAcceptable = ceil(basePrice x priceMultiplier x quantity x (1 + minimumMarginRate))` in integer fixed-point arithmetic.

## 3. Functional requirements
- FR-001: Currency registered as stackable item, stackLimit 1000, no special component.
- FR-002: Any Inventory holder may hold currency under standard rules.
- FR-003: Treasury = collective inventory of storage furniture within active Throne Room zone; balance = sum. Inflows include daily household rent (029 FR-013) moved directly into containers.
- FR-004: TradeOffer structure: buyer, seller, requested items, offered payment (currency and/or barter), expiry timeout.
- FR-005: Buyers initiate via `trade.offer.proposed`; any AI entity (013) may initiate when it has a need and a seller with `sellsItems`.
- FR-006: Materials declare `value` (data-driven); no separate item value registry.
- FR-007: Seller converts offered payment to currency-equivalent using material `value`, compares to threshold; accepts or counters with minimum acceptable amount.
- FR-008: Seller prototype supports `priceMultiplier` (default 1.0) and `minimumMarginRate` (default 0.1), decimal-authored, fixed-point stored (defaults 1000, 100); entity may update multiplier at runtime.
- FR-008b: Any entity may set/clear `sellsItems` at runtime.
- FR-009: Execution atomic: both transfers succeed or both roll back.
- FR-010: Events listed above.
- FR-011: Counter chains bounded by `maxNegotiationRounds` (3); after limit offer expires.
- FR-012: Wages paid from Throne Room treasury to worker inventory; insufficient funds -> queue, retry each tick.
- FR-013: Worker inventory without space -> defer payment.
- FR-014: Serialize pending offers and queued wage payments.
- FR-015: Emit `treasury.payment.deferred` / `treasury.payment.completed`.

Rules: faction clarification: hostile standing (021, < -30) refuses TradeOffers both ways with `faction-hostile`; Trade Agreement gives configurable `priceMultiplier` discount (e.g. 0.9x; 021 FR-008); this spec's multiplier is base before faction adjustments. Worked examples: base 5, mult 1.0, margin 10%, 2 Food -> 11; offer 12 accepts, offer 9 counters 11; mult 1.5 -> 16.5 -> counters 17 (round up). Seller with reserved goods honours first accepted offer; partial quantity (1 of 2) counters for 1 or rejects; first offer by tick order wins on stock contention; self-trade rejected silently; barter item without `value` -> reject `unknown-item-value`; wage 0 = no transfer; no Throne Room containers -> balance 0, wages cannot be paid, warning event; buyer without any seller found -> no offer, fall back to other need satisfaction; pending offer expires after timeout; buyer may withdraw/escalate.

## 4. Dependencies
Consumes: 005 (inventory, atomic transfers, errors), 006, 010, 013 (AI need/initiation, sellsItems decisions), 014/022 (material `value`, definitions), 015 (Throne Room zone), 017 (JobPosting wage, job completion trigger; Throne Room shared with crier), 018 (storage query for sellers/treasury), 020 (trade skill growth, Greedy trait modifies margin), 021 (hostile gate, price discount), 029 (rent inflow).
Provides: currency material, treasury balance/draw, wage payout, trade events, `trade.completed` for 020 skill growth (should emit `skill.work.completed`), 025 ledger (Trade source, partial), 021 gift funding (FR-010).

## 5. Ambiguities / contradictions / blockers
1. Wage on JobPosting: 017 FR-003 has no wage field and no completed-job worker payload; payer ("JobBoard or posting entity") and trigger event undefined.
2. Fixed-point vs whole-unit currency: Constitution says state numbers are x1000 milli-units; currency quantities here are whole units (stack 1000, rounding up to whole currency units). Inventory quantity representation in 005 must be reconciled (are item counts integers not milli-units? Material `value` in "currency units" authored decimal -> fixed-point?).
3. Buyer must be physically near seller? Trade geography undefined (does buyer path to seller, interaction range, seller busy?). Execution timing relative to accept ("awaiting execution when saved") vs "synchronous within a tick": what makes an accepted trade wait? Edge cases mention reserved goods/payment (seller reserve, buyer reserved payment) but no reservation mechanism or inventory hold is specified.
4. Negotiation protocol undefined: how buyer responds to `countered` (re-propose? new event?), what increments the round counter, timeout length, who handles offers when seller is player-colony vs NPC.
5. Barter valuation: seller values buyer's offered items at material `value` (with or without multiplier/margin on the received side?). AC says "applies same priceMultiplier and minimumMarginRate" to the Stone lookup - ambiguous direction.
6. Currency-equivalent when mixed payment; rounding for barter totals; seller's cost basis vs base `value` ("cost basis plus margin" in prose vs formula uses base price).
7. Trait hook: 020 "Greedy" adds +0.05 to `minimumMarginRate`; 019 has no trait modifier step in evaluation. Likewise trading skill outcome (better margins) and the skill-growth event.
8. Which entity types qualify as `sellsItems` sellers when player-colony treasury (storage furniture) draws; does seller's reserved stock appear in 018 queries?
9. Throne Room "active" status requires Throne (017); multiple Throne Rooms summed; per-container filters may block currency.
10. Faction hostile cancellation of in-flight offers (021 US6 AC5) needs standing-changed hook -> `trade.offer.cancelled` reason `faction-hostile`; not in this spec's FR list.
11. Settlement imports/exports for ProductionLedger (open question in spec).
12. Wage draw order "order retrieved by storage query" - requester/proximity used for ordering unspecified; determinism requires stable tie-break.
13. Entity destroyed mid-trade: `trade.offer.cancelled` vs `trade.execution.failed` (no reason string given for destroyed seller).

## 6. Acceptance scenarios / tests
- US1: 500 stored -> one stack; 800 + 400 -> 1000 + 200 overflow; all stacks full -> `InventoryFullError`, sender retains; same query API as other materials; serialization exact. SC-001.
- US2: Throne Room with two chests (500 each) -> treasury 1000; chest full -> flows to other, else deferred; container removal changes sum; wage draw via storage query; new coffer counted without registration.
- US3: Citizen with Food need + 20 currency emits `trade.offer.proposed` (buyer, seller, Food x2, currency x10); barter/mixed offers; timeout expiry and re-attempt; withdraw/escalate; no sellers -> no offer; toggling `sellsItems` on/off.
- US4: threshold 11: offer 12 -> accepted; offer 9 -> `countered` at 11; mult 1.5 -> counter 17; barter Stone evaluation; second buyer vs reserved goods; partial stock.
- US5: successful exchange (20 cur/5 Food -> 10 cur+2 Food / 10 cur+3 Food); buyer full -> cancelled, `trade.execution.failed` `buyer-inventory-full`, unchanged; seller full -> `seller-inventory-full`; `trade.completed` payload; save/load pending trade completes or cancels cleanly. SC-002 atomicity 100%.
- US6: wage 15 from 100-treasury -> worker +15, treasury 85; treasury 5 -> queued, `treasury.payment.deferred`, paid later with `treasury.payment.completed`; accumulation across jobs; wage 0 no transfer; worker inventory full -> deferred. SC-003 end-to-end loop, SC-005 deferred wages eventually paid, SC-006 save/load, SC-007 negotiation bound.
- Edge: buyer/seller destroyed; simultaneous buyers (first by tick order, other `insufficient-stock`); unknown-item-value; self-trade silent; no Throne Room containers warning; counter chain limit 3; hostile faction reject `faction-hostile`; agreement discount.

## 7. Size: L
Atomic exchange + negotiation state machine + wage queue + treasury aggregate; modest per-part but many interfaces and underspecified protocol.
