# Digest 018 - Stockpiles & Storage

## 1. Purpose
Storage furniture = ordinary Inventory-bearing entities (data-defined prototypes); Stockpile is a routing-designation zone type (no inventory) with optional material filters; Pantry is an enclosed-room zone that scales perishable decay. Defines tiered hauler routing and a unified synchronous material-source query.

## 2. Implied module layout / public API
Module: storage (filters, routing, StorageQuery) + zone-type data (Stockpile, Pantry) + decay-modifier hook into inventory (005).
- Storage furniture prototypes (Box, Cabinet, Bookcase, Barrel, Chest...): Inventory component params `slotCount`, `weightLimit?`, `defaultMaterialFilter?`.
- `MaterialFilter` component (on a storage entity or a stockpile zone): `{ categories?: string[], materialIds?: string[] }` (e.g. `{categories:["food"]}`, `{materialIds:["iron_ingot","copper_ingot"]}`). Absent = accept all. Deposit-time only.
- Zone types: `Stockpile` (routing designation, optional zone-level MaterialFilter, player-configurable post-designation), `Pantry` (`requiresRoom:true`, min tile size = balance constant, effect `{ type:"entity.modifier", modifier:"inventory.decay.rate", value:<int x1000> }`, e.g. 500 = 50% rate).
- `StorageQuery`: request (materialId, quantity, requester) -> ordered list of `(source entity, quantity, distance)`; multi-source; excludes inaccessible. Sources: storage furniture and hauler inventories.
- Errors reused: `WeightLimitExceededError`, `InventoryFullError` (005).
- Events: `storage.no-compatible-destination`; BlockedReason `NoStorageDestination { materialId }`.
- Haul param `deliverToZoneId` (spec 026 FR-020). No explicit function names given.

## 3. Functional requirements
- FR-001: Storage furniture are ECS entities with Inventory; behaviour entirely from inventory system (005).
- FR-002: Storage prototypes in registry (003) with configurable slot count, optional weight limit, optional default filter.
- FR-003: Stockpile zone type in zone registry (015); routing designation only, no inventory.
- FR-004: Stockpile zone may carry filter; per-furniture filter overrides zone filter; configurable after designation.
- FR-005: Filters enforced at deposit time; haulers check zone and furniture filters; rejected materials redirect.
- FR-006: Filter updates never evict existing contents.
- FR-007: Pantry zone type: requiresRoom, min size, decay effect (fixed-point); combines with difficulty `decayMultiplier` per 027 FR-015 (Pantry first, then difficulty).
- FR-008: Pantry modifier applies to perishable items in inventories of furniture whose position is on a tile in an active Pantry; non-perishable and outside unaffected.
- FR-009: Modifier applied/removed dynamically on zone (de)activation and furniture moving in/out.
- FR-010: Hauler routing tiers: (0) for runs with `deliverToZoneId` (026 FR-020) compatible storage in that zone; (1) profession-affinity zone storage matching material where zone affinity matches hauler's skill-derived affinity (dominant skill / above threshold, 020); (2) explicitly filtered storage matching material; (3) compatible furniture in a Stockpile zone; (4) any other compatible open storage. Nearest accessible wins within tier. Furniture on dwelling tiles (029) excluded from all tiers (029 FR-017). US5 tiebreak: more available space preferred, else PRNG deterministic.
- FR-011: Unified material query: (materialId, quantity) -> all accessible inventory-bearing entities on current map containing it, sorted by proximity to requester.
- FR-012: Query excludes inaccessible (locked, unreachable); checked at query time; dwelling-tile storage accessible only to that dwelling's residents (029 FR-017).
- FR-013: Multi-source fulfilment: list of sources whose combined quantity meets request.
- FR-014: All storage state (inventories, filters) serializes (006).
- FR-015: Emit `storage.no-compatible-destination` when no valid storage; also BlockedReason `NoStorageDestination`.

Rules/constants: Pantry value fixed-point x1000 (500 = half rate: 48h -> 96h expiry); multiplier 0 = never expires, valid; deactivation: decay resumes normal from current remaining time, no retroactive penalty; chest moved out of Pantry stops benefiting; removed stockpile designation leaves furniture/contents unchanged; no eviction; query perf <10ms for 100+ entities; queries synchronous in-tick; full storage -> hauler holds material and emits event, no deadlock; mixed carried materials routed independently; hauler inventory serialized with route resumption.

## 4. Dependencies
Consumes: 003 (prototypes), 005 (inventory, perishability tick-based, errors), 006, 013 (hunger queries), 014/022 (material categories, perishable flag), 015 (zone types, effect schema `entity.modifier`, Room status, disjoint zones), 016 (construction places storage), 020 (skill-derived affinity), 025 (BlockedReason), 026 (`deliverToZoneId`), 027 (decayMultiplier), 029 (dwelling exclusion/access).
Provides: StorageQuery to 016 (materials), 014 production, 019 (treasury sum, buyer seller discovery), 013; Stockpile/Pantry zone definitions; routing for haulers (022 haul job types).

## 5. Ambiguities / contradictions / blockers
1. Hauler "sources" in query: removing items from a hauler carrying them is odd (it is mid-delivery); define whether carried items are claimable and by whom.
2. Reserved/BuildSite inventories (016 FR-005) and unfinished sales (019 reservation) must be excluded from queries; no exclusion flag defined ("all inventory-bearing entities"). Also no reservation mechanism for query results (016 double-claim criterion).
3. "Locked chest" - no lock concept exists anywhere.
4. Tier (1) "profession-affinity zone" and zone "affinity" definition: how a zone type declares its skill/profession affinity (e.g. Bakery -> baking) is not in 015/018 here; "profession" wording contradicts 020 (no professions). Tier (2) "explicitly filtered" vs tier (3) generic: whether a filtered chest inside a Stockpile counts as tier 2 or 3.
5. Who generates haul postings, when (loose piles, production outputs), and which materials (haul job types in 022/026); hauling isn't specified here, only destination selection. Hauler's source of the "skill-derived affinity" threshold unspecified.
6. Filter inheritance semantics: zone filter applies to furniture "without own filter"; furniture default filter in prototype (FR-002) vs player-set filter (override vs replace); filter empty-list meaning.
7. Material category taxonomy (e.g. "food", "raw materials") owned by 022 FR?; filter references must be validated against it.
8. Pantry effect is zone `entity.modifier` whose target is furniture; but the modifier changes inventory items' decay; interaction with 005 perishability data model (per-stack remaining ticks?) is unspecified. Combination formula with difficulty decayMultiplier: multiply fixed-point both; rounding unspecified. AC5 "48 game hours" vs tick-based units.
9. Treasury (019) expects Throne Room coffers accept currency: filters on coffers may exclude currency; ensure currency category; storing currency outside Throne Room via generic routing (tier 4) would drain treasury inflow logic.
10. Nearest-distance metric (path distance vs Chebyshev), distance for tie, multi-map.
11. Dwelling exclusion (029) plus 018 US2 "furniture inside zone"; furniture overlapping zone edges.
12. Hauler holding a material forever "until space frees" vs hauler also being a worker; retry cadence unspecified.

## 6. Acceptance scenarios / tests
- US1: Box 10-slot: deposit 5 Wood -> contents and slots; Cabinet weight limit -> `WeightLimitExceededError`; API indistinguishable from citizen inventory; new Barrel prototype (5 slot/200 wt) works with zero code (SC-001); serialization preserves inventory.
- US2: Stockpile with 2 barrels, deliver 8 Stone -> in barrels not zone; full -> rejected, hauler seeks alternative; category filter rejects Bread; production query finds stone in zone furniture; removing designation leaves furniture/contents.
- US3: food-filter chest rejects Wood, accepts Bread; materialIds filter accepts Iron Ingot, rejects Stone; no filter accepts all up to capacity; zone filter governs furniture w/o own filter; own filter overrides zone; updated filter doesn't evict; all compatible full -> "no compatible storage available", hold. SC-003 100% filter compliance.
- US4: active Pantry chest of 10 Cheese decays slower than control chest after 100 ticks; deactivation stops reduction immediately (<=1 tick, SC-002); Wood unaffected; both chests in Pantry benefit; value 500 doubles 48h->96h; mixed perishable/non-perishable; chest moved out; multiplier 0.
- US5: Bakery Flour chest preferred over generic; fallback when full; two matching chests: more space wins/PRNG; no destination -> `storage.no-compatible-destination`, no deadlock; mixed Wood+Bread routed independently. SC-004 >=90%.
- US6: Wood in chest + hauler -> both sources returned; inaccessible excluded; 20 Iron across partial sources; 100+ entities <10ms (SC-005); retrieval failure after change -> re-query; SC-007 multi-source 100%.
- Tier 0 `deliverToZoneId`, dwelling exclusion/accessibility, difficulty decay composition (Pantry then difficulty), save/load SC-006.
