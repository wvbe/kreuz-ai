# Digest 015 - Zones & Rooms

## 1. Purpose
Player-designated contiguous tile zones (typed by a data registry) that auto-upgrade to Rooms when fully enclosed by wall/door entities, and grant activity unlocks and entity modifiers while their size/furniture/room requirements hold.
Also provides skill-affinity storage preference, split/merge on connectivity change, gap reporting, and queries.

## 2. Module/API (as stated)
- `ZoneTypeRegistry` (data, immutable after bootstrap; queryable by ID, profession affinity, required activity type). `ZoneType` data: `{ id, requiresRoom: boolean, minTiles: integer, furniture: [{ type|tag, count }], skillAffinity?, requiresJobBoard?: boolean (default false; 017 FR-018), effects: ZoneEffect[], unlockTier? (027) }`. Example: `{ id: "bakery", requiresRoom: true, minTiles: 6, furniture: [{ type: "oven", count: 1 }], effects: [...] }`.
- `ZoneEffect` (hybrid schema): `{ type: "activity.unlock", activityId: "baking" }` and `{ type: "entity.modifier", modifier: "mood.bonus", value: 5 }`. New effect types need engine support.
- `Zone` (entity): zone type ID, tile membership list, Room status (boolean), requirements status (met/unmet per requirement), active effects. `ZoneRequirement` kinds: MinSize, FurniturePresent, RequiresRoom (+JobBoard).
- `ZoneRequirementGap { kind: ZoneGapKind, furnitureId?, required?, present? }`, `enum ZoneGapKind { NotEnclosed, TooSmall, MissingFurniture, MissingJobBoard }` (so 025 reports `ZoneRequirementsUnmet`).
- Events: `zone.requirements.met` (inactive->active), `zone.requirements.lost` (active->inactive). Payload not defined.
- Commands (implied; no names given): designate(zoneType, tiles), add/remove tiles, delete zone, confirm merge. Errors: `ContentLockedError` (027 FR-008); "tile already in zone A" rejection text.
- Queries (FR-016, FR-009): zoneAt(tile) -> Zone|null; activeZonesOfType(typeId); zoneOfEntity(entity); isActivityPermitted(location, activityId); unmet requirements/gaps list.
- GameState persists: per zone tile list, type, current requirements status (non-authoritative).

## 3. Functional requirements
- FR-001 Zone Type Registry with fields above.
- FR-002 Load-time validation: furniture types exist in entity prototype registry.
- FR-003 Player designates zones by assigning type to tile set; tiles contiguous (map adjacency graph); non-contiguous => separate zones or rejection (OPEN); locked-tier type => ContentLockedError.
- FR-004 Each tile in at most one zone; overlap => reject or reassign with log (OPEN).
- FR-005 Room detection: zone is Room when every perimeter tile is bordered, on all non-zone sides, by a cell occupied by wall entity, door entity, or wall-equivalent solid entity (cell-occupying; no edge walls).
- FR-006 Re-run room detection after any terrain modification (wall/door add/remove) adjacent to a zone.
- FR-007 Continuous requirement re-evaluation after any change (tile count, furniture, room status); activate/deactivate effects.
- FR-008 Emit `zone.requirements.met` / `zone.requirements.lost` on transitions.
- FR-009 Activity-unlock effects queryable by location + activity type.
- FR-010 Entity-modifier effects applied while entity is within zone tiles, removed on leave.
- FR-011 `skillAffinity` zones preferred as storage destination for entities with matching skill-derived affinity (dominant skill / skill above threshold, 020); routing order defined by 018 FR-010; preference only.
- FR-012 Persist tile membership, type, requirements status to GameState.
- FR-013 On load, re-evaluate requirements from terrain/furniture state (status not authoritative).
- FR-014 Player deletion: effects cease immediately, tiles freed.
- FR-015 Split on disconnect (two zones); merge of same-type zones when separating wall removed, optional with player confirmation.
- FR-016 Queries: tile->zone/null; type->active zones; entity->zone.
- FR-017 Expose each unmet requirement as `ZoneRequirementGap`.
- Rules: doors (open or closed) always count as enclosure; only missing door breaks it; one zone type per zone; per-zone independent evaluation (adjacent same-type don't stack); furniture counts by type/tag anywhere in zone tiles; furniture moved outside => re-eval; storage affinity works even if effects inactive; full profession zone => fall back to generic stockpile; nearest reachable matching zone preferred; effects active "on the next tick" (assumption).

## 5. Ambiguities / contradictions / blockers
- Open questions: FR-003 split vs reject; FR-004 reject vs reassign (tests need a decision; recommend split-by-component for paint tool, reassign/reject by parameter).
- Timing contradiction: US3.3 and FR-014 "immediately" vs Assumptions "effects active on the next tick" vs SC-002 "within 1 tick". Define: evaluation is triggered synchronously by change events, status visible same tick, effects apply to entities next tick.
- Room definition at map border: perimeter cell outside map? Neighbours that belong to another zone but are not walls: not enclosed (must be wall/door/solid) - confirm. Solid "wall-equivalent" entities undefined (does furniture count? tag?). Voronoi rooms: "perimeter" via adjacency graph fine. Doors/closed doors vs pathing 012: confirm closed door passable.
- FR-012 stores requirements status but FR-013 says derived/not authoritative: events on load - emit `zone.requirements.met` for all satisfied zones? (affects consumers' state). Define as silent rebuild or events.
- Merge "offer ... player confirmation" in a headless engine: needs command/event (e.g., `zone.merge.offered`) and pending-offer state serialized; undefined. Zone identity on split/merge (which keeps the ID? zone ids deterministic order for tests).
- "Zone entity" (Zone is an entity? Key Entities says entity) vs `ZoneType` data; component name and entity ID allocation; serialization key names undefined.
- Entity modifiers: how delivered (event? component?), `mood.bonus` scale 5 vs 013 mood 0-100 (fixed-point?), stacking/dedupe when multiple zones, "for the duration of sleep" (US3.2: only while sleeping, not just standing? FR-010 says while within zone tiles) - inconsistent, 013 interplay.
- ZoneGapKind vs 025 `ZoneRequirementsUnmet` and 014 `MissingRoom`: mapping between these needed. Furniture requirement counts "present" - does broken/unbuilt (blueprint) furniture count? Furniture state not specified.
- Events missing payload definitions (zone id, type id, tiles?, gaps?). No "room" event (`zone.room.formed/lost`) although room status flips.
- Perf: SC-008 200+ zones <20ms/tick with continuous re-evaluation => must be incremental/dirty-flagged (event-driven off terrain/furniture changes - requires 004/005 change notifications).
- US5 skillAffinity vs "profession" wording; threshold for "skill above a threshold" undefined; 018 FR-010 routing referenced but not in this batch.
- US2.5 merging two zones "if both zones are of the same type" — different types after wall removal: tile reassignment impossible (tiles belong to their zones; shared wall tile removed is simply undesignated).
- Designation tool details: removing wall tile from a zone? tiles containing walls inside zone; walls ON zone tiles (interior walls) allowed? contiguity via traversable adjacency or any adjacency?

## 6. Tests to derive
US1: 5x5 Bakery -> 25 contiguous tiles; add adjacent tiles expands; non-contiguous input behavior (decision); remove tiles -> shrink, split into two zones when disconnected; delete frees tiles & stops effects.
US2: 5x5 enclosed with door -> Room; remove wall -> loses Room; closed->open door retains Room; adding wall closing gap upgrades automatically; removing shared wall between same-type zones -> merge offer with confirmation.
US3: Bakery (Room, >=6 tiles, 1 oven) met => baking unlocked + `zone.requirements.met`; Bedroom +mood during sleep; remove oven => `zone.requirements.lost`, activity not startable; below minTiles => zero effects & TooSmall gap; non-room Farm Field works open-air.
US4: 10+ data zone types, new type via data only; dangling furniture type rejected; 50+ types query satisfiable at location <5ms; JobBoard requirement.
US5: Baker routes flour to Bakery before Stockpile; full Bakery -> falls back; non-matching skill no preference; nearest of multiple Bakeries; inactive-effects zone still used for storage.
US6: disjoint membership; overlap rejected/reassigned (decision); stable deterministic tile order; split assigns unambiguously; undesignated tile -> null.
Edge: furniture moved in-zone (still met) and out-of-zone (lost); min tile drop; door removal; unknown zone type on load = error; two adjacent same-type zones independent; furniture by tag.
Persistence: save/load restores membership; requirements re-derived after terrain change between save and load (SC-007); 100+ zones activity query <5ms; 200+ zones eval <20ms/tick; gap list contents (ZoneGapKind with counts).
