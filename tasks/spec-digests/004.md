# Digest 004 - Game Map & Terrain System

## 1. Purpose
Cell-based spatial model (square tiles for indoor/underground, voronoi polygons for outdoor) with per-map immutable grid type, traversability, deterministic A* pathfinding, multi-map world on shared time, a grid-agnostic terrain alteration API, and four seed-driven map generators (voronoi world, cave, cellar, village pass).

## 2. Module layout / public API (as stated)
Implied: `map/Map` (+ `TileMap`), `map/grid/{square,voronoi}` (adjacency), `map/terrain` (TerrainType refs; registry is spec 022), `map/pathfinding` (A*), `map/alter` (alteration API), `map/query`, `map/generators/{voronoiWorld,cave,cellar,village}`.
- `GridType = 'square' | 'voronoi'` (immutable per map; default: voronoi outdoor, square indoor).
- `Location`: `{ cellIndex: int }` all maps; square also `{ cellX, cellY }` sugar (`cellIndex = cellY*width + cellX`). Position component (006): `{ mapId:int, cellIndex:int }`.
- Named fns: `placeWall(map, cellIndex)` (wall = entity occupying whole cell; no edge walls/orientation; cell terrain unchanged), `queryCell(map, cellIndex)` -> `{ traversable, terrainType, occupants, zoneId, ...reason }`. Others implied (doors, furniture, remove wall, create map, place/move entity, travel, findPath) but NOT named.
- Pathfinding: `(start cell, goal cell, terrain) -> Path (cell index[]) | null`; A* on 4-connected (square) / Delaunay dual (voronoi) graph; caller picks no algorithm; tie-break via seeded PRNG.
- Non-traversable reason strings: "wall","water","locked"(door),"impassable_cliff".
- Map JSON (006): `{ id, gridType, width?, height? (square only), cells: [{ terrain: "grassland" }, ...] }`; walls/doors/portals = full entities in root `entities`; door/portal Transition component `{ target:{mapId,cellIndex}, isOpen }`.
- Map travel = atomic async operation (remove from source cell + add to dest in one step, pending async ops keep running).
- Generators (each: seed-driven, only seeded PRNG, headless, build through alteration API): voronoi outdoor (biomes from elevation x moisture lookup + rivers; ~600 cells, 2 Lloyd relaxation passes), cave (cellular automata, 30x30, initial fill 0.45), cellar (room partition, ~4 rooms, connected), village pass (roads along Delaunay edges on voronoi map).

## 3. Functional requirements
- FR-001 cell-based spatial repr; positions at cell granularity only; renderer interpolates.
- FR-002 consistent across terrain types; each map declares gridType; mixed OK.
- FR-003 API to place entities in cells.
- FR-004 block movement into non-traversable cells.
- FR-005 queryable non-traversable reason per cell.
- FR-006 default grid type from engine (voronoi outdoor/square indoor), set at creation, immutable.
- FR-007 deterministic A* unified API; 4-conn square / Delaunay dual voronoi.
- FR-008 unreachable goal => null/no path.
- FR-009 100+ concurrent pathfinds <1s total, both grid types.
- FR-010 multiple maps, independent grid types.
- FR-011 shared global time across maps.
- FR-012 seamless map-to-map movement, even across grid types.
- FR-013 diverse terrain types with per-cell properties.
- FR-014 ergonomic grid-agnostic alteration API (walls/doors = entities occupying cell, door passable per state, furniture, traversability).
- FR-015 terrain query API, grid-transparent.
- FR-016 extensible for procedural generation (grid-specialized generators using alteration API).
- FR-016a deterministic seed-driven generators (4 listed).
- FR-017 serialize `"gridType"` explicitly; flat `cells[]`; dims only square.
- FR-018 deserialize identical; mismatched gridType rejected on load.
- FR-019 headless parity.
Rules/constants: co-location unlimited; other entities (citizens, animals) never block; placing into non-traversable cell => clear error; each entity at exactly one cell of one map; all maps loaded always (no streaming); traversability checks O(1); 100+ entities check <50ms/tick; queries <5ms on 1000+ cells; main + 5+ submaps; terrain alterations permanent until changed.

## 4. Dependencies
Consumes: 001 shared time; 003 entities/Position/async (travel as async op); 011 seeded PRNG (generators, tie-break); 022 terrain registry (string terrain IDs); 006 serialization; 012 (movement re-eval on terrain change, FR-006 there). Provides: Position/map model to 002 (nearest), 005 none, 006 maps array, 007 mapSize-based starting map.

## 5. Ambiguities / contradictions / blockers
- BLOCKER (with 006): voronoi geometry/adjacency is not in the save format (006 FR-003: only `cells[{terrain}]`, dims for square only). Need site points / vertices / neighbors serialized, or an explicit "regenerate from seed+options" rule (then terrain mutations + determinism across lib versions are risky). Also need centroid data for renderer and A* heuristic.
- Delaunay library/algorithm not chosen (floating-point geometry vs integer determinism; constitution wants integer state; polygon coords/centroids as ints? Lloyd relaxation uses floats -> cross-platform determinism risk).
- Pathfinding PRNG tie-breaking consumes the shared seeded stream: query order then alters later randomness (and path queries by renderers/tests would perturb state). Prefer deterministic non-PRNG tie-break (lowest cellIndex) or a dedicated derived stream that is not advanced by read-only queries.
- Edge costs/terrain movement cost unspecified (uniform? per-terrain cost, diagonal none on square). A* heuristic for voronoi unspecified. Door states in pathing (closed/locked doors = blocked? "passable per state").
- Most API names unspecified (create map, addMap, placeEntity, moveEntity, travel, placeDoor, removeWall, findPath, changeTerrain). Map ID type: int (006) but example `map_id=5`; map IDs allocation + `nextMapId`.
- OPEN: deleting a map with entities (move to main vs reject). Pathfinding on map entity isn't on: "error or null clearly" undecided.
- "occupants" list in cells vs 006 "positions only in Position component": occupant index is derived/rebuilt on load; keep consistent w/ 002 "no indexing".
- Transition (door/portal) entity arrival cell when target is non-traversable; travel cost/time (async op duration) undefined; cross-grid arrival expressed as explicit cellIndex only.
- TerrainType properties (traversable? movement cost? water => non-traversable?) belong to spec 022 but non-traversability derived from terrain AND entities: water reason string source unclear.
- MapSize enum -> cell count/dimension mapping (007) absent; village pass parameters (size, placement, road width) absent; biome lookup table, river algorithm, cellar connectivity guarantee mechanics, cave connectivity guarantee ("where generator promises") unspecified.
- Perf claim "<50ms for 100+ entities traversability" trivial; SC-003 vs FR-004 enforcement point (who rejects: movement system vs map API) unclear.
- Terrain mutated while path in progress: handled in 012 (not here).

## 6. Acceptance scenarios / tests
- Placement: entity in cell 42 appears in occupants; co-location; place into wall cell throws; positions survive JSON.
- Pathfinding: obstacle avoidance; unreachable -> null; 100 concurrent <1s on square & voronoi; identical results twice; equal-cost tie determinism; headless tick-by-tick following reaches goal.
- Multi-map: save/move/resume; events at T+100 across maps simultaneously; independent task queues same time; atomic transit (no intermediate state); async ops continue during travel; mixed grid travel (SC-008); main + 5 submaps.
- Terrain API: create from type; placeWall makes cell non-traversable, terrain unchanged; queryCell fields; reason strings; alteration persists via JSON; procedural script builds hut/house/dungeon w/o hardcoded ids; on-demand sub-map creation.
- Serialization: 4 maps x 5 entities round trip; gridType preserved/mismatch rejected; two loaded instances identical after 100 ticks; entity at (map 5, cell) restored.
- Generators: same seed+options => byte-identical serialized map; different seed => different; validity (biome per cell, rivers present, CA open/rock, cellar rooms connected, village roads follow Delaunay edges); connectivity via pathfinding where promised; only seeded PRNG used.

## 7. Size: XL (two grid types, Delaunay/Voronoi, A*, alteration API, 4 generators, serialization of geometry).
