# Digest 014 - Production & Crafting

## 1. Purpose
Data-driven material and recipe registries plus an execution flow (validate restrictions -> gather -> lock inputs -> tick-down craft -> consume/produce) with workstation/room/skill restrictions, multi-step chains, production orders and byproducts.
Crafting is a composite task in the 003 task queue; in-progress crafts serialize and resume exactly.

## 2. Module/API (as stated)
- `MaterialRegistry`, `RecipeRegistry` (global, loaded from data files at bootstrap, immutable; queryable: materials by ID/category/tag; recipes by output material, workstation type, category).
- Material JSON: `{ id: "iron_ingot", stackLimit: 20, weight: 8, categories: ["metal","refined"] }` (+ optional perishability, value).
- Recipe JSON: `{ id: "smelt_iron", inputs: [{materialId, quantity}], outputs: [{materialId, quantity}], duration: 36 /*ticks*/, restrictions: { workstation: "smelter", room?: "<roomType>", skill?: {id,min}, workstation quality?: >=2 }, outputDestination?: OutputDestination, unlockTier? (027), metadata:{difficulty} }`.
- `enum OutputDestination { Workstation (default), Crafter, Stockpile }` (Stockpile = flagged for hauling, routed per 018 FR-010).
- Entities/components: `Workstation` (furniture entity with crafting component, own inventory, compatible recipe tags, occupancy), `CraftingTask` (recipe ref, progress ticks, work inventory ref, locked inputs, target output destination), `ProductionOrder` (recipe ID, target quantity, priority, status active|paused|completed|cancelled).
- Events: `production.crafting.started`, `production.crafting.completed` (payload: recipe ID, crafter entity ID, `inputs: {materialId,quantity}[]`, `outputs: {materialId,quantity}[]` actual quantities incl. skill `outputBonus` 020 FR-007), `production.crafting.failed`, `production.crafting.interrupted`, `production.output.blocked`.
- Errors/status: `ContentLockedError` (027 FR-008); `BlockedReason` values (025): `MissingInput`, `MissingWorkstation`, `MissingRoom`, `NoQualifiedWorker`, `OutputBlocked`, `NoOrders`.
- Queries: available recipes for a workstation (<5ms with 100+ materials/50+ recipes); progress as integer ticks elapsed/required.
- Chain example: "2 Ore -> 1 Ingot" (Smelter, 36 ticks), "3 Ingot + 1 Leather -> 1 Sword" (Anvil, 60 ticks); "2 Wood -> 4 Plank" 24 ticks Sawmill; skill duration formula `duration * (1 - skillBonus)`.

## 3. Functional requirements
- FR-001 Material Registry fields id, stackLimit(int), weight(int), categories.
- FR-002 Recipe Registry fields id, inputs, outputs, duration(int ticks), restrictions.
- FR-003 Restrictions min: `workstation` (prototype tag), `room` (room type), `skill` (id + min level); all optional; none = hand-craftable anywhere.
- FR-004 Load-time validation: material IDs referenced must exist; reject with clear errors.
- FR-005 Flow: (1) validate restrictions (+ unlockTier > settlement tier => ContentLockedError), (2) gather to work inventory, (3) lock inputs, (4) tick timer, (5) consume inputs/produce outputs.
- FR-006 Work inventory = workstation's inventory if workstation required, else crafter's.
- FR-007 Gathering via task queue (003) + pathfinding (012), from any available source, deposit in work inventory.
- FR-008 Busy state; progress integer, +1 per tick.
- FR-009 On completion consume inputs, place outputs per `outputDestination` (default Workstation).
- FR-010 Multi-step chains: when needed material X is craftable, execute prerequisite recipes first or use existing stock.
- FR-011 Emit lifecycle events (list above); completed payload has inputs/outputs arrays.
- FR-012 One active crafter per workstation.
- FR-013 Inputs locked at the moment crafting begins (not during gathering).
- FR-013a Interruption (higher-priority task, incapacitation, workstation destruction, player cancel): return all locked inputs to work inventory; nothing consumed; progress resets to 0.
- FR-014 Registries re-loaded from data at bootstrap; only in-progress crafts serialized.
- FR-015 In-progress crafts (entity, recipe, progress, work inventory ref) serialize to GameState, resume identically.
- FR-016 Production orders: queue of recipe executions per workstation (recipe ID, qty, priority); settlement "keep N in stock" is 026; reject orders for locked-tier recipe (ContentLockedError).
- FR-017 Orders persist across save/load and are player-cancellable.
- FR-018 Skill requirements; skill may modify duration.
- FR-019 Byproducts (multiple outputs).
- FR-020 Deterministic (PRNG only for optional randomized quality).
- FR-021 Report stall conditions to status system as 025 BlockedReason (MissingInput, MissingWorkstation, NoQualifiedWorker, OutputBlocked, NoOrders).
- Rules from stories/edges: 0-duration recipe produces output same tick; output blocked => craft completion waits, entity stays busy, emits `production.output.blocked`, all outputs equal (none discarded); crafter death => abandoned with interruption policy; recipe removed mid-craft (only via changed content on load) => current craft completes, none new; skill XP from skill registry `baseGrowthPerCompletion` (020), not per recipe; no min skill => anyone; room restriction validated vs zone/room (015); nearest reachable valid workstation chosen; partial stock awareness when gathering; multiple trips per carrying capacity (005); intermediate-stock skipping; pipeline parallelism across entities; orders processed by player priority; order cancel lets current craft finish; waiting idle when inputs run out; no recipe failure/quality variance by default.

## 4. Dependencies
Consumes: 005 (inventory, capacity, stacks), 003 (task queue, composite task), 012 (pathing), 010 (events), 001 (ticks), 015 (room types), 020 (skills, outputBonus, baseGrowthPerCompletion), 022 (registries loader), 025 (BlockedReason, ProductionLedger consumption), 026 (standing orders), 027 (unlockTier), 018 (stockpile hauling), 017 (job assignment), 006 (serialization). Provides: recipes/materials, `production.*` events, workstation occupancy, recipe-activity IDs referenced by 015 (`activity.unlock`).

## 5. Ambiguities / contradictions / blockers
- CONTRADICTION: US8.3 "cancel order: current craft completes (not interrupted)" vs FR-013a "player cancellation" is an interruption that resets progress. Resolve: order cancel != craft cancel; specify two commands.
- Material Registry ownership: 005 inventory (material handling), 022 content loader, and 014 all define materials; "extend not replace" is vague. Single schema owner needed; stackLimit/weight/value/perishability fields.
- Skill duration: `skillBonus` undefined (per-level %?), rounding of `duration*(1-bonus)` to integer ticks, min 1? output quality "if defined"; skill restriction JSON shape; US4.4 "workstation quality >= 2" requirement not in FR-003 minimum set nor in Recipe fields; quality model absent.
- Interruption by "higher-priority task" requires task priority model (003); "crafter dies => materials follow interruption policy": materials locked in the workstation inventory return to it; if work inventory is the dead crafter's own, items drop? Unspecified. Workstation destroyed: its inventory contents fate (spec 018/005).
- "Lock": mechanism (reservation record in inventory 005?) not defined; locked qty vs `stackLimit`; interplay with FR-006 when work inventory = crafter's own (locked inputs are in own inventory but still carried).
- Variant recipes (US9.2 "generic Smelt recipe, input type determines output type") have no schema (pattern/category inputs, wildcard output). Chain planning FR-010 algorithm (recursive resolve, source search, depth/cycle limit, who assigns multi-entity pipeline) unspecified; recursion with cycles in recipes (A->B->A) not rejected.
- Order model: how an entity is "assigned to a workstation" (017 job system?), order storage location (on workstation entity? global?), status transitions/pause, priority scale, per-workstation vs settlement queue (026 posts orders - same structure?).
- Events beyond completed lack payload definitions (started/failed/interrupted/blocked); `failed` vs `interrupted` semantics; `production.crafting.failed` when? (recipes always succeed).
- Recipe room restriction: "room type" - 015 zone type id vs room; must the workstation be IN a zone of that type with requirements met (015 effects active) or just in an enclosed room? 015 gives `activity.unlock activityId` mapping - how recipe id/activity id link? ZoneRequirementsUnmet vs MissingRoom BlockedReason naming mismatch with 015's gap kinds.
- Edge "0 duration instant" vs FR-008 busy state; progress when zero.
- Gathering when materials exist only in locked state elsewhere (another workstation); stockpile reservation (race between two gatherers) - determinism and deadlock avoidance (SC-007) require reservation rules; ordering of entities within a tick.
- Perf: SC-003 <100ms/tick for 50 entities crafting vs 013's 50ms AI budget share the tick; per-tick system ordering undefined.
- Fixed-point: weight/value/skillBonus fixed-point? duration is ticks (int, OK).
