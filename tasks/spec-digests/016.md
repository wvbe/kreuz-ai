# Digest 016 - Construction System

## 1. Purpose
Player queues ConstructionJob/DeconstructionJob (posted to job boards, spec 017); an adult humanoid claims one, hauls consumable materials into a BuildSite inventory, carries (but never consumes) required tools, is "busy" N ticks at the site, then the built entity is placed (or removed). Zones/rooms are not coupled: completion/removal just triggers terrain + zone re-evaluation.

## 2. Implied module layout / public API (as stated; spec gives NO signatures)
Module: construction (queue + job state machine + build-site + deconstruction). Named types/entities:
- `ConstructionJob` (serializable): target location (map + tile), entity prototype id to build, required consumables `{materialId, quantity}[]`, required tools (entity type/tag list), duration (integer ticks), assigned builder, progress (ticks elapsed), status `pending | gathering | in-progress | complete | suspended | cancelled`; plus priority (integer), paused flag. Suspended carries spec-025 `BlockedReason` in {`MissingInput`,`MissingTool`,`LocationBlocked`,`NoQualifiedWorker`}. (Spec text also uses reason strings "missing materials: Stone", "missing tool: Hammer", "location blocked", "materials unavailable", "location already occupied".)
- `DeconstructionJob`: variant of ConstructionJob; target = existing entity id, duration, builder, progress, status.
- `BuildSite`: transient in-world entity at target tile with its own Inventory (staged materials). Cleared on completion/cancel.
- `ConstructionQueue`: colony-wide, globally accessible, serializable player-side ordered view of pending / in-progress / suspended / recently-completed jobs (both kinds). Query returns status + target location per job.
- Prototype fields consumed: `deconstructionYield: {materialId, quantity}[]` (empty = nothing), `unlockTier` (spec 027), construction duration (per prototype or separate data file), tool requirements.
- Errors: `ContentLockedError` (spec 027 FR-008).
- Events: `construction.job.queued|started|completed|cancelled|suspended`. `completed` payload: jobId, placed entity type, location, `consumed: {materialId, quantity}[]` (empty for decon), and for decon `yield: {materialId, quantity}[]`.
- Player operations implied (no command names given): issue construction job, issue deconstruct order, cancel, pause/unpause, set priority/mark urgent, reorder (to position 1), query queue.
- Notifies terrain (spec 004: wall/door entity occupies cell, sets traversability, terrain type unchanged) and zone/room system (015).

## 3. Functional requirements (condensed)
- FR-001: Every ConstructionJob is posted to a job board (017); entities claim from boards, not a separate queue; ConstructionQueue is the player-side ordered view, ordering reflected in postings.
- FR-001b: Construction is a job posting; only prerequisite = adult humanoid; no capability flag/occupation.
- FR-002: Job declares target loc, prototype, consumables, non-consumed tools, duration ticks, status set above; suspended carries BlockedReason.
- FR-003: DeconstructionJob variant; removes entity, drops `deconstructionYield` as loose pile at tile; empty yield = nothing.
- FR-004: Materials must be transported to build site (tile or adjacent staging) before construction phase; uses task queue (003) + pathfinding (012).
- FR-005: Delivered materials physically transferred into BuildSite inventory (005) at delivery; leave stockpile at pickup; not available for general hauling; on cancel returned to nearby stockpile or dropped as loose pile.
- FR-006: Tools carried by builder during construction, retained after, never deposited.
- FR-007: Construction phase = builder busy at site for integer duration ticks; progress +1/tick.
- FR-008: On completion: site consumables destroyed, entity placed, builder leaves busy, job complete.
- FR-009: On completion notify terrain and zone systems for room-detection/zone re-eval.
- FR-010: Emit lifecycle events (payloads above).
- FR-011: Interrupt in construction phase -> job back to pending, materials stay staged, progress resets to 0, next builder restarts phase (no re-gather). Interrupt in gathering -> delivered materials stay, next builder gathers only remainder.
- FR-012: One builder per job at a time; no cooperative construction.
- FR-013: Integer job priority == posting's player priority in 017 FR-007 selection order; highest wins; player can modify.
- FR-014: Pause and cancel per job; paused skipped; cancel immediate in any status (pending: removed + posting withdrawn; in-progress: builder stops, nothing placed, staged materials to nearby stockpile or loose pile).
- FR-015: All job state serializes (006), resumes identically.
- FR-016: Queue-time validation: tile buildable (not occupied by non-removable entity, in bounds); prototype `unlockTier` > settlement tier -> `ContentLockedError`.
- FR-017: Prototype looked up in registry (003); missing -> reject at queue time; unlockTier check as FR-016.

Constants/rules: progress integer ticks elapsed/total; decon duration shorter than construction (ratio = balance constant, unspecified); interruption resets progress to 0 (intentional); no half-built visual state.

## 4. Dependencies
Consumes: 003 (prototype registry, task queue), 004 (terrain/traversability, bounds), 005 (inventory transfer), 006 (serialization), 010 (events), 012 (pathfinding), 015 (zone/room re-eval), 017 (job boards/priority order FR-007, adult humanoid prerequisite), 018 (stockpile/material query for sources + return destination), 025 (BlockedReason, ProductionLedger consumes completed payload, LoosePile entity, NoQualifiedWorker), 027 (unlockTier, ContentLockedError), 020 (implicit: construction skill; duration/speed modifiers).
Provides: placed furniture/walls (to 015 zones, 018 storage furniture, 029 dwellings), events to 025 ledger, `skill.work.completed` source (should emit, not stated), loose-pile materials needing haul postings.

## 5. Ambiguities / contradictions / blockers
1. Which board receives a ConstructionJob posting? Spec says "a job board" with no routing rule. Also whether player-issued construction posts must go via Town Crier (017 FR-010 user-managed boards apply changes only on crier arrival) or posts instantly. Critical gap vs 017.
2. 017 postings have no wage, no eligibility prerequisites (adult humanoid), no poster-faction field; 016 FR-001b needs an eligibility predicate hook on postings.
3. Skill/trait effects: 020 FR-007/008 shrink/stretch duration (and construction skill), but 016 FR-007 says fixed integer duration; need to state duration used = modified duration, determined at start (rounded up, min 1). 016 never says it emits `skill.work.completed {entityId, skillId:"construction"}` (020 FR-005 requires it) nor which skill id.
4. Tool acquisition: "tool storage location" undefined; tool reservation (US3 AC5: one Hammer, multiple builders) has no mechanism; "tool" matched by entity type or tag unspecified; what if tool is in another builder's inventory.
5. Material reservation before delivery: AC US2.5 says no double-claiming by competing builders, but only mechanism is physical pickup; need reservation at the stockpile/storage-query level (018 query is "synchronous in tick", retrieval can fail and re-query). Not specified.
6. Open question in spec: mobile entity standing on target cell (entities do not block cells per 004).
7. Loose pile: prototype and owner of haul posting undefined (open question; 025).
8. Status model overlap: 016 status `suspended`/`paused` vs 017 posting status (available/partially-claimed/fully-claimed/suspended) and board pause (017 FR-014); mapping not defined. "Urgent" is a priority value? 017 FR-007 lists urgency distinct from player priority.
9. Build-site inventory must be excluded from 018 FR-011 material queries (018 says "all inventory-bearing entities"), and from hauling.
10. BuildSite adjacency: "target tile or adjacent staging area" - which one; BuildSite occupies target tile? Walls make cell non-traversable only at completion.
11. Requirement list of material gathering vs hauling: is gather performed by builder (yes per US2) while a separate haul job type also exists (022); who hauls to BuildSite is only the builder.
12. "Recently-completed" retention window undefined. Deconstruct validity (what if target entity already gone/non-removable); deconstruct "non-removable" flag undefined. Tile "buildable" rule beyond occupancy undefined (terrain type, multi-tile prototypes?).
13. Same-type-same-location rejection ("location already occupied") overlaps FR-016; duplicate pending jobs at same tile?
14. Builder deleted mid-job -> pending (edge case) conflicts nothing but 017 save/load says claimed jobs resume with assigned entity; builder-gone on load not covered.
15. Event `construction.job.started` semantic: gathering start or construction phase start? unspecified.

## 6. Acceptance scenarios / tests to write
- US1: issue Wall job -> ConstructionJob at (10,5) pending with materials listed; 3 jobs queued/in order, posted to board, claimed and run one at a time; cancel 1 of 5 keeps others' order; queue query returns pending/in-progress/recent with status+location; save/load mid-job resumes with progress and assigned entity.
- US2: Wall needs 4 Stone -> builder paths to stockpile, fetches up to capacity, deposits; site has 2 already -> fetches only 2; no material anywhere -> suspended "missing materials: Stone"/MissingInput, auto-resume when available; multiple trips when capacity < need; reservation prevents double-claim among builders.
- US3: builder with Hammer builds and keeps it; builder without fetches from tool storage first; no Hammer in world -> suspended MissingTool; interruption keeps Hammer; one Hammer, many jobs -> only one holder, others take non-Hammer jobs.
- US4: 10-tick wall: builder busy exactly 10 ticks; progress 5/10 at tick 5; at completion Wall occupies cell (non-traversable, terrain unchanged), materials gone, job complete; `construction.job.completed` has id, entity type, location, consumed; furniture completion triggers zone re-eval within 1 tick (SC-002).
- US5: Oven placed in Bakery zone -> zone re-evaluates/activates; walls enclosing -> Room granted; 2 Workbenches (second completes) -> partial to active; decon of furniture -> zone may deactivate.
- US6: decon job queued, builder travels, busy, entity removed; yield [{stone_block,3}] drops 3 as loose pile hauled to stockpile; decon wall makes cell traversable, room loses Room status; save/load mid-decon.
- US7: reorder/urgent D picks first; paused skipped; no double assignment among concurrent entities; reordered job executed next; order/priority/paused persist through save/load.
- Edge/clarifications: interrupt in construction resets progress to 0, materials stay; interrupt in gathering keeps delivered materials; cancel in-progress returns staged materials; duplicate location job rejected "location already occupied"; unknown prototype and locked tier rejected at queue time; no adult humanoid -> NoQualifiedWorker.
- SC-001 determinism; SC-003 10+ concurrent jobs no deadlock/double claim/collision; SC-004 save/load fidelity; SC-005 100% reservation reliability; SC-006 tool retention 100%; SC-007 suspension reasons + auto-resume; SC-008 decon re-triggers terrain/zone, yields per policy.
