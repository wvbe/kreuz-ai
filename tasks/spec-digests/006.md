# Digest 006 - Game State & Save Format

## 1. Purpose
Defines the root GameState JSON (version, timestamp, time, prng, eventQueue, initOptions, statuses, productionLedger, stewardship, entities, maps), `save()`/`load()` semantics (no file I/O in engine), versioning/migration, and the deterministic round-trip guarantee.

## 2. Module layout / public API (as stated)
Implied: `save/serialize`, `save/deserialize+validate`, `save/migrations/` (version N -> N+1 chain), `save/errors`, canonical numeric rules.
- `save(): string | JSON-compatible object` (one consistent snapshot, taken at tick boundary; host persists atomically).
- `load(json: string | object)` -> returns a GameState; rejects with typed error (`InvalidSaveFormatError`; newer-version error type name unspecified). (007 calls it `GameEngine.loadGame(save)`.)
- Root shape: `{ version:int, timestamp:ISO8601 UTC, time:{tickCount,paused,speed,tickIntervalMs}, prng:{state + derived streams (spec 011); includes identity.names, housing.immigration streams}, eventQueue (spec 010), initOptions (incl seed; spec 007), statuses, productionLedger (025 FR-014), stewardship (standing orders, nextOrderId, owned runs, stewardEntityId, board, pending extra-review flag, last review tick; 026 FR-026), entities:[{id,prototype,components:{...}}], maps:[{id, gridType:'square'|'voronoi', width?,height? (square only), cells:[{terrain:'grassland'},...]}] }`.
- Position component: `{ mapId:int, cellIndex:int }`. Transition component: `{ target:{mapId,cellIndex}, isOpen }`. Task record fields: task ID, task type, entity ID, cancellation token state (with `reason`), checkpoint (state-machine phase+data); task queue lives inside owning entity's component. Components serialized as root-less (SettlementProgress 027, SettlementChronicle 028 FR-018, Identity 028 FR-003, Dwelling/Citizen.homeDwellingId 029) - NOT root keys.
- Errors: `InvalidSaveFormatError` (corrupt/invalid JSON/validation fail).

## 3. Functional requirements
- FR-001 root `version` int. FR-002 `entities` array `{id,prototype,components}`. FR-003 `maps` array (id, gridType, w/h square only, flat cells[]; cell `{terrain: string id}`; walls/doors/portals are entities; no entity positions in map data).
- FR-004 `time` object. FR-004a root includes prng, eventQueue, initOptions, statuses, productionLedger, stewardship (components for 027/028/029 NOT root).
- FR-005 all component state under `components.{Name}`; Position `{mapId,cellIndex}` for all grids; no sub-cell.
- FR-006 Position is sole source of truth for location; map doesn't store entity locations. FR-006a `timestamp` ISO UTC metadata, excluded from equality.
- FR-007 mutated terrain saved as final state in cells[] (no delta).
- FR-008 transitions are full entities with Position + transition data.
- FR-009 in-flight tasks serialize task id/type/entity id/token/checkpoint; no promises. FR-010 token includes reason.
- FR-011 save() returns complete snapshot; engine does no I/O.
- FR-012 load accepts string/object; rejects invalid/newer; migrates older forward.
- FR-013 valid UTF-8 plain JSON, no custom markers.
- FR-014 all numerics JSON integers; fixed-point ×1000 default unless spec defines better unit (e.g. ticks); content decimals converted at load.
- FR-015 after load entity ID sequences, components, relations match exactly; positions rebuilt from Position.
- FR-016 migrate `initOptions.difficulty` normal/hard -> steady/harsh (027 FR-024).
Perf/limits: SC-001 100+ entities, 5 maps, 1000 ticks round trip <100ms; SC-002 byte-identical (minus timestamp); SC-004 corrupt save rejected <10ms w/o corrupting current game; SC-005 compat within major version.

## 4. Dependencies
Consumes: 001 (time), 003 (entity/task serialization, version excluded), 004 (map/cell/Position), 007 (initOptions, loadGame wrapper), 010 (eventQueue), 011 (prng), 022 (terrain/material registries loaded at bootstrap, not saved), 025/026/027/028/029 (extra root keys/components). Provides: persistence contract for everything.

## 5. Ambiguities / contradictions / blockers
- BLOCKER (with 004): voronoi maps need geometry/adjacency; cells[] holds only `{terrain}` and dims are square-only. No place for site points/vertices/neighbors or a "regenerate from seed" rule.
- BLOCKER: no counters for ID allocation (`nextEntityId`, next task id, next map id; stewardship has `nextOrderId` but entities don't) although FR-015/assumptions require ID sequences preserved and IDs never reused. Add to root.
- Root key list inconsistent: US1 AC1 lists only version,timestamp,time,prng,eventQueue,initOptions,entities,maps; FR-004a/Key Entities add statuses, productionLedger, stewardship. Treat FR-004a as authoritative.
- Version numbers: examples say current = 1 and migrate 0 -> 1, while FR-016 introduces a difficulty-rename migration (implies a bump); current version int + migration registry location unspecified. No typed error for newer version / invalid time state (001 says generic throw). `load` (returns GameState object) vs 007 `loadGame` (returns engine) naming/return mismatch; save() return type (string vs object) should be one with options.
- Byte-for-byte determinism requires canonical key order & stable entity/array order; JS orders integer-like object keys numerically (e.g. any map keyed by entity/map id) - need ordering rule or arrays; undefined/NaN/Infinity/-0 handling; `timestamp` requires Date (allowed only as metadata; inject clock for tests).
- "Tasks that cannot serialize are cancelled before save" (assumption) contradicts "save is a consistent snapshot / no side effects": save() would mutate game state and break SC-003 equality.
- Unknown material/terrain/prototype ids on load (registry drift) - validation behavior unspecified; "validation" schema (Zod?) for save not defined; partial/unknown fields policy (007 says ignore unknown initOptions fields).
- Save mid-tick: "taken at tick boundary" yet save() called from system code mid-tick? Define as queued to end of tick or error.
- Registry content versions not recorded in save (materials/prototypes loaded separately), so no check that save matches content set.
- Statuses/productionLedger/stewardship schemas live in unseen specs 025/026.
- Position stored only on entities: entities without Position (factions) fine; items inside inventories have no Position.

## 6. Acceptance scenarios / tests
- save(): 3 citizens/1 map/100 ticks -> root keys present; valid UTF-8 JSON parse; mid-trade task record + token serialized, no promise; multiple mutations -> one consistent snapshot.
- load(): version validation; migrate older; reject newer; reject invalid/truncated JSON with InvalidSaveFormatError without altering current game (<10ms); IDs preserved without collision; resume tick identical; in-flight task resolves when expected.
- Round trip: save->load->save identical except timestamp; N ticks vs M + save/load + (N-M) ticks identical final state (SC-003); PRNG continuation identical; async task completes identically.
- Positions rebuilt from Position component only; terrain mutation persisted; doors/portals serialized as entities; gridType enforced.
- Migration: v0 -> v1 default for new field; difficulty rename migration; future version rejected.
- Perf: 100 entities x 5 maps x 1000 ticks <100ms.

## 7. Size: M (shape is simple, but it touches every system; migration framework + validation schema push to M-L as specs accumulate).
