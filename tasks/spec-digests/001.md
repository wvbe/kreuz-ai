# Digest 001 - Game Loop & Time Progression

## 1. Purpose
Integer-tick game clock (pause/resume, 5 discrete speeds, calendar helpers) that is fully independent of rendering; `engine.tick()` is the only primitive. Time state is JSON-serializable and deterministic; an optional `AutoRunner` wraps tick() with a real-world interval.

## 2. Module layout / public API (as stated)
Implied files: `time/GameTime` (state + derived helpers + commands), `engine tick()` (primitive, lives on GameEngine per 007), `AutoRunner` (optional, outside sim, only place real timers allowed).
- `GameTime` fields: `tickCount: int` (safe integer, canonical), `paused: boolean`, `speedMultiplier` (enum of {0.25,0.5,1,2,4}; serialized as ENUM VALUE/INDEX not fraction), `ticksPerHour = 12` (design constant, NOT per-save), `tickIntervalMs` (int, runtime-configurable, default 6250 at 1x, serialized).
- Derived read-only helpers: `toGameHours()` (= tickCount/ticksPerHour), `toDay()`, `toWeek()`, `toYear()`. No public mutable state; all changes via commands.
- Commands (verbs stated, exact names NOT given): pause, resume, set speed (fixed set), set tick interval. Query interface for tick count, paused, speed (names not given; 007 calls it `getTime()`, 007 US5 `getGameTime()`).
- `engine.tick()`: advances exactly 1 tick (5 game min = 1/288 day) at EVERY speed. Does not auto-run. Paused => no time advance.
- `AutoRunner`: wraps engine; start/stop/pause; calls `tick()` every `tickIntervalMs / speedMultiplier` real ms (1x 6250ms; 2x 3125; 4x ~1562.5; 0.5x 12500; 0.25x 25000).
- Serialized `time` (per 006 FR-004): `{ tickCount, paused, speed, tickIntervalMs }`.
- Error on invalid speed (type unspecified), error on invalid saved time state (type unspecified; "throws, refuses to load").
- GameState holds GameTime as nested property.

## 3. Functional requirements
- FR-001: Time = integer tickCount since sim start; hours derived = tickCount/ticksPerHour (12); no float time stored.
- FR-002: pause command; paused flag persisted in state.
- FR-003: resume command.
- FR-004: speed command accepts only {0.25,0.5,1,2,4}; others (incl 0, negative) rejected with error, multiplier unchanged.
- FR-005: speed affects ticks per real second, never ticks' delta (always 1 tick); AutoRunner interval = base/speed.
- FR-006: query interface: elapsed time, paused, speed.
- FR-007: loop independent of renderer; tick interval runtime-configurable, effective next tick.
- FR-008: serialize tickCount, paused, speed (enum value), tickIntervalMs as integers, lossless.
- FR-009: deserialize; invalid (negative tick, unknown speed, missing field, NaN) => throw, no default fallback.
- FR-010: same seed + same command sequence => same time state.
- FR-011: calendar helpers toDay/toWeek/toYear derived only, never stored.
Constants: ticksPerHour 12; 288 ticks/day; 6250 ms/tick @1x; 1 game day = 30 real min @1x (=48x realtime); safe int max 2^53-1.

## 4. Dependencies
Provides: GameTime/tickCount to everything (005 expiry ticks, 003 async resolution, 006 `time` root key, 007 engine.tick/getTime). Consumes: nothing except 006 for persistence shape, 007 for host class. Constitution II (no Date.now in sim).

## 5. Ambiguities / gaps / contradictions
- Speed "enum value/index" numeric encoding never defined (0..4 index? ×1000? e.g. 250/500/1000...). 006 just says "speed-multiplier enum value". Blocks save compat.
- Year/week lengths undefined (days/week assumed 7; days/year, months, no calendar names). toDay() 0- or 1-indexed? return types (int vs object)? toGameHours() float vs integer rule.
- Command/query names not specified; 007 uses `getTime()` and `getGameTime()` inconsistently; no event names (pause/resume/speedChanged events? spec 010).
- "tick while paused": does engine.tick() no-op entirely (no systems run) or run systems without time advance? Edge case says "should not advance time" only. Also how are commands issued: direct methods or through command queue (spec 012+)? 
- Error classes not named (invalid speed, invalid time state).
- tickIntervalMs lives in sim state but is only consumed by AutoRunner (host/real-time concern); mixed with ×speed gives non-integer ms (1562.5) - rounding unspecified. tickIntervalMs validation range unspecified (0? negative?).
- AutoRunner: no spec for drift handling/catch-up/max ticks per frame, timer injection for tests, start/stop/pause vs engine pause relationship.
- "Speed changes take effect within one tick cycle" - AutoRunner must re-read speed each tick (setTimeout chain, not setInterval).
- US3 AC3 "game loop 10 ticks/sec" conflicts with default 6250ms; only illustrative.
- Tick-processing order of systems is not defined here (belongs to another spec).

## 6. Acceptance scenarios / tests
- Pause: tick while paused leaves tickCount; resume advances +1; query while paused stable; save includes paused flag; load restores paused.
- Speed: invalid values (0, -1, 3, NaN) rejected & unchanged; valid set accepted; get speed; save/load speed; AutoRunner interval math per speed (2x = 2 ticks per base interval, each tick still +1).
- Headless: 100 ticks with no renderer; mid-run renderer attach no effect; headless vs loaded save advance identically.
- Serialization: 500h(=6000 ticks) 2x paused -> JSON fields; load into new instance; two instances same save + N ticks identical; same save loaded multiple times independent; invalid save (negative tick, unrecognized speed, missing field, NaN) throws.
- Calendar helpers derive from tickCount only (e.g. 288 ticks = day 1).
- SC: 1M ticks without overflow/leak; pause zero drift; serialize round trip bit-equal; determinism; 100% field coverage.
- No Date.now/performance.now used in sim (lint/grep test).

## 7. Size: S-M (small core; M including AutoRunner + validation + calendar).
