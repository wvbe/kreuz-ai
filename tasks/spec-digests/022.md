# Digest 022 - Game World Content (13th-century setting) - spec.md 1123 lines, fully read

## 1. Purpose
Defines the baseline DATA set (JSON, Zod-validated) the engine loads: 13 ID-keyed registries + fixed-key config tables. No engine logic, except engine-registered BT handler names and a content loader/validator.
Setting: generic W-European 13th c., no magic, no anachronisms, one currency (silver_penny).

## 2. Implied module / file layout, schema, formats
Spec fixes: JSON files, Zod schemas -> TS types via z.infer, STATIC imports in a FIXED ORDER (no fs scanning), registries read-only after load, kebab-case file names (e.g. raw-resources.json), snake_case content IDs, dot-namespaced snake segments for job/activity/modifier IDs. Authored decimals -> fixed-point x1000 at load (spec 006 FR-014). Spec does NOT fix the directory. Proposed (src/game/content/ ; README.md in EVERY folder per 023 FR-016):
```
src/game/content/
  schemas/            MaterialSchema.ts SkillSchema.ts NeedSchema.ts TerrainSchema.ts TraitSchema.ts FurnitureSchema.ts
                      ZoneTypeSchema.ts FactionSchema.ts JobTypeSchema.ts RecipeSchema.ts BehaviorTreeSchema.ts
                      EntityPrototypeSchema.ts NameListSchema.ts ContentConstantsSchema.ts (+ fixed-key table schemas)
  data/               materials/{raw-resources,processed-goods,tools-equipment,food-drink,currency}.json (split free)
                      skills.json needs.json terrain.json traits.json furniture.json zones.json factions.json jobs.json
                      recipes.json behavior-trees.json entity-prototypes.json name-lists.json
                      dwelling-levels.json settlement-tiers.json difficulty-modes.json content-constants.json
                      moment-templates.json name-formats.json     (last 6 = fixed-key tables)
  ContentLoader.ts    static imports in fixed order -> ContentRegistries (readonly)
  ContentValidator.ts cross-ref + count + tier rules; returns ALL errors in one pass
```
Note: 023 FR-003 forbids import extensions but JSON static imports need ".json" (+ resolveJsonModule) - see section 5.

Record shapes (inferred from tables; spec gives field names only where quoted):
- Material: id, name, categories[], stackLimit (int), weight (NOT given for any material), value? (NOT given), perishability? (positive int ticks; REQUIRED if perishable; "Yes (slow)" -> larger value). Inputs column is descriptive, recipes are authoritative.
- Recipe: id, name, inputs[{materialId,qty}], outputs[{materialId,qty}] (byproducts allowed), durationTicks, workstation (furniture id/tag), roomRestriction?, skill? (id, null = none), unlockTier?.
- Furniture: id, name, categories[] (tags), hasInventory, constructionMaterials[{id,qty}], storage: slots, weightLimit, materialFilter(categories); effect(s); unlockTier?. Components: Position required, Inventory optional.
- ZoneType: id, requiresRoom, minTiles, furnitureRequirements[{tagOrId,count}] ("any bed type", "2x Crate or 2x Chest" => needs tag + OR syntax), effects[] ("activity.unlock: baking", "entity.modifier: inventory.decay.rate x 0.5", "mood.bonus +5", "safety.bonus +10 (area)"), skillAffinity?, unlockTier?.
- HumanoidPrototype: id, startingSkills{skill:int}, equipment[{material,qty}], defaultFactions[], needPriority? override, traitSlots 1-3, sellsItems?, nameListId? (default common_13c), givenName?, byname?, behavior tree id. Components Position, Inventory, TaskQueue, factions, needs.
- AnimalPrototype: id, kind livestock|wild, products/drops[], tendingSkill?, zone?, habitat terrain[], behavior tree id, threatLevel.
- Skill: id, name, baseGrowthPerCompletion (decimal->x1000), diminishingReturnsThreshold 0-100, diminishingFactor, outcomeEffects[] (maxSpeedBonus | outputBonus | qualityBonus per 020 FR-007), titleNoun (required).
- Trait: id, name, modifiers[]: skillAptitude{skill|ALL, growthMultiplier, startingValueBonus?}, performanceModifier{skill|ALL work|ALL crafting, multiplier|outputBonus|speedMultiplier}, needModifier{need, decayRateMultiplier, satisfactionBonusMultiplier, or mood bonus}.
- Need: id, name, decayRatePerTick, criticalThresholdPct, satisfactionMethods[] (item -> +N, furniture -> restore/tick, zone passive bonus).
- JobType: id, name, skillDomain|null, toolRequired?, zoneContext (zone id(s) | terrain | per-recipe | any), recurrence (one-time | recurring | one-time-per-season | recurring daily), outputs?[{materialId,quantity}] (gathering jobs, FR-024), unlockTier?, "not a job-board job" flag for diplomacy.dispatch & govern.steward_audience.
- Terrain: id, name, traversable, buildable ("No (must clear)"), speed modifier class (slow/very slow/fast/fastest - NUMBERS NOT GIVEN), harvestable[].
- Faction: id, name, factionType occupational|religious, leaderTitle, disposition (mercantile|isolationist...), membership criterion {skill,min}, masterSkillThreshold (0-100, > membership min, default 60), associatedZones[] (religious), mechanics.
- BehaviorTree: JSON node tree {type: selector|sequence|condition|action, name?, children?}, depth <= 5, names must resolve to engine-registered handlers.
- NameList: id, weighted givenNames[], bynames[]. 
- ContentConstants (FR-023): stewardReviewTickOfDay, stewardAudienceTicks, maxOpenRunsPerOrder, maxStandingOrders, defaultRestockFraction, noticePostRadius, bellRadius, bellRingTicksOfDay; housingEvaluationTickOfDay(72), upgradeGraceDays(3), downgradeGraceDays(7 > upgrade), foodVarietyWindowDays(3), householdStockDays(2), maxImmigrantsPerDay(2); minFoundingMembers(3); titleThreshold, titleSwitchMargin, finestMinimumLevel, finestCooldownDays, bynameChance, nameRedrawLimit, journalCapacity, chronicleCapacity. (Only some values given.)
Public API implied: loadContent(): ContentRegistries | throws ContentValidationError{errors[]}; typed readonly getters per registry; engine-side registerBehaviorHandlers (conditions/actions); registers condition `household_needs_goods`, action `fetch_household_goods`.

## 5. Validation rules (loader/validator)
Per-record: Zod shape; IDs snake_case / dotted; ints in range (skill 0-100, trait slots 1-3, perishability>0 when perishable, masterSkillThreshold > membership min, downgradeGraceDays > upgradeGraceDays).
Cross-ref (dangling = error): recipe -> materials, workstation furniture, skill; furniture construction -> materials; zone furniture reqs -> furniture tags/ids; prototype -> skills, traits, factions, materials (equipment), nameListId, BT id; trait -> skills/needs; need satisfaction -> items/furniture/zones; job -> skill, tool material, zone, outputs materials; terrain harvestables -> materials; faction -> skills, zones; livestock products -> materials; BT handler names -> engine registry; unlockTier -> SettlementTier + 027 FR-010/011 consistency; dwelling-level keys complete; moment-template keys complete; name list dupes + byname vs titleNoun.
Corpus-level (belong in content-pack tests, NOT the loader, so a slice pack can load): count minima (FR-001..014), no orphan raw materials (except eaten/medicinal), every processed material has >=1 producing recipe, every tool required as non-consumed tool by >=1 recipe/construction job, no recipe dependency cycles, >=70% materials in a recipe (SC-006), >=3 chains depth>=3, no two zone types with identical requirement sets, BT depth<=5, exactly 9 occupational and 3 religious factions (as written), >=15 food items each declaring perishability or non-perishable.

## 8. Ambiguities / contradictions / missing (implementation blockers marked [B])
1. [B] No directory/location for data files and no loader API; Zod schema field names are not given (only inferred). Must be fixed in plan.
2. [B] JSON import vs 023 FR-003 "no file extensions": JSON static imports require ".json" and `resolveJsonModule`; needs an explicit exemption.
3. [B] Missing prototypes: wall, door, job_board, town_crier, diplomatic_envoy (stated open question). Also no steward/notice-post-driven prototypes for 026 beyond notice_post furniture; bell_tower is a zone requiring church_bell.
4. [B] Behavior-tree template reference ("Fallback: daily_routine", "called by daily_routine") undefined with only 4 node types; daily_routine never actually calls worker_cycle (it inlines the work branch). Proposal: a `subtree` action or engine action `run_tree:<id>`.
5. [B] gathering-job `outputs` (FR-024) unauthored; also no crop/seed model: farm.sow/harvest has no seed material, crop->terrain->yield mapping (fertile_soil yields wheat/barley/rye/vegetables - which?), no growth time, no calendar/season system (open question, "one-time per season").
6. [B] Skill effects: trading ("improved evaluation accuracy") and preaching ("faith.bonus +5") are not valid 020 FR-007 effect types (open question).
7. Hunting/butchering/shearing/milking: wild "drops on hunt" and livestock "butcher/shear/milk" have no job types (only tend.animals); Butcher's Block has no recipe; no `hunt` job; Apiary has no recipe (tend.bees outputs).
8. charity.distribute job missing from registry (open question) though used by mendicant friars.
9. Material `weight` and `value` required by the Material story but not provided for any item; storage weight limits (e.g. 200) have no unit; no hunger/other need starting values ("initialized to starting values" - not given); only a subset of food has hunger values (Cheese, Fruit etc. listed; Eggs, Ale, Pottage OK; Salted Fish, Butter, Preserves, Rye Bread absent).
10. Mood is referenced as a need-like stat (generous/miserly traits "mood: bonus", priest "mood below 15%", great_hall mood.bonus) but is not in the need registry. Modifier ID vocabulary (mood.bonus, social.bonus, faith.bonus, safety.bonus, inventory.decay.rate, activity.unlock:*) not defined as a registry; spec says "valid modifier IDs" are verified.
11. Zone furniture requirement grammar: tags vs ids ("any bed type", "2x Crate or 2x Chest", "Oven" is both prototype name and tag). Furniture categories list "bed" tag but pantry/etc. Recipe "Workstation" is a name not an id; recipes also carry optional room restriction without any example.

Forge furniture is used by no recipe (only by Smithy requirement). Charcoal only burns oak (3 oak -> 2 charcoal) though material says oak/pine/birch.

18. Terrain: traversal speed multipliers numeric values not given; "forest clearing yields grassland" rule has no schema field (clearsTo); stone_road "requires construction" but no recipe/construction entry; floor_* terrain vs furniture/construction of floors; sub-map terrain (caves) not defined.
