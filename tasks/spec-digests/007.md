# Digest 007 - GameEngine Bootstrap

## 1. Purpose
`GameEngine` entry point: `newGame(options)` / `loadGame(save)` produce an idle, manually-ticked, headless engine (seed handling, Zod-validated options, dependency-ordered system init hooks, query facade). Constitution seed carve-out lives here.

## 2. Module layout / public API (as stated)
Implied: `engine/GameEngine.ts`, `engine/options.ts` (Zod schema, enums), `engine/SystemRegistry.ts`, `engine/errors.ts`.
- `GameEngine.newGame(options?: GameInitOptions)` -> idle engine (spec writes it as static AND as an instance-level reset; see issues). `GameEngine.loadGame(save: string | object)` -> idle engine. `engine.tick()` (manual; no auto-run). Query facade: `getEntities()`, `getState()`, `getTime()` (US5 says `getGameTime()`), `getEntityAt(id)` (by ENTITY ID, not by location), `getMap(id)`, `getComponents(entityId)`. `engine.prng.getSeed()`.
- `GameInitOptions`: `difficulty: Difficulty` (enum Peaceful|Steady|Harsh; string values peaceful|steady|harsh; default Steady), `startingTier?: SettlementTier` (default Hamlet, 027 FR-022), `mapSize?: MapSize` (Small|Medium|Large), `seed?: integer`, "starting entity counts" (US1/US3 only), "other game-specific params". Stored as `initOptions` in GameState (006). Unknown fields ignored.
- `SystemRegistry`: systems register init fns with dependency declarations (API names not given); topological sort, cycle detection error, missing dependency error; run synchronously before newGame returns.
- Errors: `InvalidSaveFormatError`; validation error message format "Invalid difficulty: 'super-hard'. Valid values: peaceful, steady, harsh."; `OutOfMemoryError` (rollback).
- Events: `game.started`, `game.loaded` (spec 010).
- Bootstrap output: tick 0, entities = exactly one: player government faction (021 FR-002) with `SettlementProgress` (027 FR-002) and `SettlementChronicle` (028 FR-018). No map unless map options (e.g. mapSize) given => generator calls (spec 004).

## 3. Functional requirements
- FR-001 `newGame(options?)` returns idle engine; loop doesn't auto-run.
- FR-002 init loop infra, time 0, entity collection with only government faction (+progress, chronicle); caller must call tick().
- FR-003 fully unload any previous game.
- FR-004 `loadGame(save)` string|object, resumes; engine does no I/O; returns idle.
- FR-005 loadGame parses GameState (006), restores entities/components/time/async tasks.
- FR-006 reject (typed) on invalid JSON/validation fail/newer version; older migrated.
- FR-007 options: difficulty(default steady), startingTier(default Hamlet), mapSize, seed, other.
- FR-008 no seed => generate exactly once at bootstrap, record in initOptions (only allowed non-determinism).
- FR-009 pass seed to PRNG (011) before loop starts.
- FR-010 Zod (or equivalent) validation before creating game.
- FR-011 headless: no window/renderer/UI.
- FR-012 options serializable and stored in GameState.
- FR-013 bootstrap doesn't need other systems pre-initialized (registries pre-registered separately).
- FR-014 repeated newGame/loadGame transitions leak nothing.
- FR-015 system-init hook: topo-sorted by declared deps; missing dep => clear error; cycles rejected (SC-008).
- FR-016 query methods listed above exist after newGame.
- FR-017 no check that required prototypes are registered; failure deferred to runtime.
Perf: SC-001 bootstrap <100ms; SC-002 validation reject <50ms; SC-007 queries <5ms @1000+ entities; SC-006 runs in Node/Deno/browsers, no native modules or fs.

## 4. Dependencies
Consumes: 001 (tick/time), 006 (GameState, loadGame/migration), 004 (generators for mapSize), 011 (PRNG), 010 (events), 021 (government faction prototype), 027 (Difficulty/SettlementTier, multipliers FR-013..016, FR-022), 028 (Chronicle), 022 (registries), 003 (entities). Provides: engine host used by every test and by AutoRunner (001).

## 5. Ambiguities / contradictions / blockers
- Static vs instance: `GameEngine.newGame()` (static factory) vs "second newGame() call on an engine unloads previous" (instance method). Pick: `new GameEngine()` + `engine.newGame(opts)` (reset) or static factory + no reuse; US5 "separate engine instances" assumes the former.
- FR-017 (don't validate prototypes) contradicts FR-002 (bootstrap instantiates government faction + components): a missing prototype breaks newGame itself. Also circular: prototypes/registries must exist before newGame but registration API not specified (global vs per-engine).
- "starting entity counts" option (US1, US3 text) contradicts FR-002 ("bootstrap creates no other entities") and Bare-minimum default; FR-007 omits it. Treat as removed.
- Map generation: Assumption "map generation is separate/out of scope" vs US3 AC1 and Assumptions say newGame creates a starting map through 004 generators when mapSize given. MapSize -> cell count/generator mapping, which generator(s)/sub-maps, and whether village pass runs, undefined.
- Method name drift: `getTime()` (FR-016) vs `getGameTime()` (US5 AC3); `loadGame` vs 006 `load`; `getEntityAt(id)` misnamed. Return type of getState() (live object vs snapshot) unspecified; SC-007 "direct access" implies live reference (violates immutability/encapsulation vs 001 "no public mutable state").
- Seed: integer range, source of random seed with no Date.now/Math.random in sim code (inject entropy source for tests), PRNG algorithm (011). Seed `0`/negative/float validation.
- `OutOfMemoryError` is not reliably catchable in JS; unimplementable as written. "Previous game unloaded" vs "current state unchanged on failed load": implement load-into-temp then swap; failed newGame validation must happen before unload.
- System init hooks: registration API/names, whether they run on loadGame (state restore) and ordering vs deserialization, async hooks not allowed, who owns the registry (global singleton leaks across engine instances - conflicts with FR-014/US5 AC5 isolation).
- Zod "or equivalent": runtime dependency choice (SC-006 no native modules ok). Forward compatibility: unknown fields ignored but typos in option names pass silently.
- Event emission `game.started/loaded` timing relative to hooks; whether tick 0 events exist.
- Missing required fields: none required, so US4 AC3 vacuous.
- Difficulty is also stored in `initOptions` and affects decay/hostility only via multipliers (027); startingTier effect on bootstrap entities unspecified.

## 6. Acceptance scenarios / tests
- newGame(): time 0, idle (tick not auto-run), exactly 1 entity (government faction w/ SettlementProgress + SettlementChronicle), no map without options; `{difficulty: Harsh, seed:12345}` stores both; seed absent => generated once, in initOptions and in save, reproducible replay; second newGame fully replaces state; options recoverable from save.
- loadGame(): string and object inputs; entities/components/time/tasks restored; next tick deterministic; empty/non-JSON/corrupt => InvalidSaveFormatError, state unchanged; load->save identical (minus timestamp); newer version rejected; older migrated.
- Options: mapSize Small + Peaceful => generated starting map (004 generator) ; `engine.prng.getSeed()==42`; difficulty only scales decay/need/hostility, same map/entities across difficulty (027 FR-016); invalid difficulty/type (`mapSize:123`) rejected with specified message format; unknown fields ignored; params preserved in saves.
- Headless in Node w/o `window`; ticking deterministic; query API works (<5ms @1000 entities); save written/read by host; two engines side by side isolated.
- SystemRegistry: topological order, missing dependency error, cycle error; hooks run before newGame returns.
- Perf: bootstrap <100ms; validation <50ms; repeated newGame no leak.

## 7. Size: M (small surface, but integrates everything; Zod options + registry + isolation).
