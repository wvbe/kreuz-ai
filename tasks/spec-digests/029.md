# Digest 029 — Dwellings & Household Upgrades

## 1. Purpose
Player designates enclosed bed rooms as `dwelling` zones with four levels (Hovel -> Burgher House); a daily housing evaluation assigns homeless citizens, consumes supplied goods, advances up/downgrade streaks with grace periods, collects rent into the treasury, and admits settlers (seeded `housing.immigration`), giving production chains a goal loop.

## 2. Module layout / public API
Implied: `housing/` (daily evaluation pipeline, requirement evaluators, household fetch chore action `fetch_household_goods`, immigration, rent), content `dwelling` zone type + `dwelling-levels.json` + constants, hooks into 013 (beds, food recording), 018 (reservation), 015, 019, 024 FR-042..044.
Enums: `DwellingLevel {Hovel:"hovel", Cottage:"cottage", TimberFramedHouse:"timber_framed_house", BurgherHouse:"burgher_house"}`; `DwellingRequirementKind {MinTiles, Furniture, FoodVariety, ServiceNearby, SuppliedGood, TierUnlocked}`; `EvictionReason {CapacityReduced, DwellingChanged, DwellingRemoved}`; `RentShortfallReason {InsufficientFunds, TreasuryUnavailable}`; `ImmigrationBlockedReason {NoSeatOfGovernment, NoArrivalCell}`.
Components: `Dwelling { level, upgradeStreak, downgradeStreak, consumptionAccumulators: map(group index -> milli-units), foodRecord: map(foodMaterialId -> last game day eaten), lastEvaluatedDay }` on zone entity; `Citizen.homeDwellingId (zoneId|null)`, `Citizen.homeAssignedTick`.
DwellingLevelDefinition (dwelling-levels.json, exactly one per level): `{ level, capacity, rentPerDay, minTiles, furniture:[{type|tag,count}], foodVariety, services:[{zoneTypes[],maxPathCells}], suppliedGoods:[{materialIds[] (any-of, ordered), perResidentPerDay (authored decimal, stored x1000)}], immigrantPrototypes (weighted), unlockTier? }`.
Zone type: `dwelling` { requiresRoom: true, minTiles: 4, furniture 1x (tag bed) }.
Queries: dwelling level/capacity/residents/rent; `getDwellingRequirementStatus(dwellingId)` -> per-requirement entries (kind, met, required, current, e.g. `FoodVariety{current,required}`, `ServiceNearby{zoneTypes, nearestPathCells|null, maxPathCells}`, `SuppliedGood{materialIds,inStock,needed,status}`) for current and next level + both streaks + grace constants; `countDwellingsAtOrAbove(level)`; totals of housed, homeless, free slots.
Events: `housing.dwelling.upgraded {dwellingId,fromLevel,toLevel}`, `.downgraded {…}`, `.at-risk {dwellingId,level,unmetRequirements}` (on evaluation where downgradeStreak becomes 1), `housing.resident.assigned {dwellingId,entityId}`, `.evicted {dwellingId,entityId,reason}`, `housing.rent.collected {dwellingId,amount}`, `.unpaid {dwellingId,shortfall,reason}`, `housing.goods.consumed {dwellingId,materialId,quantity}`, `housing.immigrant.arrived {entityId,prototypeId,dwellingId}`, `housing.immigration.blocked {reason}`.
Action handler `fetch_household_goods` (registered per 022 FR-014; 022 BT template already lists it). PRNG stream `housing.immigration` (011 FR-010, `randomWeighted` FR-006).
Constants (022 FR-023): `housingEvaluationTickOfDay`=72, `upgradeGraceDays`=3, `downgradeGraceDays`=7 (must be > upgrade), `foodVarietyWindowDays`=3, `householdStockDays`=2, `maxImmigrantsPerDay`=2.
Representative level table (tunable): Hovel minTiles4, no extras, food0, cap2, rent1; Cottage 6 tiles, +Hearth, food2, Chapel|Church <=40, cap3, rent2; TimberFramedHouse 9 tiles, Hearth+Table+1 (tag storage), food3, Chapel|Church<=40 & Tavern<=40, Ale0.5 + Candle0.25, cap5, rent5; BurgherHouse 12 tiles, Hearth+Table+2 Chair+Tapestry+1 storage, food4, Church<=30 & Tavern<=30, Ale0.5 + Candle0.5 + (Linen Cloth|Wool Cloth)0.2, cap6, rent10. Immigrant tables: Hovel peasant/lumberjack/shepherd; Cottage farmer/fisherman/miner/cook; TFH carpenter/mason/blacksmith/baker/brewer/weaver; Burgher merchant/scholar + master-craft.

## 3. Functional requirements
- FR-001 Content `dwelling` zone type (requiresRoom true, minTiles 4, 1x tag bed). Unmet base => inactive.
- FR-002 DwellingLevel enum (spec 023 FR-005), display names Hovel/Cottage/Timber-Framed House/Burgher House.
- FR-003 dwelling-levels.json exactly one entry per level (missing/duplicate/unknown = load error); fields as above; all references must exist (022 FR-015).
- FR-004 Dwelling component fields (authoritative serialized progression).
- FR-005 Home stored only as Citizen.homeDwellingId + homeAssignedTick; household derived by query; only adult humanoid player-faction members are housed.
- FR-006 Daily housing evaluation at tickCount mod ticksPerDay = housingEvaluationTickOfDay (72); dwellings processed ascending zone entity id; order per evaluation: (1) clear invalid homes, (2) consume supplied goods, (3) evaluate requirements & update streaks/levels, (4) apply evictions, (5) collect rent, (6) house homeless, (7) admit settlers.
- FR-007 Requirement kinds. MinTiles/Furniture counted over dwelling tiles; FoodVariety met when distinct materials in foodRecord within last foodVarietyWindowDays >= level.foodVariety; TierUnlocked met when no unlockTier or settlement tier (027) >= unlockTier.
- FR-008 ServiceNearby met when an ACTIVE zone (015 FR-008) of a listed type has a tile whose min path cost (integer, 012 FR-001) from some dwelling tile <= maxPathCells; cost only, no tie-breaking/PRNG; unreachable = unmet (012 FR-004); bounded multi-source search allowed (012 FR-010) if equal.
- FR-009 SuppliedGood: daily demand = residentCount * perResidentPerDay (milli) added to group accumulator; need floor(acc/1000) units; consume from storage furniture on dwelling tiles in group materialIds order, furniture ascending id; all available -> consume, subtract 1000*units, met; else consume nothing, accumulator capped at 1000*units, unmet. No storage furniture => fails every SuppliedGood with `NoHouseholdStorage`. Emits `housing.goods.consumed` (025 ledger HouseholdConsumption).
- FR-010 Demanded goods = union of suppliedGoods of current and next level; consumption applies to every demanded good.
- FR-011 Streaks updated only for active dwellings with >=1 resident. All next-level requirements met -> upgradeStreak++ else reset 0; at upgradeGraceDays level +1 exactly, both streaks reset. Any current-level requirement unmet -> downgradeStreak++ else 0; at downgradeGraceDays level -1 (never below Hovel), both streaks reset. Inactive/uninhabited: streaks unchanged. downgradeGraceDays > upgradeGraceDays validated at load.
- FR-012 Capacity = min(level.capacity, tag-bed count on dwelling tiles); over-capacity: evict latest homeAssignedTick (ties higher entity id) first.
- FR-013 Rent each evaluation from every active dwelling with >=1 resident: up to rentPerDay coin taken from residents' inventories ascending id, 1 coin per resident per round robin; deposited into treasury (019 FR-003) with wage-transfer semantics reversed (019 FR-012); no container space => nothing moves (TreasuryUnavailable); shortfall => `housing.rent.unpaid`, no carry-over; not a tax.
- FR-014 Homeless eligible citizens ascending id each assigned to active dwelling with free capacity of highest level, ties ascending zone id; set homeDwellingId/homeAssignedTick; emit assigned.
- FR-015 Immigration after FR-014: freeSlots = total free capacity of active dwellings; spawn min(freeSlots, maxImmigrantsPerDay) settlers; each fills next free slot in FR-014 order; prototype from that level's immigrantPrototypes via randomWeighted on `housing.immigration`; traits (020 FR-004), name at spawn (028 FR-004); joins player faction; placed at arrival cell then walks to dwelling. Arrival cell = traversable main-map boundary cell with min path distance (FR-008 metric) to seat of government (Throne Room), ties lowest cellIndex. No seat/boundary => no settlers + `housing.immigration.blocked`.
- FR-016 Fetch chore: if stock of a demanded group in household storage < householdStockDays days of demand, household eligible; at most one resident per household fetching; chosen by utility scoring (013 FR-014) via `fetch_household_goods`, only when resident holds no claimed job; takes shortfall (bounded by carry capacity) from nearest accessible non-household source (018 FR-011..013) into dwelling storage furniture; never a job-board posting; no source => household exposes MissingInput.
- FR-017 Household reservation: storage furniture on dwelling tiles (active or inactive) accessible only to residents; excluded from others' material queries (018 FR-012), hauler routing tiers (018 FR-010), settlement stock (025 FR-013, 026 FR-006). Beds only usable by residents; residents prefer own dwelling beds (013 FR-002).
- FR-018 On each food-category consumption by a resident record materialId -> current game day in household foodRecord; prune entries older than window each evaluation.
- FR-019 Headless queries listed above.
- FR-019a Dwelling is a 025 status subject: reports DwellingRequirementsUnmet{targetLevel,unmet} (Idle if only next-level unmet, Blocked if current-level unmet), NoHouseholdStorage, MissingInput (fetch), LockedByTier, ZoneInactive when inactive; reported at each daily evaluation.
- FR-020 Events listed above.
- FR-021 Serialize Dwelling component, homeDwellingId/AssignedTick, `housing.immigration` stream, in-progress fetch tasks; requirement status re-derived.
- FR-022 All housing numbers content data (level table fixed-key config; constants in 022 FR-023); no wall-clock or non-stream randomness.
Edge rules: split zone -> both keep level, streaks reset, residents stay with zone retaining original id (excess homeless: DwellingChanged); merge -> lower level, streaks reset, residents kept by ascending assignment tick up to capacity (rest DwellingChanged); delete -> state removed, residents homeless (DwellingRemoved), goods stay in now-ordinary furniture; resident death/leaves faction clears home; services unlimited/shared; goods no longer demanded stay; load re-derives requirement satisfaction.

## 5. Ambiguities / blockers
- Same default tick 72 as 026 review (stewardReviewTickOfDay): both mutate stock (housing consumes/fetches; Steward counts stock); no cross-spec intra-tick ordering. Also tier eval at tick%288==0 vs 72 — tier is stale by a day for dwelling counts.
- Supplied-good accumulators keyed by "group index" while demanded goods = union of current + next level groups (FR-010): group indices differ per level (e.g. TFH group0 Ale/group1 Candle, BH group0 Ale/group1 Candle/group2 Cloth) and the rates differ (Candle 0.25 vs 0.5); union rule and which rate applies when both levels demand same material are undefined; on level change accumulators keyed by index become invalid.
- Which requirements set is evaluated for SuppliedGood met flags: both current (for downgrade) and next (for upgrade); but consumption (step 2) happens once for the union; unclear how a good demanded by next level but already consumed under current-level group counts for each.
- Goods consumed for next-level requirement even when other next-level requirements fail (wasteful, intentional?). Top level: no next => no extra.
- Step 1 "clear invalid homes" not defined (dead, left faction, dwelling gone? non-adult?).
- Eviction in step 4 after streak update; in step 3 capacity may drop on downgrade; but capacity also drops when beds removed (no level change) — handled by FR-012 each evaluation? Not stated explicitly in step order; US4 only covers downgrade.
- Settlers fill "next free slot in FR-014 order" but spawn count uses total free slots incl. slots reserved by assignment ordering; whether a new settler prototype is drawn from the dwelling's level before assignment tick is set; `homeAssignedTick` for settler = spawn tick vs arrival tick (matters for eviction order).
- Children/non-adults: 026 and 029 say "adult humanoid" but no spec defines children/ageing (028 notes none). Fine but "adult" predicate undefined.
- Dwelling inactive but with residents: beds/storage remain reserved; rent not collected; other inactive effects fine. An "uninhabited" dwelling never builds streak => cannot upgrade empty house, but immigration assigns residents at step 6 after step 3, so first upgrade streak counts start next day.
- Spec 025 Dwelling subject vs Zone subject (same entity) double reporting. 025 edge-case says Dwelling Blocked on current-level unmet; zone-level ZoneInactive overlay: rule in FR-019a.
- Food variety counts per household: FR-018 "household foodRecord" keyed by the resident's household; residents with no home contribute nothing; homeless food not recorded. Food category membership uses 022 `food` category; the hook point for recording is the `need.item.consumed` event (013 FR-023) -> must map entity -> homeDwellingId.
- Path distance "from some dwelling tile" uses tile-to-tile cost; Church <=40 vs 027 pathing cost units (integer edge costs vs "path-cells" naming): cost units not equal to cells if terrain costs vary (012 FR-001). Terminology mismatch "maxPathCells".
- Money supply open question (rent is pure transfer; treasury never increases from coin creation -> "bring more coin" claim false), unpaid rent consequences, trade-based goods, shelter need: all open.
- Arrival cell metric and `cellIndex` tie-break: need 004's cell index definition; arrival cell recomputed daily (could change as roads/walls change).
- `homeAssignedTick` ties for same tick: higher entity id evicted first.
- 027 unlock table doesn't include `dwelling` zone type; dwelling-level `unlockTier` values not assigned anywhere (needed for Tavern/Church gating of TFH/BH; Tavern is Village, Church Market Town, so Burgher House must be >= Market Town to be satisfiable; Chartered Town requires 3 Burgher Houses).
- Fetch chore competes with job claims: "only when it holds no claimed job" but job claims later may preempt mid-fetch; interrupt semantics undefined; in-progress fetch tasks serialize (FR-021) but task format unspecified.
