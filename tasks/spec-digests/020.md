# Digest 020 - Skills & Traits

## 1. Purpose
Entities have integer 0-100 skills (stored as x1000 fixed-point) that grow on work completion with diminishing returns, plus immutable traits (aptitudes, performance modifiers, need modifiers). No professions: specialisation emerges because skill raises job affinity and work outcomes.

## 2. Implied module layout / public API
Module: skills (SkillRegistry, TraitRegistry, SkillProfile/TraitList components, growth system, outcome calculator, affinity query).
- `SkillRegistry` entry: `skillId` (string), name, `baseGrowthPerCompletion` (decimal authored -> x1000), `diminishingReturnsThreshold` (int, e.g. 50), `diminishingReturnsFactor` (decimal -> x1000, e.g. 0.5), `outcomeEffects[]`: `maxSpeedBonus` (e.g. 0.5), `outputBonus { maxExtra: n }`, `qualityBonus` (reserved no-op).
- `TraitRegistry` entry: `traitId`, name, description, `modifiers[]`: `skillAptitude { skillId, growthMultiplier, startingValueBonus }`, `performanceModifier { domain, multiplier }` (e.g. `speedMultiplier`, trade `minimumMarginRate` add), `needModifier { needId, offset }` (013).
- `SkillProfile` component: map `skillId -> accumulated fixed-point [0..100000]`; queried level = `floor(acc/1000)`; missing = 0 or prototype start value (022).
- `TraitList` component: trait ids, immutable (1-3 procedural, any for authored).
- Query: skill profile (all skills with values), trait list (name+effect descriptions), `dominantSkill` (null/"none" if all 0; deterministic tie-break: PRNG or alphabetical).
- Events: in `skill.work.completed { entityId, skillId }` (emitted by construction/production/trade/hauling systems); out `skill.increased { entityId, skillId, oldValue, newValue }` (on floor-integer increase only).
- Functions implied: growth on event, `skillAffinityBonus(entity, domain)`, `effectiveDuration(base, entity, skill)`, `effectiveOutput`, trait-modifier combiner.

## 3. Functional requirements
- FR-001: Skill Registry open data-driven; fields above.
- FR-002: Every entity has skill profile (fixed-point, 0..100000), queried as integer 0..100; serialized.
- FR-003: Trait Registry open data-driven; modifier kinds skillAptitude / performanceModifier / needModifier.
- FR-004: Procedural entities get 1-3 traits at creation; authored may have any; immutable; serialized.
- FR-005: Growth triggered by `skill.work.completed` on event bus; skill system listens.
- FR-006: `growth = baseGrowthPerCompletion x aptitudeMultiplier x diminishingFactor(currentLevel)`; factor 1.0 below threshold, `diminishingReturnsFactor` at/above; accumulate x1000; floor on query; cap 100000.
- FR-007: Outcome effects applied when work executes: `maxSpeedBonus`, `outputBonus`, `qualityBonus`(no-op); linear 0..100; `speedBonus = maxSpeedBonus x level / 100`; `duration = baseDuration x (1 - speedBonus)`.
- FR-008: Trait performance modifiers multiplicative on top; `duration = baseDuration x (1 - speedBonus) / speedMultiplier`; fixed-point; round UP to whole ticks, minimum 1.
- FR-009: Job affinity: `skillAffinityBonus = skill[domain]/100 x configuredAffinityWeight` (global balance constant); incorporated in 017 selection.
- FR-010: Initial skill = prototype start (022, default 0) + trait `startingValueBonus`, clamped [0,100].
- FR-011: All registries data-defined; no code change.
- FR-012: Profile and trait list queryable, reflecting state as of last completed tick.
- FR-013: Emit `skill.increased` on floor-integer increase.

Rules: growth once per completion (not per tick, independent of duration); no growth event at 100; conflicting traits both apply multiplicatively; multiple aptitude traits stack (multiplicative or per trait); dangling skill reference in save/trait = load-validation error (022 FR-015); skills never decrease; registries immutable after bootstrap; "dominantSkill" max skill; entity baking 100 gets no construction benefit; traits' needModifier integrates with 013.

## 4. Dependencies
Consumes: 003 (components), 006 (serialization), 010 (event bus), 011 (PRNG tie-break), 013 (needs), 014 recipes (declare skill granted, duration), 016 (construction duration/skill), 017 (job def declares skill; affinity input), 019 (trade skill; margin modifier), 022 (prototype starting skills, load validation FR-015, procedural trait draw at spawn), 028 (titles derived from skills).
Provides: affinity scoring to 017 (familiarity criterion), dominant skill to 018 (hauler affinity tier 1) and 028, speed/output modifiers to 014/016/019, `skill.increased` events.

## 5. Ambiguities / contradictions / blockers
1. Affinity score vs lexicographic order: 020 FR-009 produces a numeric bonus; 017 FR-007 uses familiarity as an ordered criterion with ties to distance/PRNG. Without a quantisation rule, familiarity (continuous) almost never ties, making distance irrelevant; AC "scores nearly equal at baking 5" implies additive scoring. Also US4 test says "equal stated priority" and 90% pick rate (probabilistic) while 017 is deterministic except ties. Also SC-001 "3x the rate" requires an probabilistic model not defined.
2. Growth examples inconsistent with formula: AC "2 points at level 10" and "0.5 at 90" require `baseGrowth` and factor values; formula gives base x aptitude x 1.0 below threshold, so base=2.0 and factor=0.25 for those numbers; not stated. SC-007 example 0.5/completion needs 20 completions -> base 0.5. Threshold comparison (< or <=) unspecified; uses accumulated or floor level for "currentLevel".
3. Multiple aptitude traits stacking: "multiplicative stacking or as defined per trait" (US3 AC6) vs conflicting-trait edge case "combined mathematical effect" - pick multiplicative and define additive `performanceModifier` types (Greedy adds +0.05 to a rate, not a multiplier).
4. Greedy trait modifies 019's `minimumMarginRate` additively: no hook defined in 019; "domain" naming for performanceModifier (`construction speed`, `speedMultiplier`, trade margin) not enumerated.
5. Who emits `skill.work.completed`? 016, 019, 014 do not state it; 017 board doesn't know skills. Mapping job/recipe -> skillId lives in job/recipe definition (022/014) which does not exist in these specs. Trade completion for both buyer and seller? Wage/idle jobs.
6. `outputBonus.maxExtra` chance function ("chance to produce up to 5") unspecified: probability = level/100? Use PRNG stream? Interaction with trait `outputBonus`.
7. Duration modifier timing: computed at job start vs completion; mid-job skill change; relationship to 016's integer duration and 014 recipe duration (rounding rule only in FR-008).
8. needModifier semantic (offset to what: decay rate, max, mood) deferred to 013 which this reader hasn't seen.
9. `dominantSkill` tie-break "PRNG or alphabetical" - pick one (query must be pure; PRNG in a query breaks determinism).
10. Entity types: skill/trait components on "every entity" including furniture? presumably living only; hauler "adult humanoid" etc.
11. Authored entities' more-than-3 traits and procedural generation algorithm (draw weights, duplicates, conflicts) unspecified.
12. Skill removal edge case and dangling traits refer to 022 FR-015 validation; fine but needs 022.
13. Hostile staleness: `startingValueBonus` unit (levels 0-100 vs fixed-point) unspecified.

## 6. Acceptance scenarios / tests
- US1: default 0 unless prototype/trait; baking 35 survives save/load; new skill `glassblowing` returns 0 with no migration; cap at 100; always integer 0..100.
- US2: baking 10 + recipe -> +configured growth (2 at level 10); at 90 smaller; construction job grows construction only; trait multiplier applied; at 100 no growth event; total growth from 10 < growth from 0 over same completions (diminishing); fractional accumulation (0.5/completion -> floor 10 after exactly 20, SC-007).
- US3: Gifted Baker x1.5 -> 50% faster growth (and fewer completions to 50, SC-004); Heavy-Handed 0.8 -> duration +25%; Greedy margin +0.05; new trait via data only; traits identical after save/load; 3 stacked traits all applied.
- US4: baking 80 vs construction 10 picks bake in >=90% runs; baking 5 near-equal scores, priority/distance decides; skilled baker falls back to other jobs; urgent priority overrides affinity (017 order); 100 in-game hours baking raises baking selection rate (SC-001 3x).
- US5: 24-tick recipe at skill 0 = 24, at skill 100 with maxSpeedBonus 0.5 = 12; outputBonus maxExtra 1 -> up to 5 Bread; new effect via data after bootstrap; trait + skill combined (not overriding); SC-005 difference >= maxSpeedBonus.
- US6: profile lists all skills + dominantSkill; traits show name and effect description; immediate update after growth (no cache lag); all zero -> null/"none"; ties deterministic.
- Edge: determinism SC-002 (same seed/sequence identical values), save/load SC-006, dangling skill/trait reference validation error, conflicting traits both apply, duration rounding up min 1, growth once per completion regardless of duration.

## 7. Size: M
Small data model and formulas but touches many specs via hooks; ambiguity cost is in integration.
