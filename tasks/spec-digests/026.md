# Digest 026 — Standing Orders & Steward

## 1. Purpose
Player sets "keep N of material X in stock" once; a Steward (office held by an adult humanoid, needs active Throne Room) reviews daily, applying hysteresis, and posts `craft.produce` one-run postings on user-managed boards via spec 017 PendingBoardUpdates carried by Town Criers. Later unlocks (Notice Post, Bell Tower) shorten delivery for all user-managed board updates.

## 2. Module layout / public API
Implied: `stewardship/` (orders, steward office, review, owned runs, stock counting), `delivery/` hooks into 017 (notice post, bell tower, `via`), content for `notice_post` furniture and `bell_tower` zone type (already present in 022 catalog tables), renderer 024 FR-029..033.
Types/enums: `StandingOrder { orderId, materialId, recipeId, targetQuantity, restockThreshold, scope: StandingOrderScope{Settlement,Zone}(+zoneId), priority, postingBoardId|null, paused, state: StandingOrderState{Satisfied,Restocking,Blocked,Paused} }` (derived: outputPerRun, countedStock, ownedRuns by status). `OwnedRun { boardId, postingRef(provisional until delivered), status: PendingAdd|Open|Claimed }`. `StandingOrderError {NoProducingRecipe, AmbiguousRecipe(list candidates), InvalidQuantity, DuplicateOrder, UnknownZone, BoardNotUserManaged, IneligibleSteward, TooManyOrders}`. `StewardVacancyReason {Dismissed, Replaced, Died, LeftFaction}`. `DeliveryMethod {TownCrier, NoticePost, BellTower}`. Tier-locked recipe -> 027 `ContentLockedError`.
Commands: `createStandingOrder`, `updateStandingOrder`, `pauseStandingOrder`, `resumeStandingOrder`, `deleteStandingOrder`, `appointSteward`, `dismissSteward`, `setStewardBoard`, `requestStewardReview`. Query `getStandingOrders()` -> fields + `countedStock`, `ownedRuns` by status, `state`, current spec 025 BlockedReason|null.
Task type: `govern.steward_audience` (already in 022 job-type table). Posting: job type `craft.produce`, param `recipeId`, concurrency 1, one-time, priority=order.priority, metadata `standingOrderId`, `deliverToZoneId` (Zone scope).
Events: `standing-order.created|updated|paused|resumed|deleted|restock.started|satisfied`, `steward.appointed`, `steward.dismissed`(reason), `steward.review.completed {tick,ordersEvaluated,postingsQueued,withdrawalsQueued}`, `steward.review.skipped {tick,reason}`, `bell-tower.rang`; modifies 017 `jobboard.update.applied` to carry `via`.
Save: root key `stewardship` = orders list, `nextOrderId`, owned runs (status, board), `stewardEntityId`, Steward board, pending extra-review flag, last review tick. All ints.
Constants (022 FR-023 table, Zod): `stewardReviewTickOfDay`=72 (0..287), `stewardAudienceTicks`=12, `maxOpenRunsPerOrder` (NO default stated), `maxStandingOrders` (NO default), `defaultRestockFraction`=750 (x1000), `noticePostRadius` (no default), `bellRadius` (no default), `bellRingTicksOfDay`=[72,108,144,180,216].
Content: furniture `notice_post` (unlockTier village), zone type `bell_tower` (not room, 1x Church Bell, unlockTier market_town).

## 3. Functional requirements
- FR-001 StandingOrder record fields (above); orderId from monotonic counter; state derived.
- FR-002 Create takes materialId or recipeId. Material only: resolve single recipe whose outputs contain it (0 -> NoProducingRecipe, >1 -> AmbiguousRecipe w/ candidates). Recipe only: target material = first listed output. Both: recipe must output material. outputPerRun = recipe's quantity of target material.
- FR-003 restockThreshold default = floor(target * defaultRestockFraction/1000), clamped to target-1.
- FR-004 Invalid commands rejected with typed StandingOrderError; state unchanged; locked recipe -> ContentLockedError (027 FR-008).
- FR-005 Commands + getStandingOrders() as listed.
- FR-006 countedStock = sum over scope of: (a) storage-furniture inventories (018 FR-001/002) excl. household storage (029 FR-017); (b) Settlement scope only: unreserved units in workstation inventories (014 FR-006, excl. locked inputs 014 FR-013); (c) units carried by entities executing `haul.deliver` to in-scope storage. Settlement scope = all maps of the player settlement (main + sub-maps). Zone scope = furniture on zone's tiles (015 FR-016). Not counted: personal inventories, build sites, loose piles, household storage. (a) for Settlement == getFlowSummary.stock.
- FR-007 Counting is pure read, no PRNG.
- FR-008 Review once/day at tick-of-day stewardReviewTickOfDay, plus next tick after requestStewardReview; only if Steward appointed AND active Throne Room; no wall-clock.
- FR-009 Orders track owned runs (PendingAdd/Open/Claimed); run ceases to be owned on complete, abandon-without-repost, withdrawn, or lost with board/crier.
- FR-010 For each non-paused order: (1) Satisfied && stock <= threshold -> Restocking + `standing-order.restock.started`; (2) Restocking && stock >= target -> Satisfied + `standing-order.satisfied`; (3) desiredRuns = Restocking ? min(maxOpenRunsPerOrder, ceil((target-stock)/outputPerRun)) : 0; (4) owned<desired -> queue (desired-owned) new postings; owned>desired -> queue withdrawal of unclaimed owned runs (PendingAdd first, then Open, newest first) until equal or none left; Claimed never withdrawn.
- FR-011 Evaluate orders in priority desc, orderId asc; deterministic, no randomness.
- FR-012 Each posting = standard 017 JobPosting (craft.produce, recipeId, conc 1, one-time, priority, metadata standingOrderId, deliverToZoneId for Zone scope); claim/execute per 017/014 unchanged.
- FR-013 At most one Steward; eligible = adult humanoid (016 FR-001b), member of player faction (021 FR-002), not a Town Crier (017 FR-012). Stored as `stewardEntityId` in settlement state (not a profession component). No active Throne Room (015 FR-008) -> office stays filled, reviews skipped.
- FR-014 Review skipped (no Steward / no Throne Room): every non-paused order reports NoSteward / NoSeatOfGovernment, status.blocked per 025; owned postings untouched (+ `steward.review.skipped`).
- FR-015 Each review: Steward gets `govern.steward_audience` task: walk to Throne Room, stay stewardAudienceTicks (12); precedence over job-board work, not over critical needs (013 FR-003). Review outcome independent of audience.
- FR-016 Office vacated with `steward.dismissed {StewardVacancyReason}` on dismiss, replace, entity destroyed, or leaving player faction.
- FR-017 requestStewardReview schedules one extra review at next tick; repeats collapse; does not move the daily review.
- FR-018 Every add/withdraw = 017 PendingBoardUpdate on the order's board; dispatched/carried/applied by Town Criers under 017 FR-010..013, merged with player changes for same board; withdrawal hitting a claimed posting = no-op.
- FR-019 Posting board resolved each review: order.postingBoardId -> settlement Steward board (setStewardBoard) -> reachable user-managed board with shortest path distance (012) from Throne Room, tie lowest entity id. Only user-managed (017 FR-008/009). If resolved board differs from board holding unclaimed runs: withdraw there, repost on new.
- FR-020 Outputs of runs with deliverToZoneId: try compatible storage in that zone before 018 FR-010 tiers; fallback to 018 routing if no capacity.
- FR-021 Notice Post furniture (`notice_post`, village). Board is "served" if hop distance on map adjacency graph (004) <= noticePostRadius; nearest post wins (ties lowest id). Crier plans trip to the post instead of served boards; on arrival applies pending updates of every board that post serves.
- FR-022 Bell Tower zone type (`bell_tower`, market_town, 1x Church Bell). At each tick-of-day in bellRingTicksOfDay each active Bell Tower rings, emits `bell-tower.rang`; every pending update whose board hop distance from the tower's Church Bell <= bellRadius is applied that tick and removed from any crier payload/queue; crier left empty returns to Throne Room.
- FR-023 Notice Post and Bell Tower apply to all user-managed board updates (player's too); `jobboard.update.applied` carries `via: DeliveryMethod`.
- FR-024 Emit the 12 events listed.
- FR-025 Order is a status subject (`StatusSubjectKind.StandingOrder`); uses kinds NoSteward, NoSeatOfGovernment, LockedByTier, ScopeZoneMissing, NoReachableJobBoard, AwaitingTownCrier, MissingInput, MissingWorkstation, NoQualifiedWorker, Paused{standingOrderId}; non-Paused reason => state Blocked.
- FR-026 Serialize under `stewardship`; ints; resume identically.
- FR-027 Constants in 022 FR-023 table, Zod-validated, out-of-range = load error.
Edge-case rules (normative in effect): missing inputs -> still post, order shows MissingInput; no workstation -> MissingWorkstation; skill outputBonus may overshoot target (allowed); byproduct counts as stock; harvested materials rejected NoProducingRecipe (open question); category orders unsupported v1; edits apply at next review; paused orders skipped and unclaimed postings withdrawn next review; delete withdraws unclaimed, claimed finish, order record dropped when last run ends; destroyed crier => postings lost and re-posted; one order per (material,scope) else DuplicateOrder; locked recipe loaded from save posts nothing, reports LockedByTier; dangling recipe on load = load error (022 FR-015); review does not run if game paused.

## 5. Ambiguities / blockers
- Missing defaults: `maxOpenRunsPerOrder`, `maxStandingOrders`, `noticePostRadius`, `bellRadius`. Required to implement/test US2.6 (example uses 5).
- Initial state of a newly created order unspecified (Satisfied or Restocking?). If stock <= threshold at creation, first review must flip; if stock between threshold and target at creation, order should be Satisfied (never restocks until <= threshold) -- confirm.
- State precedence: Blocked vs Paused vs Satisfied/Restocking: FR-001 says state in {Satisfied,Restocking,Blocked,Paused} but Blocked loses Restocking/Satisfied info; is hysteresis state retained underneath while Blocked? Not stated.
- Hysteresis formula: Satisfied with stock exactly == threshold restocks (<=), but US2 sc.1 example "stock 17, threshold 15" fine; "target + outputPerRun" band in SC-001 vs hysteresis OK.
- desiredRuns ignores in-flight output of Claimed runs (claimed runs' yields not subtracted from deficit): owned = claimed+open+pending, compared to desired computed from stock which doesn't include goods still being crafted => OK by design but claimed runs finishing leave stock > target; withdraw logic never withdraws claimed. Fine, but SC-002 phrase `max(claimed, desired)` consistent.
- Distance metrics inconsistent within spec: board selection uses 012 path distance; Notice Post / Bell Tower use hop distance on adjacency graph (004) -- hops vs weighted cost, and "bell's distance from Church Bell" (furniture position) vs zone.
- Bell Tower "Church Bell" is a furniture entity inside the zone; "active Bell Tower with Church Bell removed" -> inactive via 015; fine. But a Bell Tower inside a Chartered...no.
- Crier route planning with Notice Post/Bell Tower changes 017 FR-012 behaviour (payload clearing, route replanning, mid-trip turn-back) -- 017 spec text not amended by this spec beyond FR-021..023; heavy hidden work. Also a board served by a post but the post is unreachable by the crier: fallback to board? unspecified.
- 017 PendingBoardUpdate carries provisional posting refs: need stable id so FR-018 withdrawal can target a still-pending add (cancels both?). "Queue withdrawal of PendingAdd" semantics (remove from payload vs create a withdraw change) not specified.
- Review at default tick 72 collides with 029 daily housing evaluation default tick 72 (households consume goods and fetch; counting order matters). Also 025 FR-008 status eval is after all systems, fine. Specify intra-tick ordering.
- Steward "leaving faction" and "being destroyed" detection requires events from 021/002 (not named). Steward cannot be a Town Crier — and a Steward appointed later conscripted as a crier? 017 crier selection must exclude Steward (not stated in this spec as an amendment to 017).
- `govern.steward_audience` is "recurring (daily)" in 022 table vs spec says task assigned per review; confirm ownership (who creates the task: the review).
- Audience task vs 013 FR-003 priority hierarchy needs an entry in 013's utility/priority model.
- Zone-scope `deliverToZoneId` runs are created with the board's craft.produce job; output hauling hook requires 018 to read job metadata (cross-system data path undefined).
- Harvest and category orders (open questions) leave "keep tools above 5" from the input unaddressed.
- A paused order's state: `Paused` reason from "propagated from its runs or board" -- unclear which Paused.
- LockedByTier for standing order handled in 025 but 027 FR-008 doesn't list standing orders as a command (only production orders); 026 adds its own rejection.
- ledger/stock consistency: workstation inventories counted by order but not by 025 `stock` (documented).
