# Digest 017 - Job Work Prioritization (Job Boards, Town Crier)

## 1. Purpose
Entities obtain all new work only by physically visiting a JobBoard entity and claiming a posting (exclusive or multi-slot, one-time or recurring), selected by a fixed order (player priority > urgency > familiarity > distance > PRNG). Boards are system-managed (pause/resume only) or user-managed (player edits are carried by a finite fleet of Town Crier entities from the Throne Room).

## 2. Implied module layout / public API (spec gives names, not signatures)
Module: jobboard (+ town-crier / governance dispatch).
Types:
- `JobBoard` entity: list of `JobPosting`, management mode (`system-managed` | `user-managed`), pause state, owner (zone / production order for system; player governance for user), map-local. Zone types may declare `requiresJobBoard: true` (FR-018).
- `JobPosting`: jobTypeId (open set; catalog in spec 022, e.g. `craft.produce`, `haul.deliver`, `guard.patrol`), concurrency count (default 1; = available slots), recurrence policy (`one-time`|`recurring`), familiarity tags, priority (integer; includes player "urgent"), job-specific params incl. optional `standingOrderId`, `deliverToZoneId` (spec 026 FR-012), status (`available | partially-claimed | fully-claimed | suspended`); blocked state with BlockedReason e.g. `MissingWorkstation`.
- `JobClaim`: entityId, posting ref, claim tick, status (`in-progress|completed|abandoned`).
- `TownCrier` entity (finite fleet = count of Town Crier entities in world): destination(s), status (traveling/arrived), pending changes carried; multi-board trips allowed.
- `PendingBoardUpdate`: queued add/remove/reorder/modify postings for a user-managed board.
- `DeliveryMethod` enum: `TownCrier`, `NoticePost`, `BellTower` (spec 026).
- Entity attribute: home board (FR-017), idle-threshold constant (ticks), `ContentLockedError`.
- BlockedReason values used: `NoReachableJobBoard, NoJobsAvailable, AwaitingWorker, AwaitingTownCrier, NoSeatOfGovernment, Paused, Unreachable, MissingWorkstation`.
- Events: `jobboard.job.posted|claimed|completed|abandoned`, `jobboard.update.applied` (payload `via: DeliveryMethod`), `jobboard.update.abandoned`, `jobboard.paused|resumed`. `jobboard.job.completed` carries `outputs: {materialId, quantity}[]` for material-producing job types (from job type `outputs`, spec 022 FR-024).
- Operations implied: post job, remove job, reorder, modify (user boards; deferred), pause/resume board, cancel pending update (recall crier), claim/abandon/complete job.

## 3. Functional requirements
- FR-001: JobBoard entity; independent posting lists, boards unconnected.
- FR-002: Claiming requires physical travel to board; no remote assignment.
- FR-003: Posting declares jobTypeId, concurrency (default 1), recurrence, familiarity tags, priority, extra params (incl. standingOrderId, deliverToZoneId). New posting of job type with unlockTier > settlement tier rejected `ContentLockedError` on both board modes; re-post of recurring is not "new".
- FR-004: Claim decrements slots; 0 = unclaimable; concurrency 1 posting removed on claim.
- FR-005: Recurring completion re-posts with fresh slots (full concurrency restored); not if board paused or owning zone inactive.
- FR-006: One-time completion or cancel removes posting permanently.
- FR-007: Selection order: (1) player priority (incl. urgent) (2) urgency (need-driven/time-sensitive) (3) familiarity (skill per 020 + experience alignment; higher preferred; take unfamiliar rather than idle) (4) distance; each only breaks ties of previous; remaining ties by PRNG. 016 and 020 defer to this.
- FR-008: Two modes: system-managed, user-managed.
- FR-009: System-managed: owning system sole authority; player individual changes rejected (with message).
- FR-010: User-managed: changes queued as pending, applied only when Town Crier physically arrives.
- FR-011: Crier dispatched from seat of government (Throne Room zone with Throne), pathfinds to board, applies all pending changes on arrival.
- FR-012: Finite fleet; first available dispatched; crier carries all pending changes for its destination at departure; later changes to same board go to another crier if free, else queue for next free crier; one crier may visit multiple boards in one trip; delivery shortcuts Notice Post / Bell Tower (026 FR-021-023) may apply updates without crier.
- FR-013: Board destroyed before arrival -> crier returns to base, changes discarded, `jobboard.update.abandoned`.
- FR-014: Pause/resume any board: paused offers no jobs and no recurring re-post; claimed jobs continue to completion.
- FR-015: Emit lifecycle events (list above).
- FR-016: Serialize all board state (postings, slots, pending changes, pause, crier assignments); resume identically.
- FR-017: Each entity has home board (work-zone board or nearest at last assignment); check home first; if no suitable work for configurable idle-threshold ticks may seek other reachable boards; zone-assigned entities return to home board as soon as it posts suitable work.
- FR-018: Zone type may declare `requiresJobBoard: true`.
- FR-019: Expose status per 025 with BlockedReason values above.

Rules: idle entity (empty task queue, no pending needs) goes to home board else nearest reachable; at board claims within 1 tick of arrival (SC-001); equal-distance boards: higher-priority/more-familiar, PRNG tiebreak; claimed jobs serialized as in-progress on save and resume on load (not returned to board); crier destroyed -> changes lost, player re-issues; no seat of government -> user-board updates rejected; board behind walls -> inert; claim-time validation of workstation (post-time not checked); abandoned job returns to board available (or suspended if permanent); idle with no board work waits and re-evaluates on `jobboard.job.posted`; optional greedy re-route when closer board posts during transit; abandoning concurrent slot reopens it; paused-zone recurring: current instance completes, re-post suppressed; resumed system board has no backlog.

## 4. Dependencies
Consumes: 003 (entities, task queue), 006 (serialization), 010 (events), 012 (pathfinding), 013 (idle/needs trigger, need-driven urgency), 015 (zone activation, requiresJobBoard, Throne Room), 020 (skills -> familiarity), 022 (job type catalog, `outputs`, FR-024), 025 (BlockedReason), 026 (standingOrderId, deliverToZoneId, Notice Posts/Bell Towers, DeliveryMethod), 027 (unlockTier), 021 (Diplomatic Envoy is separate; labour-access gate hostile < -30 on postings by player faction).
Provides: JobBoard/posting API to 016 (construction postings), 014 production orders, 019 (wage on posting - NOT currently defined), 018/haul postings, 026 stewards; events `jobboard.job.posted/completed` consumed by 020 (skill.work.completed is emitted by systems, not board), 025 ledger.

## 5. Ambiguities / contradictions / blockers
1. Wage: 019 US6 requires a wage amount "defined on the JobPosting" and payout on completion by "JobBoard (or the posting entity)"; 017 FR-003 posting fields have no wage and `jobboard.job.completed` has no worker/wage. Must add `wage` to FR-003 and name payer/trigger.
2. Eligibility predicates (016 "adult humanoid", 021 labour-access faction gate, 027 tier) have no place in posting schema or claim algorithm; also postings have no poster/faction field (021 "jobs posted by the player's faction").
3. Familiarity: 017 describes "familiarity tags" + "experience tags" (Assumptions) but 020 defines only skillId and a continuous `skillAffinityBonus = skill/100 × weight` score. FR-007 is strict lexicographic but 020 treats familiarity as additive score; define how score maps to ordering (threshold? quantisation?), how "no dominant skill" (generalist) works (US4 AC4), "dominant skill" for Baker label (020 FR-012/US6; null/alphabetical tiebreak vs 017 PRNG tie).
4. Definition of "urgency" (criterion 2) and relationship to "player-set urgent" (criterion 1) undefined; where need-driven urgency data comes from (013).
5. 016 ConstructionQueue priority/pause/cancel vs board semantics: which board holds construction postings; are queue edits "user-managed" (needing crier) or immediate? 016 says immediate; 017 says only user boards via crier.
6. Concurrency + recurrence interplay: multiple slots with partial completion: "re-posts restore full concurrency when both instances complete" (AC) vs per-completion re-post (FR-005); clarify whether each completion re-posts one slot.
7. Idle-threshold, crier fleet size defaults, SC-005 proportionality, "within 1 tick" are constants unspecified. Greedy re-route "may optionally" -> nondeterministic design choice; specify.
8. Home board assignment for entities in no zone with no board; maps (multi-map): boards map-local but cross-map travel not specified.
9. Crier recall on cancel: "recalled (or pending changes cleared)" - pick one. Crier destroyed while carrying vs queued changes (lost, but queued ones?). Crier "returns to seat and becomes available". Is Town Crier a citizen (needs, jobs)? Does crier claim jobs? Spawn vs placed: FR-011 "dispatched from seat" vs FR-012 fleet are placed/spawned entities.
10. `jobboard.job.abandoned` vs JobClaim status; slot accounting during save/load mid-claim.
11. System-managed board pause when zone inactive: "pauses (or stops posting)" - ambiguous; does it differ from player pause (resume after zone re-activate overrides player pause?). Two pause sources need a rule.
12. Job type definitions (022) must carry `outputs`, familiarity/skill domain, wage; not in this spec.
13. Distance metric (path length vs Manhattan) unspecified; 20 boards <10ms perf budget.
14. NoticePost/BellTower shortcut semantics only referenced (026).

## 6. Acceptance scenarios / tests
- US1: board with 3 jobs, idle entity travels, claims one (2 remain), executes; two entities on exclusive job -> exactly one claims; entity finishing a job immediately seeks home board/nearest; no suitable jobs -> claims nothing, may seek another/wait; claimed job invisible to others.
- US2: concurrency 1 removed on claim; concurrency 3 with 4 entities -> 3 claim, 4th cannot, 0 slots shown; abandon reopens slot; mixed exclusive+concurrent browsing. SC-002: never exceeds concurrency (100%).
- US3: recurring bake re-posts immediately after completion (<=1 tick, SC-003); one-time does not; paused board suppresses re-post; concurrency 2 -> 2 re-posted; board/zone deleted stops re-post.
- US4: Baker picks bake over haul; takes unfamiliar if only those; Baker/Smith each take own specialty; generalist uses priority/urgency/distance; newly gained familiarity preferred next visit. SC-004: >=90% skill-matched.
- US5: zone active -> board auto-posts; player add/remove on system board rejected with message; pause stops new posts; zone deactivation pauses board; resume without backlog. SC-007.
- US6: user board 30 tiles away -> crier dispatched, board shows old state until arrival; crier inspectable (destination, status, pending changes); accumulation with second crier / unleft crier absorbs; board destroyed -> crier returns, `jobboard.update.abandoned`; cancel recalls/clears; travel time proportional to distance (SC-005); no Throne -> `NoSeatOfGovernment`; all criers busy -> changes queue (`AwaitingTownCrier`).
- US7: nearest board empty -> go to second; choose nearest/highest-priority among multiple; none anywhere -> idle until `jobboard.job.posted`; assigned worker stays at own board; greedy reroute.
- Edge: crier destroyed -> changes lost; workstation destroyed -> posting blocked at claim time (`MissingWorkstation`); equidistant boards PRNG tie; save/load of claimed jobs resumes; unreachable board inert.
- SC-006 board state save/load fidelity (incl. assigned crier); SC-008 20+ boards <10ms/tick.
